# Capítulo Dezassete - Interrupções

Configurar as suas próprias interrupções pode ser um pesadelo da primeira vez que tenta, pois trata-se de um assunto complicado. Com a prática, torna-se um pouco mais fácil. Para fazer o Spectrum correr a nossa própria rotina de interrupção, temos de lhe indicar onde está a rotina, colocar a máquina no modo de interrupção 2 e garantir que as interrupções estão ativadas. Parece bastante simples, não é? A parte difícil é dizer ao Spectrum onde está localizada a nossa rotina.

Com a máquina no modo 2, o Z80 utiliza o registo `I` para determinar o byte alto do endereço do ponteiro para o endereço da rotina de serviço de interrupção. O byte baixo é fornecido pelo hardware. Na prática, nunca sabemos qual será o byte baixo – então, consegue ver o problema? O byte baixo pode ser 0, pode ser 255 ou pode estar em qualquer valor intermédio. Isto significa que precisamos de um bloco inteiro de 257 bytes composto por ponteiros para o endereço inicial da nossa rotina de serviço. Como o byte baixo fornecido pelo hardware pode ser ímpar ou par, temos de garantir que o byte baixo e o byte alto do endereço da nossa rotina de serviço sejam idênticos. Isto restringe seriamente os locais onde podemos colocar a nossa rotina. Também só devemos colocar a nossa tabela de ponteiros e a nossa rotina em RAM não contendida (*uncontended RAM*). Não os coloque abaixo do endereço 32768. Mesmo paginar um banco de RAM não contendido para esse fim, como o banco 1, produzirá problemas em certos modelos de Spectrum. Pessoalmente, considero o banco 0 um local tão bom como qualquer outro.

Digamos que escolhemos o endereço 51400 como a localização da nossa rotina de interrupção. Isto é válido porque tanto o byte alto como o byte baixo são 200, uma vez que 200 * 256 + 200 = 51400. Precisamos então de uma tabela de 129 ponteiros todos a apontar para este endereço, ou 257 instâncias de `defb 200`, localizadas no início de um limite de página de 256 bytes. Assumindo que a colocamos numa zona alta da memória para não estorvar, poderíamos iniciá-la em 254 * 256 = 65024. Faríamos isto:

```assembly
    org 51400
int:
    ; ... (rotina de serviço de interrupção)

    org 65024
    ; 257 ponteiros para a rotina de interrupção.
    DUP 257
    defb 200
    EDUP
```

Em vez de escrever 257 vezes `defb 200`, usamos a diretiva `DUP 257` … `EDUP` do sjasmplus, que repete as linhas entre as duas.

Uf! De qualquer forma, chegamos agora à nossa rotina de interrupção. As interrupções podem ocorrer em qualquer momento, pelo que temos de preservar todos os registos que provavelmente iremos usar, executar o nosso código, opcionalmente chamar a rotina de serviço da ROM, restaurar os registos, reativar as interrupções e, finalmente, retornar da interrupção com um `reti`.

A nossa rotina poderá assemelhar-se a esta:

```assembly
int:
    push af
    push bc
    push hl
    push de
    push ix             ; preservar registos.
    call 49158          ; reproduzir música.
    rst 56              ; rotina da ROM, ler teclas e atualizar relógio.
    pop ix
    pop de
    pop hl
    pop bc
    pop af              ; restaurar registos.
    ei                  ; reativar sempre as interrupções antes de retornar.
    reti                ; concluído.
```

Se não estiver a ler o teclado através das variáveis do sistema, poderá dispensar o `rst 56`. Fazer isso libertará os registos `IY`. No entanto, se a sincronização do seu jogo contar os fotogramas utilizando o método descrito no capítulo sobre sincronização, precisará de incrementar o temporizador você mesmo:

```assembly
    ld hl,23672         ; contador de fotogramas.
    inc (hl)            ; incrementá-lo.
```

Com tudo isto preparado, estamos prontos para ativar as nossas interrupções. Temos de apontar o registo `I` para a tabela de ponteiros e selecionar o modo de interrupção 2. Atenção: o valor a pôr em `I` é o byte alto do endereço da **tabela** (254, porque a tabela está em 254 × 256 = 65024), e não o da rotina. Algumas versões desta listagem usam `ld a,200`, o que faria o Z80 ir buscar o ponteiro a 51200, onde não há tabela nenhuma, e o programa rebentaria na primeira interrupção. Este código faz o trabalho:

```assembly
    di                  ; desativar interrupções por precaução.
    ld a,254            ; byte alto da tabela de ponteiros (254*256 = 65024).
    ld i,a              ; definir byte alto.
    im 2                ; selecionar modo de interrupção 2.
    ei                  ; ativar interrupções.
```

## Um Exemplo Completo

O programa seguinte instala uma rotina de interrupção nos endereços usados acima e deixa-a correr durante 5 segundos. A rotina conta as interrupções e muda a cor da margem a cada 16, e chama `rst 56` para a ROM continuar a ler o teclado e a atualizar o relógio. Para não ter de gravar na cassete um bloco de código que vai de 32768 até 65280, a tabela e o salto para a rotina são construídos pelo próprio programa: a tabela é preenchida com `ldir`, e em 51400 é escrita a instrução `jp int` (o código 195 seguido do endereço). No fim, o programa repõe o modo 1 e o valor normal de `I` (63) antes de voltar ao BASIC.

```assembly
        DEVICE ZXSPECTRUM48
        ORG 32768
start:
    di                  ; nada de interrupções enquanto preparamos tudo.
    ld hl,65024         ; tabela de ponteiros em 254*256.
    ld (hl),200         ; primeiro byte.
    ld de,65025
    ld bc,256           ; mais 256 bytes: 257 no total.
    ldir
    ld a,195            ; código da instrução jp.
    ld (51400),a        ; em 51400 = 200*256+200 fica "jp int".
    ld hl,int
    ld (51401),hl
    ld a,254            ; byte alto da tabela.
    ld i,a
    im 2                ; modo de interrupção 2.
    ei                  ; e já está!
espera:
    halt                ; esperar pela próxima interrupção.
    ld a,(cont)
    cp 250              ; 250 interrupções = 5 segundos.
    jr c,espera
    di
    ld a,63             ; valor normal do registo I no Spectrum.
    ld i,a
    im 1                ; voltar ao modo de interrupção da ROM.
    ei
    ret

    ; A nossa rotina de serviço de interrupção.
int:
    push af             ; preservar os registos que usamos.
    push hl
    ld hl,cont
    inc (hl)            ; contar esta interrupção.
    ld a,(hl)
    rrca                ; dividir por 16...
    rrca
    rrca
    rrca
    and 7               ; ...e usar o resultado como cor (0-7).
    out (254),a         ; mudar a cor da margem.
    rst 56              ; rotina da ROM: teclado e relógio.
    pop hl
    pop af              ; restaurar os registos.
    ei                  ; reativar as interrupções.
    reti

cont:   defb 0          ; número de interrupções.
fim:

; --- Carregador BASIC + ficheiro .tap (igual em todos os exemplos) ---
        ORG 23755
basic:  db 0,10                 ; 10 CLEAR 32767: LOAD "" CODE: RANDOMIZE USR 32768
        dw basic_fim-basic-4
        db $FD,$B0,'"32767":',$EF,'""',$AF,':',$F9,$C0,$B0,'"32768"',13
basic_fim:
        EMPTYTAP "cap17_1.tap"
        SAVETAP  "cap17_1.tap",BASIC,"cap17_1",basic,basic_fim-basic,10
        SAVETAP  "cap17_1.tap",CODE,"cap17_1",start,fim-start
```

## Notas

* Em modo 2, quando chega uma interrupção, o Z80 forma um endereço com `I` no byte alto e o valor que está no barramento de dados no byte baixo, lê nesse endereço um ponteiro de 2 bytes e salta para onde ele aponta. No Spectrum, o valor do barramento é imprevisível (normalmente 255, mas não é garantido), e é por isso que a tabela tem 257 bytes todos iguais: qualquer que seja o byte baixo, o ponteiro lido é sempre 200 + 200 × 256 = 51400.
* `rst 56` chama a rotina de interrupção normal da ROM (no endereço 56 = `$38`). Essa rotina usa o registo `IY` para chegar às variáveis de sistema, por isso só pode ser chamada se o programa não tiver alterado `IY`.
* A rotina de interrupção tem de preservar todos os registos que altera. Caso contrário, o programa principal veria registos a mudar "sozinhos" em momentos imprevisíveis.
