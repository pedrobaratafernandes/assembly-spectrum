# Capítulo Catorze - Movimento Mais Sofisticado

Até agora, movilizámos os *sprites* para cima, para baixo, para a esquerda e para a direita por píxeis inteiros. No entanto, muitos jogos requerem manipulação de *sprites* mais sofisticada. Os jogos de plataformas necessitam de gravidade, os jogos de corrida vistos de cima utilizam movimento rotacional e outros usam inércia.

## Tabelas de Salto e Inércia

A forma mais simples de obter gravidade ou inércia é ter uma tabela de valores. Por exemplo, os jogos *Egghead* utilizam uma tabela de saltos e mantêm um ponteiro para a posição atual. Uma tabela desse tipo poderá parecer-se com a seguinte:

```assembly
    EMPTYTAP "14_prog1.tap"

    ; --- BASIC loader ---
    ORG $5D00
BasicStart:
    db 0,10
    dw Line1End-Line1Start
Line1Start:
    db $fd, $b0, $22, "32767", $22, $0d
Line1End:
    db 0,20
    dw Line2End-Line2Start
Line2Start:
    db $ef, $22, $22, $af, $0d
Line2End:
    db 0,30
    dw Line3End-Line3Start
Line3Start:
    db $f9, $c0, $b0, $22, "32768", $22, $0d
Line3End:
BasicEnd:
    SAVETAP "14_prog1.tap", BASIC, "loader", BasicStart, BasicEnd-BasicStart, 10

    ORG 32768

    DEVICE ZXSPECTRUM48
    ORG $8000

start:
    ; Tabela de saltos.
    ; Valores >128 indicam subida, <128 indicam descida.
    ; Quando atingimos o valor 128, alcançámos a velocidade máxima.
jptr:   defw jtabu           ; ponteiro de salto.
jtabu:  defb 250,251,252     ; valores de subida.
       defb 253,254,254
       defb 255,255,255
       defb 0,255,0
jtabd:  defb 1,0,1,1,1,2     ; valores de descida.
       defb 2,3,4,5,6,6
       defb 6,6,128


    SAVESNA "14_prog1.sna", start
    SAVETAP "14_prog1.tap", CODE, "14_prog1", start, $ - start, start
```

Com o ponteiro guardado em `jptr`, poderíamos fazer algo assim:

```assembly
    EMPTYTAP "14_prog2.tap"

    ; --- BASIC loader ---
    ORG $5D00
BasicStart:
    db 0,10
    dw Line1End-Line1Start
Line1Start:
    db $fd, $b0, $22, "32767", $22, $0d
Line1End:
    db 0,20
    dw Line2End-Line2Start
Line2Start:
    db $ef, $22, $22, $af, $0d
Line2End:
    db 0,30
    dw Line3End-Line3Start
Line3Start:
    db $f9, $c0, $b0, $22, "32768", $22, $0d
Line3End:
BasicEnd:
    SAVETAP "14_prog2.tap", BASIC, "loader", BasicStart, BasicEnd-BasicStart, 10

    ORG 32768

    DEVICE ZXSPECTRUM48
    ORG $8000

start:
    ld hl,(jptr)        ; obter ponteiro de salto.
    ld a,(hl)           ; obter próximo valor.
    cp 128              ; atingiu o fim da tabela?
    jr nz,skip          ; não, prosseguir.
    dec hl              ; voltar à velocidade máxima.
    ld a,(hl)           ; obter velocidade máxima.
    inc hl
skip:
    ld (jptr),hl        ; definir próxima posição do ponteiro.
    ld hl,verpos        ; posição vertical do jogador.
    add a,(hl)          ; adicionar quantidade relevante.
    ld (hl),a           ; definir nova posição do jogador.



; --- Mocks para compilação autónoma ---
jptr: defw 0
verpos: defb 0

    SAVESNA "14_prog2.sna", start
    SAVETAP "14_prog2.tap", CODE, "14_prog2", start, $ - start, start
```

Para iniciar um salto, definiríamos `jptr` para `jtabu`. Para começar a cair, definiríamos para `jtabd`.

Tudo bem, isto é um pouco simplista. Na prática, usaríamos normalmente o valor da tabela de saltos como um contador de ciclos, movendo o jogador para cima ou para baixo um píxel de cada vez, verificando colisões com plataformas, paredes, itens mortais, etc., à medida que avançamos. Poderíamos também usar o marcador de fim (128) para significar que o jogador caiu de uma altura demasiado grande e definir uma flag para que, da próxima vez que o jogador atinja algo sólido, perca uma vida. Dito isto, percebe a ideia geral.

## Coordenadas Fracionárias

Se quisermos uma gravidade, inércia ou movimento rotacional mais sofisticados, precisamos de coordenadas fracionárias. Até agora, com a resolução do Spectrum a 256 x 192 píxeis, apenas precisámos de usar um byte por coordenada. Se, em vez disso, usarmos um par de registos de dois bytes, com o byte alto para a parte inteira e o byte baixo para a fração, abrimos um mundo inteiramente novo de possibilidades. Isto dá-nos 8 casas decimais binárias, permitindo movimentos muito precisos e subtis. Com uma coordenada no par `HL`, podemos definir o deslocamento em `DE`, e somar os dois. Ao desenhar os nossos *sprites*, simplesmente usamos os bytes altos como as nossas coordenadas x e y para o cálculo do endereço do ecrã, e descartamos os bytes baixos que contêm as frações. O efeito de adicionar uma fração a uma coordenada não será visível em cada fotograma (*frame*), mas mesmo a menor fração, 1/256, moverá lentamente um *sprite* ao longo do tempo.

Olhemos agora para a gravidade. Trata-se de uma força constante que, na prática, acelera um objeto em direção ao solo a 9.8m/s². Para a simular num jogo do Spectrum, configuramos a nossa coordenada vertical como uma palavra de 16 bits. De seguida, configuramos uma segunda palavra de 16 bits para a nossa aceleração (momento). Em cada fotograma, adicionamos uma pequena fração ao momento e depois adicionamos o momento à posição vertical. Por exemplo:

```assembly
    EMPTYTAP "14_prog3.tap"

    ; --- BASIC loader ---
    ORG $5D00
BasicStart:
    db 0,10
    dw Line1End-Line1Start
Line1Start:
    db $fd, $b0, $22, "32767", $22, $0d
Line1End:
    db 0,20
    dw Line2End-Line2Start
Line2Start:
    db $ef, $22, $22, $af, $0d
Line2End:
    db 0,30
    dw Line3End-Line3Start
Line3Start:
    db $f9, $c0, $b0, $22, "32768", $22, $0d
Line3End:
BasicEnd:
    SAVETAP "14_prog3.tap", BASIC, "loader", BasicStart, BasicEnd-BasicStart, 10

    ORG 32768

    DEVICE ZXSPECTRUM48
    ORG $8000

start:
    ld hl,(vermom)      ; momento.
    ld de,2             ; fração minúscula (1/128).
    add hl,de           ; aumentar momento.
    ld (vermom),hl      ; guardar momento.
    ld de,(verpos)      ; posição vertical.
    add hl,de           ; adicionar momento.
    ld (verpos),hl      ; guardar nova posição.
    ret

verpos: defw 0       ; posição vertical.
vermom: defw 0       ; momento vertical (velocidade vertical).


    SAVESNA "14_prog3.sna", start
    SAVETAP "14_prog3.tap", CODE, "14_prog3", start, $ - start, start
```

De seguida, para desenhar os nossos *sprites*, pegamos apenas no byte alto da nossa posição vertical, `verpos+1`, para nos dar o número de píxeis a partir do topo do ecrã. Valores diferentes de `DE` variarão a força da gravidade; de facto, podemos até inverter a direção subtraindo `DE` de `HL`, ou adicionando uma distância negativa (65536-distância). Podemos aplicar o mesmo à coordenada y também, e ter o *sprite* sujeito a momento em todas as direções. É assim que procederíamos para escrever um jogo ao estilo *Thrust*.

## Movimento Rotacional

A outra coisa de que poderemos precisar para um jogo do tipo *Thrust*, jogos de corridas vistos de cima, ou qualquer jogo onde estejam envolvidos círculos ou trigonometria básica, é de uma tabela de senos/cossenos. A matemática não é a preferência de toda a gente e, se a sua trigonometria estiver um pouco enferrujada, sugiro que leia sobre senos e cossenos antes de continuar com o resto deste capítulo.

Na matemática, podemos encontrar a distância x e y a partir do centro de um círculo, dados o raio e o ângulo, utilizando senos e cossenos. No entanto, enquanto na matemática um círculo é composto por 360 graus ou 2 PI radianos, é mais conveniente para o programador do Spectrum representar o seu ângulo como, digamos, um valor de 8 bits de 0 a 255 (ou até usar menos bits, dependendo do número de posições que o *sprite* do jogador possa assumir). Ele pode então usar este valor para procurar os seus valores fracionários de 16 bits para o seno e cosseno numa tabela. Assumindo que temos um ângulo de 8 bits definido no acumulador e desejamos encontrar o seno, acedemos simplesmente à tabela de forma semelhante a esta:

```assembly
    EMPTYTAP "14_prog4.tap"

    ; --- BASIC loader ---
    ORG $5D00
BasicStart:
    db 0,10
    dw Line1End-Line1Start
Line1Start:
    db $fd, $b0, $22, "32767", $22, $0d
Line1End:
    db 0,20
    dw Line2End-Line2Start
Line2Start:
    db $ef, $22, $22, $af, $0d
Line2End:
    db 0,30
    dw Line3End-Line3Start
Line3Start:
    db $f9, $c0, $b0, $22, "32768", $22, $0d
Line3End:
BasicEnd:
    SAVETAP "14_prog4.tap", BASIC, "loader", BasicStart, BasicEnd-BasicStart, 10

    ORG 32768

    DEVICE ZXSPECTRUM48
    ORG $8000

start:
    ld de,2             ; fração minúscula - 1/128.
    ld l,a              ; ângulo no byte baixo.
    ld h,0              ; sem deslocamento no byte alto.
    add hl,hl           ; duplicar deslocamento pois as entradas são de 16 bits.
    ld de,sintab        ; endereço da tabela de senos.
    add hl,de           ; somar deslocamento para este ângulo.
    ld e,(hl)           ; fração do seno.
    inc hl              ; apontar para a segunda metade.
    ld d,(hl)           ; parte inteira.
    ret                 ; retornar com o seno em de.



; --- Mocks para compilação autónoma ---
sintab: defw 0

    SAVESNA "14_prog4.sna", start
    SAVETAP "14_prog4.tap", CODE, "14_prog4", start, $ - start, start
```

O Sinclair BASIC fornece-nos os valores de que necessitamos através das suas funções `SIN` e `COS`. Utilizando isto, podemos fazer `POKE` dos valores retornados para a RAM e gravá-los em fita, ou exportar o binário usando um emulador como o SPIN. Alternativamente, poderá preferir usar outra linguagem de programação no PC para gerar uma tabela de valores de seno formatados para importar para o seu ficheiro de código-fonte, ou incluir como ficheiro binário. Para uma tabela de senos com 256 ângulos igualmente espaçados, precisaríamos de um total de 512 bytes, mas teríamos de ter o cuidado de converter o número retornado por `SIN` num valor que o nosso jogo reconheça. Multiplicar o seno por 256 dar-nos-á os nossos valores positivos, mas nos casos em que `SIN` retorna um resultado negativo, podemos precisar de multiplicar o valor absoluto (`ABS`) do seno por 256 e, de seguida, subtrair esse valor a 65536 ou definir o bit `d7` do byte alto para indicar que o número deve ser subtraído em vez de adicionado à nossa coordenada.

Com uma tabela de senos construída desta maneira, não precisamos de uma tabela separada para cossenos, pois basta adicionar ou subtrair 64 (um quarto de volta) ao ângulo antes de pesquisar o valor na nossa tabela. Para mover um *sprite* num ângulo A, adicionamos o seno de A a uma coordenada e o cosseno de A à outra coordenada. Ao alterar se somamos ou subtraímos um quarto de volta para obter o cosseno, e qual dos eixos utiliza senos e qual utiliza cossenos, podemos iniciar o nosso círculo em qualquer um dos 4 pontos cardeais principais e fazê-lo girar no sentido dos ponteiros do relógio ou no sentido contrário.
