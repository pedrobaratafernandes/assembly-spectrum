# Capítulo Dois - Controlo por Teclado e Joystick

## Uma Tecla de Cada Vez

Desde que não tenha desativado ou interferido de outra forma com o modo de interrupção padrão do Spectrum, a ROM lerá automaticamente o teclado e atualizará várias variáveis de sistema localizadas na posição de memória 23552, cinquenta vezes por segundo. A forma mais simples de verificar a pressão de uma tecla é carregar primeiro o endereço 23560 com um valor nulo, e depois interrogar este local até que mude, sendo o resultado o valor ASCII da tecla pressionada. Isto é mais útil para aquelas situações de "pressione qualquer tecla para continuar", para escolher itens de um menu e para entrada de teclado, como rotinas de introdução de nome para pontuações máximas.

Uma rotina destas poderia ser assim:

```assembly
    EMPTYTAP "2_prog1.tap"

    ; --- BASIC loader ---
    ORG $5D00
BasicStart:
    db 0,10
    dw Line1End-Line1Start
Line1Start:
    db $fd, $b0, $22, "32767", $22, $0d
Line1End:
    db 0,20
    dw Line2End-Line2Start
Line2Start:
    db $ef, $22, $22, $af, $0d
Line2End:
    db 0,30
    dw Line3End-Line3Start
Line3Start:
    db $f9, $c0, $b0, $22, "32768", $22, $0d
Line3End:
BasicEnd:
    SAVETAP "2_prog1.tap", BASIC, "loader", BasicStart, BasicEnd-BasicStart, 10

    ORG 32768

    DEVICE ZXSPECTRUM48
    ORG $8000

start:
loop:
    ld hl,23560        ; variável de sistema LAST K.
    ld (hl),0          ; colocar lá um valor nulo.
    ld a, (hl)         ; novo valor de LAST K.
    cp 0               ; ainda é zero?
    jr z, loop         ; sim, logo nenhuma tecla pressionada.
    ret                ; tecla foi pressionada.


    SAVESNA "2_prog1.sna", start
    SAVETAP "2_prog1.tap", CODE, "2_prog1", start, $ - start, start
```

## Múltiplas Teclas Pressionadas

No entanto, pressões de teclas únicas raramente são úteis para jogos de arcada de ação rápida; para isso precisamos detetar mais do que uma pressão de tecla em simultâneo e é aqui que as coisas ficam um pouco mais complicadas. Em vez de lermos endereços de memória, temos de ler uma de oito portas, cada uma correspondendo a uma linha de cinco teclas. Claro que a maioria dos modelos do Spectrum parece ter muito mais teclas do que estas, então para onde foram todas? Bem, na verdade, não foram para lado nenhum. O layout original do teclado do Spectrum consistia em apenas quarenta teclas, organizadas em oito grupos ou linhas de cinco. Para aceder a algumas das funções, era necessário pressionar certas combinações de teclas juntas - por exemplo, para apagar (delete), a combinação necessária era CAPS SHIFT e 0 ao mesmo tempo. A Sinclair adicionou estas teclas extras quando o Spectrum Plus entrou em cena em 1985, e elas funcionam simulando as combinações de pressões de teclas necessárias para os modelos originais de teclas de borracha.

O layout original do teclado estava separado nestes grupos:

| Porta | Teclas |
| :--- | :--- |
| 32766 | B, N, M, Symbol shift, Space |
| 49150 | H, J, K, L, Enter |
| 57342 | Y, U, I, O, P |
| 61438 | 6, 7, 8, 9, 0 |
| 63486 | 5, 4, 3, 2, 1 |
| 64510 | T, R, E, W, Q |
| 65022 | G, F, D, S, A |
| 65278 | V, C, X, Z, Caps Shift |

Para descobrir que teclas estão a ser pressionadas, lemos o número da porta apropriado, sendo alocado a cada tecla da linha um dos cinco bits mais baixos d0-d4 (valores 1, 2, 4, 8 e 16), onde d0 representa a tecla mais de fora e d4 a mais interior. Curiosamente, cada bit fica no estado alto (1) quando não está pressionado e no estado baixo (0) quando está - o oposto do que se poderia esperar.

Para ler uma linha de cinco teclas, carregamos simplesmente o número da porta no par de registos bc e, de seguida, executamos a instrução `in a, (c)`. Como apenas precisamos dos bits de valor mais baixo, podemos ignorar os bits que não queremos através de um `and 31` ou rodando os bits do acumulador para a flag de carry usando cinco instruções `rra` seguidas de `call c, (endereço)`.

Se isto for difícil de compreender, considere o seguinte exemplo:

```assembly
    EMPTYTAP "2_prog2.tap"

    ; --- BASIC loader ---
    ORG $5D00
BasicStart:
    db 0,10
    dw Line1End-Line1Start
Line1Start:
    db $fd, $b0, $22, "32767", $22, $0d
Line1End:
    db 0,20
    dw Line2End-Line2Start
Line2Start:
    db $ef, $22, $22, $af, $0d
Line2End:
    db 0,30
    dw Line3End-Line3Start
Line3Start:
    db $f9, $c0, $b0, $22, "32768", $22, $0d
Line3End:
BasicEnd:
    SAVETAP "2_prog2.tap", BASIC, "loader", BasicStart, BasicEnd-BasicStart, 10

    ORG 32768

    DEVICE ZXSPECTRUM48
    ORG $8000

start:
    ld bc, 63486       ; linha de teclado 1-5 / porta de joystick 2.
    in a, (c)          ; ver que teclas estão pressionadas.
    rra                ; bit mais de fora = tecla 1.
    push af            ; lembrar o valor.
    call nc,mpl        ; está a ser pressionada, mover para a esquerda.
    pop af             ; restaurar acumulador.
    rra                ; próximo bit (valor 2) = tecla 2.
    push af            ; lembrar o valor.
    call nc,mpr        ; está a ser pressionada, logo mover para a direita.
    pop af             ; restaurar acumulador.
    rra                ; próximo bit (valor 4) = tecla 3.
    push af            ; lembrar o valor.
    call nc,mpd        ; está a ser pressionada, logo mover para baixo.
    pop af             ; restaurar acumulador.
    rra                ; próximo bit (valor 8) = tecla 4.
    call nc,mpu        ; está a ser pressionada, mover para cima.



; --- Mocks para compilação autónoma ---
mpr: ret
mpl: ret
mpd: ret
mpu: ret

    SAVESNA "2_prog2.sna", start
    SAVETAP "2_prog2.tap", CODE, "2_prog2", start, $ - start, start
```

## Joysticks

As portas 1 e 2 de joystick da Sinclair estavam simplesmente mapeadas em cada uma das linhas de teclas numéricas, e pode provar isto facilmente indo ao editor BASIC e usando o joystick para digitar números. A Porta 1 (Interface 2) estava mapeada nas teclas 6, 7, 8, 9 e 0; a Porta 2 (Interface 1) nas teclas 1, 2, 3, 4 e 5. Para detetar a entrada do joystick, lemos a porta da mesma forma que lemos o teclado. Os joysticks da Sinclair usam as portas 63486 (Interface 1 / porta 2) e 61438 (Interface 2 / porta 1); os bits d0-d4 darão 0 para pressionado, 1 para não pressionado.

O popular formato de joystick Kempston não está mapeado no teclado e pode ser lido utilizando a porta 31 em vez disso. Isto significa que podemos usar um simples `in a, (31)`. Mais uma vez, usam-se os valores dos bits d0-d4, embora desta vez as configurações dos bits sejam como seria de esperar, com um bit definido no estado alto (1) se o joystick estiver a ser aplicado numa determinada direção. Os valores dos bits resultantes serão 1 para pressionado e 0 para não pressionado.

```assembly
    EMPTYTAP "2_prog3.tap"

    ; --- BASIC loader ---
    ORG $5D00
BasicStart:
    db 0,10
    dw Line1End-Line1Start
Line1Start:
    db $fd, $b0, $22, "32767", $22, $0d
Line1End:
    db 0,20
    dw Line2End-Line2Start
Line2Start:
    db $ef, $22, $22, $af, $0d
Line2End:
    db 0,30
    dw Line3End-Line3Start
Line3Start:
    db $f9, $c0, $b0, $22, "32768", $22, $0d
Line3End:
BasicEnd:
    SAVETAP "2_prog3.tap", BASIC, "loader", BasicStart, BasicEnd-BasicStart, 10

    ORG 32768

    DEVICE ZXSPECTRUM48
    ORG $8000

start:
    ; Exemplo de rotina de controlo de joystick.
joycon: ld bc, 31   ; porta do joystick Kempston.
    in a, (c)          ; ler entrada.
    and 2              ; verificar bit de "esquerda".
    call nz, joyl      ; mover para a esquerda.
    in a, (c)          ; ler entrada.
    and 1              ; testar bit de "direita".
    call nz, joyr      ; mover para a direita.
    in a, (c)          ; ler entrada.
    and 8              ; verificar bit de "cima".
    call nz, joyu      ; mover para cima.
    in a, (c)          ; ler entrada.
    and 4              ; verificar bit de "baixo".
    call nz, joyd      ; mover para baixo.
    in a, (c)          ; ler entrada.
    and 16             ; testar o bit de fogo.
    call nz, fire      ; fogo pressionado.



; --- Mocks para compilação autónoma ---
joyd: ret
fire: ret
joyl: ret
joyu: ret
joyr: ret

    SAVESNA "2_prog3.sna", start
    SAVETAP "2_prog3.tap", CODE, "2_prog3", start, $ - start, start
```

## Um Jogo Simples

Agora podemos ir um passo mais longe e, pondo em prática o que já abordámos, escrever a secção de controlo principal para um jogo básico. Isto formará a base de uma variante simples do Centipede que iremos desenvolver ao longo dos próximos capítulos. Ainda não abordámos tudo o que é necessário para tal jogo, mas podemos começar com um pequeno ciclo de controlo que permite ao jogador manipular uma pequena base de arma pelo ecrã. Fique avisado, este programa não tem saída para o BASIC, por isso certifique-se de que guardou uma cópia do seu código-fonte antes de o correr.

```assembly
    EMPTYTAP "2_prog4.tap"

    ; --- BASIC loader ---
    ORG $5D00
BasicStart:
    db 0,10
    dw Line1End-Line1Start
Line1Start:
    db $fd, $b0, $22, "32767", $22, $0d
Line1End:
    db 0,20
    dw Line2End-Line2Start
Line2Start:
    db $ef, $22, $22, $af, $0d
Line2End:
    db 0,30
    dw Line3End-Line3Start
Line3Start:
    db $f9, $c0, $b0, $22, "32768", $22, $0d
Line3End:
BasicEnd:
    SAVETAP "2_prog4.tap", BASIC, "loader", BasicStart, BasicEnd-BasicStart, 10

    ORG 32768

    DEVICE ZXSPECTRUM48
    ORG $8000

start:
    ; Queremos um ecrã preto.
    ld a,71            ; tinta branca (7) em papel preto (0), brilho (64).
    ld (23693), a      ; definir as cores do nosso ecrã.
    xor a              ; forma rápida de carregar o acumulador com zero.
    call 8859          ; definir as cores permanentes da margem.

    ; Configurar os gráficos.
    ld hl, blocks      ; endereço dos dados dos gráficos definidos pelo utilizador.
    ld (23675), hl     ; fazer os UDGs apontarem para aí.

    ; Ok, vamos iniciar o jogo.
    call 3503          ; rotina da ROM que limpa o ecrã, abre o canal 2.

    ; Inicializar coordenadas.
    ld hl,21+15*256    ; carregar par hl com coordenadas iniciais.
    ld (plx), hl       ; definir as coordenadas do jogador.
    call basexy        ; definir as posições x e y do jogador.
    call splayr        ; mostrar símbolo da base do jogador.

    ; Este é o ciclo principal.
mloop: equ $

    ; Apagar o jogador.
    call basexy        ; definir as posições x e y do jogador.
    call wspace        ; mostrar espaço sobre o jogador.

    ; Agora que apagámos o jogador, podemos movê-lo antes de o voltar a mostrar
    ; nas suas novas coordenadas.
    ld bc, 63486       ; linha do teclado 1-5 / porta do joystick 2.
    in a, (c)          ; ver que teclas estão pressionadas.
    rra                ; bit mais exterior = tecla 1.
    push af            ; lembrar o valor.
    call nc,mpl        ; está a ser pressionada, mover para a esquerda.
    pop af             ; restaurar acumulador.
    rra                ; próximo bit (valor 2) = tecla 2.
    push af            ; lembrar o valor.
    call nc,mpr        ; está a ser pressionada, mover para a direita.
    pop af             ; restaurar acumulador.
    rra                ; próximo bit (valor 4) = tecla 3.
    push af            ; lembrar o valor.
    call nc,mpd        ; está a ser pressionada, mover para baixo.
    pop af             ; restaurar acumulador.
    rra                ; próximo bit (valor 8) = tecla 4.
    call nc,mpu        ; está a ser pressionada, mover para cima.

    ; Agora que se moveu, podemos voltar a mostrar o jogador.
    call basexy        ; definir as posições x e y do jogador.
    call splayr        ; mostrar o jogador.
    halt               ; atraso.

    ; Saltar de volta para o início do ciclo principal.
    jp mloop           

    ; Mover jogador para a esquerda.
mpl:
    ld hl,ply          ; lembre-se, y é a coordenada horizontal!
    ld a, (hl)         ; qual é o valor atual?
    and a              ; é zero?
    ret z              ; sim, não podemos ir mais para a esquerda.
    dec (hl)           ; subtrair 1 à coordenada y.
    ret

    ; Mover jogador para a direita.
mpr:
    ld hl, ply         ; lembre-se, y é a coordenada horizontal!
    ld a, (hl)         ; qual é o valor atual?
    cp 31              ; está na extremidade direita (31)?
    ret z              ; sim, não podemos ir mais para a direita.
    inc (hl)           ; adicionar 1 à coordenada y.
    ret

    ; Mover jogador para cima.
mpu:
    ld hl,plx          ; lembre-se, x é a coordenada vertical!
    ld a, (hl)         ; qual é o valor atual?
    cp 4               ; está no limite superior (4)?
    ret z              ; sim, não podemos ir mais para cima.
    dec (hl)           ; subtrair 1 à coordenada x.
    ret

    ; Mover jogador para baixo.
mpd:
    ld hl, plx         ; lembre-se, x é a coordenada vertical!
    ld a, (hl)         ; qual é o valor atual?
    cp 21              ; já está no fundo (21)?
    ret z              ; sim, não podemos descer mais.
    inc (hl)           ; adicionar 1 à coordenada x.
    ret

    ; Configurar as coordenadas x e y para a posição da base/arma do jogador,
    ; esta rotina é chamada antes da visualização e eliminação da base.
basexy: ld a, 22    ; código AT.
    rst 16
    ld a, (plx)        ; coordenada vertical do jogador.
    rst 16             ; definir posição vertical do jogador.
    ld a, (ply)        ; posição horizontal do jogador.
    rst 16             ; definir a coordenada horizontal.
    ret

    ; Mostrar o jogador na posição de impressão atual.
splayr: ld a,69     ; tinta ciano (5) no papel preto (0), brilho (64).
    ld (23695), a      ; definir as nossas cores de ecrã temporárias.
    ld a, 144          ; código ASCII para Gráfico Definido pelo Utilizador 'A'.
    rst 16             ; desenhar o jogador.
    ret

wspace: ld a, 71    ; tinta branca (7) no papel preto (0), brilho (64).
    ld (23695), a      ; definir as nossas cores de ecrã temporárias.
    ld a,32            ; caráter de ESPAÇO.
    rst 16             ; mostrar espaço.
    ret

plx:  defb 0        ; coordenada x do jogador.
ply:  defb 0        ; coordenada y do jogador.

    ; Gráficos UDG.
blocks: defb 16,16,56,56,124,124,254,254 ; base do jogador.


    SAVESNA "2_prog4.sna", start
    SAVETAP "2_prog4.tap", CODE, "2_prog4", start, $ - start, start
```

Rápido, não é? Na verdade, abrandámos o ciclo com uma instrução `halt`, mas ainda corre a uns rápidos 50 fotogramas por segundo, o que é provavelmente um pouco rápido demais. Não se preocupe, à medida que adicionamos mais funcionalidades ao código, este começará a abrandar. Se se sentir confiante, talvez queira tentar adaptar o programa acima para funcionar com um joystick Kempston. Não é difícil e requer apenas a mudança da porta 63486 para a porta 31 e a substituição das quatro subsequentes `call nc, (endereço)` por `call c, (endereço)` (os bits são invertidos, lembra-se?).

Teclas redefiníveis são um pouco mais complicadas. Como provavelmente sabe, o teclado original do Spectrum estava dividido em 8 linhas de 5 teclas cada, e lendo a porta associada a uma determinada linha de teclas e, em seguida, testando os bits d0-d4, podemos saber se uma determinada tecla está a ser pressionada. Se substituísse `ld bc,31` no trecho de código acima por `ld bc,49150`, poderia testar a linha de teclas do H ao Enter - embora isso não resulte numa rotina conveniente de redefinição de teclas. Felizmente, existe outra forma de contornar a questão.

Podemos estabelecer a porta necessária para cada linha de teclas utilizando a fórmula do manual do Spectrum. Sendo n o número da linha de 0 a 7, o endereço da porta será $254+256*(255-2^n)$. Há uma rotina da ROM no endereço 654 que faz muito do trabalho árduo por nós, devolvendo o número da tecla pressionada no registo e, no intervalo 0-39. Os números 0 a 7 correspondem à tecla mais interior de cada linha sucessivamente (ou seja, B, H, Y, 6, 5, T, G e V), os números 8 a 15 à tecla seguinte em cada linha até 39 para a tecla mais exterior na última linha - CAPS SHIFT. O estado da tecla shift, a título de curiosidade, também é retornado em d. Se nenhuma tecla for pressionada, então e retorna 255.

A rotina da ROM só pode devolver um único número de tecla, o que não serve para detetar mais do que uma pressão de tecla em simultâneo. Para determinar se uma tecla específica está ou não a ser pressionada a qualquer momento, precisamos de converter o número novamente numa porta e num bit, e depois ler essa porta e verificar o bit individualmente por nós próprios. Existe uma rotina muito útil que utilizo para o trabalho, e é a única rotina nos meus jogos que não escrevi eu mesmo. O crédito por essa rotina deve ser dado a Stephen Jones, um programador que costumava escrever excelentes artigos para o Spectrum Discovery Club há muitos anos atrás. Para usar a sua rotina, carregue o acumulador com o número da tecla que deseja testar, chame ktest e depois verifique a flag de carry. Se estiver ativada (set), a tecla não está a ser pressionada; se não houver carry, a tecla está a ser pressionada. Se isso for demasiado confuso e parecer o contrário do esperado, coloque uma instrução `ccf` um pouco antes do `ret`.

```assembly
    EMPTYTAP "2_prog5.tap"

    ; --- BASIC loader ---
    ORG $5D00
BasicStart:
    db 0,10
    dw Line1End-Line1Start
Line1Start:
    db $fd, $b0, $22, "32767", $22, $0d
Line1End:
    db 0,20
    dw Line2End-Line2Start
Line2Start:
    db $ef, $22, $22, $af, $0d
Line2End:
    db 0,30
    dw Line3End-Line3Start
Line3Start:
    db $f9, $c0, $b0, $22, "32768", $22, $0d
Line3End:
BasicEnd:
    SAVETAP "2_prog5.tap", BASIC, "loader", BasicStart, BasicEnd-BasicStart, 10

    ORG 32768

    DEVICE ZXSPECTRUM48
    ORG $8000

start:
    ; Rotina de teste de teclado do Sr. Jones.
ktest:
    ld c,a             ; tecla a testar em c.
    and 7              ; mascarar bits d0-d2 para a linha.
    inc a              ; no intervalo 1-8.
    ld b,a             ; colocar em b.
    srl c              ; dividir c por 8,
    srl c
    srl c              ; para encontrar a posição dentro da linha.
    ld a,5             ; apenas 5 teclas por linha.
    sub c              ; subtrair posição.
    ld c,a             ; colocar em c.
    ld a,254           ; byte alto da porta a ler.
ktest0:
    rrca               ; rodar para a posição.
    djnz ktest0        ; repetir até encontrarmos a porta relevante a ler.
    in a, (254)        ; ler porta (a=alto, 254=baixo).
ktest1:
    rra                ; rodar bit para fora do resultado.
    dec c              ; contador do ciclo.
    jp nz, ktest1      ; repetir até que o bit para a posição esteja no carry.
    ret


    SAVESNA "2_prog5.sna", start
    SAVETAP "2_prog5.tap", CODE, "2_prog5", start, $ - start, start
```

## Desmistificar as Portas Físicas e o Controlo

Nesta encruzilhada de comandos de movimento, torna-se imperativo decifrar como o Spectrum enceta o contacto visceral com o mundo exterior. Para além dos endereços letárgicos de RAM, operados tradicionalmente pelos comuns comandos `ld`, a arquitetura do hardware providencia portas físicas que ligam o miolo do processador aos circuitos externos, tais como a membrana do teclado ou as ranhuras do joystick. 

A invocação central que arromba este cofre é a instrução vital `in a, (254)`. Através deste trâmite cruzado, o processador ausculta o estado elétrico puro estanque à porta 254 (ou no habitual jargão do programador veterano, o afamado feudo de `$FE` hexadecimal), transigindo os seus humores perante o recetáculo do nosso Acumulador `A`. A referida porta assume uma preponderância avassaladora por encarnar valências multifunções; caso invoquemos uma diretiva `IN` nesta morada, a resposta providenciada espelha com exatidão o estado físico da pressão exercida na membrana das teclas. Para orquestrar este varrimento estrito o artífice tira partido da engenhosa disposição do teclado do Spectrum: ele orla fisicamente dividido em oito meias-linhas com um estanque rigoroso alojando exatas cinco teclas. Para apurar eximiamente as intenções da escolha do flanco a averiguar perante a matriz, o processador empurra as amarras de um sinal assente em oito bits derramados nas calhas vertiginosas do barramento colossal de endereços com extensão na faixa dos dezasseis bits absolutos. Operacionalmente, a própria sintaxe do comando `in a, (254)` funciona sub-repticiamente nas vias ocultas como um atalho mestre, ditando inquestionavelmente que a porção guardada presentemente no registo `A` (ou alternativamente no seio do estribo assente no par `BC`) é catapultada vertiginosamente para encimar a metade cimeira alta afeta ao endereço (neste plano redutor `A` impõe e forja sem rodeios a escolha da linha no varrimento ativo do teclado). Condicionante obrigatória na dita leitura dita na imposição de aterrar um bit do registo em nulidade cravada num rotundo `0`, garantindo a iluminação exata balizando na escolha da linha respetiva ativada sob estrito encarte perante o olho clínico da leitura.

A colheita resultante das leituras da porta varre exaustivamente as tranches com os exatos oito bits (o preenchimento dum byte) num estiramento colossal único arremessado de volta. Mas aos meandros práticos perante as labutas, o nosso escrutínio foca inquestionavelmente num minúsculo ponto exato assente e amarrado aos ditames perante um estrito bit ditado pela morada associada dum caráter do teclado cruzado com valências numa direção de comando cravada num controlador de joystick. A decantação destas águas remanescentes barrentas a fim de espelhar o isolamento cirúrgico limpo é alcançada com mestria pelas ferramentas batizadas universalmente "máscaras de bits", que encarnam na linguagem sob a figuração operatória assente na premissa lógica imperativa da diretiva `and`. A referida operação matemática submete os pares de bits transacionados na mesa num despique comparativo cruel a rasar em eliminação e negação cega, sobrevivendo estritamente afirmado incólume a imposição redonda num vitorioso `1` caso as duas barricadas defrontantes clamem igual glória num uníssono `1`. Desta forma o estribo operatório assente via `and 7` foca a comparação da orla do registo matriz face à negação ditada pela base matemática encastrada cega dum valor recheado estrito pela orla de contorno natural em binário `00000111`. Com tal manobra arrasadora, a máquina limpa no embate impiedoso obliterando todos e íntegros cinco estáticos baluartes com os maiores pesos vitais do cume encastrado e reduz com negação liminar cega o rescaldo remetendo tudo a nulidades, encostando sobreviventes ilesos isolados cravados num resguardo na estrita decantação impoluta para o recheio cravado contíguo exato encabeçando os três bits base e balizados (no ditame das suas margens de origem associados como 0, 1 e as franjas balizadas a encerrar perante o estrito flanco cravado a 2).

Por rescaldo finda esta orquestração matemática depara-se inquestionável a manobra de rodar e fletir de forma física nas linhas as tranches. É sabido de origem e fundição perante o baluarte processual do Z80 um arsenal imperioso na orquestração cirúrgica ditado perante deslocamentos escorreitos contíguos rodopiantes de calhas fletindo perante comandos nas tranches de bits empurrando nas frentes para os flancos laterais, ora descendo na escada em abismo pela margem direita ou ascendendo vigorosamente cruzando limites atirando cegamente esquerdo em cima das trincheiras esgotadas contíguas. 
Neste escopo de mnemónicas imperativas repousa no pedestal glorioso o clássico da lufa de comando `rrca` (Rotate Right Circular Accumulator), encarregue e batizado com o dever inquestionável assente de varrer e rolar todos íntegros estribos da malha do Acumulador assente empurrando na esteira contígua rodando as casas contáveis avançando os pilares cravados em matriz atirando cego contíguo de uma casa perante direita contígua; a premissa engenhosa subverte o abismo natural impondo preceitos cíclicos espantosos perante o derradeiro pilar encabeçando e arrastando nos recantos encurralado na parede na ponta dita base exata extremidade absoluta da ilharga base da orla ditada balizada na contagem contígua o 0 e atirando como resgate de morte o despenho e salvando "dando volta" numa arrojada cambalhota cega repescando o limite cimeiro recriado na franja vital recheando no engate transposto ao salto fixando o topo exato colado à esquerda matriz (na casa dita exata no 7).
