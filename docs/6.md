# Capítulo Seis - Tabelas

## Os Inimigos Não Vêm Um de Cada Vez

Digamos, a título de exemplo, que estávamos a escrever um jogo *Space Invaders* com onze colunas, cada uma contendo cinco linhas de invasores. Seria impraticável escrever o código para cada um dos cinquenta e cinco alienígenas à vez, por isso precisamos de configurar uma tabela. Em Sinclair BASIC, poderíamos fazer isto definindo três matrizes (arrays) de cinquenta e cinco elementos – uma para as coordenadas x dos invasores, uma para as coordenadas y e uma terceira para o byte de estado (status). Poderíamos fazer algo semelhante em montador (assembler) configurando três tabelas de cinquenta e cinco bytes cada na memória, e depois adicionando o número correspondente a cada alienígena ao início de cada tabela para aceder ao elemento individual. Infelizmente, isso seria lento e complexo.

Um método muito melhor é agrupar os três elementos de dados de cada invasor numa estrutura e, em seguida, ter cinquenta e cinco destas estruturas numa tabela. Podemos então apontar `HL` para o endereço de cada invasor, sabendo que `HL` aponta para o byte de estado, `HL` mais um aponta para a coordenada x, e `HL` mais dois aponta para a coordenada y. O código para mostrar um alienígena seria algo assim:

```assembly
    ld hl,aliens        ; estruturas de dados dos alienígenas.
    ld b,55             ; número de alienígenas.
loop0:
    call show           ; mostrar este alienígena.
    djnz loop0          ; repetir para todos os alienígenas.
    ret

show:
    ld a,(hl)           ; obter estado do alienígena.
    cp 255              ; o alienígena está desligado?
    jr z,next           ; sim, por isso não o mostramos.
    push hl             ; guardar endereço do alienígena na pilha.
    inc hl              ; apontar para a coordenada x.
    ld d,(hl)           ; obter coordenada.
    inc hl              ; apontar para a coordenada y.
    ld e,(hl)           ; obter coordenada.
    call disply         ; mostrar alienígena em (d,e).
    pop hl              ; recuperar endereço do alienígena da pilha.
next:
    ld de,3             ; tamanho de cada entrada na tabela de alienígenas.
    add hl,de           ; apontar para o próximo alienígena.
    ret                 ; deixa hl a apontar para o próximo.
```

## Usar os Registos de Índice

O inconveniente desta rotina é que temos de ter muito cuidado com a posição para onde `HL` está a apontar a cada momento. Uma ideia seria guardar `HL` numa posição de memória temporária de dois bytes antes de chamar `show`, restaurando-o depois, adicionando três no final do ciclo principal e executando a instrução `djnz`. Se estivéssemos a escrever para o Nintendo GameBoy, com o seu CPU Z80 reduzido, esta seria provavelmente a nossa melhor opção. Em máquinas com processadores mais avançados, como o Spectrum e o Amstrad CPC464, podemos usar os registos de índice, `IX`, para simplificar um pouco o nosso código. Como o par de registos `IX` permite-nos deslocar o nosso endereçamento indireto, podemos apontar `IX` para o início da estrutura de dados de um alienígena e aceder a todos os elementos dentro dela sem a necessidade de alterar o valor de `IX` novamente. Usando `IX`, a nossa rotina de exibição de alienígenas poderia ser assim:

```assembly
    ld ix,aliens        ; estruturas de dados dos alienígenas.
    ld b,55             ; número de alienígenas.
loop0:
    call show           ; mostrar este alienígena.
    ld de,3             ; tamanho de cada entrada na tabela de alienígenas.
    add ix,de           ; apontar para o próximo alienígena.
    djnz loop0          ; repetir para todos os alienígenas.
    ret

show:
    ld a,(ix)           ; obter estado do alienígena.
    cp 255              ; o alienígena está desligado?
    ret z               ; sim, por isso não o mostramos.
    ld d,(ix+1)         ; obter coordenada x.
    ld e,(ix+2)         ; obter coordenada y.
    jp disply           ; mostrar alienígena em (d,e).
```

Usar `IX` significa que apenas precisamos de apontar para o início da estrutura de dados de um alienígena, pelo que `IX` retornará sempre o estado do invasor atual, `IX+1` a coordenada x, e assim sucessivamente. Este método permite ao programador usar estruturas de dados complexas para os seus alienígenas com até 128 bytes de comprimento, sem se confundir sobre para qual parte da estrutura os registos estão a apontar a cada momento, ao contrário do exemplo anterior com `HL`. Infelizmente, usar `IX` é um pouco mais lento do que usar `HL`, por isso não o devemos utilizar para tarefas de processamento mais intensivas, como a manipulação de gráficos.

Vamos aplicar este método ao nosso jogo Centipede. Em primeiro lugar, precisamos de decidir quantos segmentos são necessários e quais os dados a guardar sobre cada segmento. No nosso jogo, os segmentos precisarão de se mover para a esquerda ou para a direita até atingirem um cogumelo, descendo depois para voltar na direção oposta. Assim, parece que precisaremos de uma flag para indicar a direção específica em que um segmento se está a deslocar, além de uma coordenada x ou y. A nossa flag também pode ser usada para indicar que um determinado segmento foi destruído.

Com isto em mente, podemos configurar uma estrutura de dados de três bytes:

```assembly
centf: defb 0        ; flag: 0=esquerda, 1=direita, 255=morto.
centx: defb 0        ; coordenada x do segmento (vertical).
centy: defb 0        ; coordenada y do segmento (horizontal).
```

Se optarmos por ter dez segmentos na nossa centopeia, precisamos de reservar um espaço na tabela de trinta bytes. Cada segmento precisa de ser inicializado no início e depois apagado, movido e mostrado novamente durante o jogo.

Inicializar os nossos segmentos é provavelmente a tarefa mais simples, pelo que podemos usar um ciclo simples que incrementa o par de registos `HL` para cada byte antes de o definir. Algo como isto costuma resolver o problema:

```assembly
    ld b,10             ; número de segmentos a inicializar.
    ld hl,segmnt        ; tabela de segmentos.
segint: ld (hl),1    ; começar por mover para a direita.
    inc hl
    ld (hl),0           ; começar no topo (x=0).
    inc hl
    ld (hl),b           ; usar o registo B como coordenada y.
    inc hl
    djnz segint         ; repetir até que todos estejam inicializados.
```

Processar e mostrar cada segmento será ligeiramente mais complicado, pelo que usaremos os registos `IX` para isso. Precisamos de escrever um algoritmo simples que manipule um único segmento para a esquerda ou para a direita até atingir um cogumelo, movendo-o depois para baixo e invertendo a sua direção. Chamaremos a esta rotina `proseg` (de *process segment*) e configuraremos um ciclo que aponta para cada segmento sucessivamente e chama `proseg`. Desde que o algoritmo de movimento esteja correto, deveremos ver a centopeia a serpentear através dos cogumelos. Aplicar isto ao nosso código é simples – verificamos o byte da flag de cada segmento (`IX`) para ver em que direção ele se move, incrementamos ou decrementamos a coordenada horizontal (`IX+2`) em conformidade e depois verificamos o atributo nessa célula de caráter. Se for verde e preto, incrementamos a coordenada vertical (`IX+1`) e invertemos a flag de direção (`IX`).

Existem mais algumas coisas a considerar, como atingir os lados ou o fundo do ecrã, mas isso é apenas uma questão de verificar as coordenadas do segmento e inverter a direção ou movê-lo para o topo do ecrã quando necessário. Os segmentos também precisam de ser apagados das suas posições antigas antes de serem movidos, e depois mostrados novamente nas suas novas posições, mas já cobrimos os passos necessários para realizar essas tarefas.

O nosso novo código fica assim:

```assembly
        DEVICE ZXSPECTRUM48
        ORG 32768
start:
    ; Queremos um ecrã preto.
    ld a,71             ; tinta branca (7) em papel preto (0), brilho (64).
    ld (23693),a        ; definir as cores do nosso ecrã.
    xor a               ; forma rápida de carregar o acumulador com zero.
    call 8859           ; definir as cores permanentes da margem.

    ; Configurar os gráficos.
    ld hl,blocks        ; endereço dos dados dos gráficos definidos pelo utilizador.
    ld (23675),hl       ; fazer os UDGs apontarem para aí.

    ; Ok, vamos iniciar o jogo.
    call 3503           ; rotina da ROM que limpa o ecrã, abre o canal 2.

    ; Inicializar coordenadas.
    ld hl,21+15*256     ; carregar par hl com coordenadas iniciais.
    ld (plx),hl         ; definir as coordenadas do jogador.
    ld b,10             ; número de segmentos.
    ld hl,segmnt        ; tabela de segmentos.
segint: ld (hl),1    ; começar a mover para a direita.
    inc hl
    ld (hl),0           ; coordenada x inicial (topo).
    inc hl
    ld (hl),b           ; coordenada y inicial (usando b).
    inc hl
    djnz segint         ; repetir para os 10 segmentos.
    call basexy         ; definir as posições x e y do jogador.
    call splayr         ; mostrar símbolo da base do jogador.

    ; Agora queremos encher a área de jogo com cogumelos.
    ld a,68             ; tinta verde (4) em papel preto (0), brilho (64).
    ld (23695),a        ; definir as nossas cores temporárias.
    ld b,50             ; começar com alguns.
mushlp: ld a,22      ; código de controlo para o caráter AT.
    rst 16
    call random         ; obter um número "aleatório".
    and 15              ; queremos a coordenada vertical no intervalo de 0 a 15.
    rst 16
    call random         ; obter outro número pseudoaleatório.
    and 31              ; queremos a coordenada horizontal no intervalo de 0 a 31.
    rst 16
    ld a,145            ; UDG 'B' é o gráfico do cogumelo.
    rst 16              ; colocar cogumelo no ecrã.
    djnz mushlp         ; ciclo de volta até que todos os cogumelos sejam mostrados.

    ; Este é o ciclo principal.
mloop: equ $

    ; Apagar o jogador.
    call basexy         ; definir as posições x e y do jogador.
    call wspace         ; mostrar espaço sobre o jogador.

    ; Agora que apagámos o jogador, podemos movê-lo antes de o voltar a mostrar
    ; nas suas novas coordenadas.
    ld bc,63486         ; linha do teclado 1-5 / porta do joystick 2.
    in a,(c)            ; ver que teclas estão pressionadas.
    rra                 ; bit mais exterior = tecla 1.
    push af             ; lembrar o valor.
    call nc,mpl         ; está a ser pressionada, mover para a esquerda.
    pop af              ; restaurar acumulador.
    rra                 ; próximo bit (valor 2) = tecla 2.
    push af             ; lembrar o valor.
    call nc,mpr         ; está a ser pressionada, mover para a direita.
    pop af              ; restaurar acumulador.
    rra                 ; próximo bit (valor 4) = tecla 3.
    push af             ; lembrar o valor.
    call nc,mpd         ; está a ser pressionada, mover baixo.
    pop af              ; restaurar acumulador.
    rra                 ; próximo bit (valor 8) = tecla 4.
    call nc,mpu         ; está a ser pressionada, mover cima.

    ; Agora que se moveu, podemos voltar a mostrar o jogador.
    call basexy         ; definir as posições x e y do jogador.
    call splayr         ; mostrar o jogador.

    ; Agora processar os segmentos da centopeia.
    ld ix,segmnt        ; tabela de dados dos segmentos.
    ld b,10             ; número de segmentos na tabela.
censeg: push bc
    ld a,(ix)           ; o segmento está ativo?
    inc a               ; 255=desligado, incrementa para zero.
    call nz,proseg      ; está ativo, processar segmento.
    pop bc
    ld de,3             ; 3 bytes por segmento.
    add ix,de           ; obter próximo segmento nos registos ix.
    djnz censeg         ; repetir para todos os segmentos.
    halt                ; atraso.

    ; Saltar de volta para o início do ciclo principal.
    jp mloop

    ; Mover jogador para a esquerda.
mpl:
    ld hl,ply           ; lembre-se, y é a coordenada horizontal!
    ld a,(hl)           ; qual é o valor atual?
    and a               ; é zero?
    ret z               ; sim, não podemos ir mais para a esquerda.

    ; agora verificar se não há um cogumelo no caminho.
    ld bc,(plx)         ; coordenadas atuais.
    dec b               ; olhar 1 quadrado para a esquerda.
    call atadd          ; obter endereço do atributo nesta posição.
    cp 68               ; cogumelos são brilho (64) + verde (4).
    ret z               ; há um cogumelo - não nos podemos mover para lá.

    dec (hl)            ; subtrair 1 à coordenada y.
    ret

    ; Mover jogador para a direita.
mpr:
    ld hl,ply           ; lembre-se, y é a coordenada horizontal!
    ld a,(hl)           ; qual é o valor atual?
    cp 31               ; está na extremidade direita (31)?
    ret z               ; sim, não podemos ir mais para a direita.

    ; agora verificar se não há um cogumelo no caminho.
    ld bc,(plx)         ; coordenadas atuais.
    inc b               ; olhar 1 quadrado para a direita.
    call atadd          ; obter endereço do atributo nesta posição.
    cp 68               ; cogumelos são brilho (64) + verde (4).
    ret z               ; há um cogumelo - não nos podemos mover para lá.

    inc (hl)            ; adicionar 1 à coordenada y.
    ret

    ; Mover jogador para cima.
mpu:
    ld hl,plx           ; lembre-se, x é a coordenada vertical!
    ld a,(hl)           ; qual é o valor atual?
    cp 4                ; está no limite superior (4)?
    ret z               ; sim, não podemos ir mais para cima.

    ; agora verificar se não há um cogumelo no caminho.
    ld bc,(plx)         ; coordenadas atuais.
    dec c               ; olhar 1 quadrado para cima.
    call atadd          ; obter endereço do atributo nesta posição.
    cp 68               ; cogumelos são brilho (64) + verde (4).
    ret z               ; há um cogumelo - não nos podemos mover para lá.

    dec (hl)            ; subtrair 1 à coordenada x.
    ret

    ; Mover jogador para baixo.
mpd:
    ld hl,plx           ; lembre-se, x é a coordenada vertical!
    ld a,(hl)           ; qual é o valor atual?
    cp 21               ; já está no fundo (21)?
    ret z               ; sim, não podemos descer mais.

    ; agora verificar se não há um cogumelo no caminho.
    ld bc,(plx)         ; coordenadas atuais.
    inc c               ; olhar 1 quadrado para baixo.
    call atadd          ; obter endereço do atributo nesta posição.
    cp 68               ; cogumelos são brilho (64) + verde (4).
    ret z               ; há um cogumelo - não nos podemos mover para lá.

    inc (hl)            ; adicionar 1 à coordenada x.
    ret

    ; Configurar as coordenadas x e y para a posição da base/arma do jogador,
    ; esta rotina é chamada antes da visualização e eliminação da base.
basexy: ld a,22      ; código AT.
    rst 16
    ld a,(plx)          ; coordenada vertical do jogador.
    rst 16              ; definir posição vertical do jogador.
    ld a,(ply)          ; posição horizontal do jogador.
    rst 16              ; definir a coordenada horizontal.
    ret

    ; Mostrar o jogador na posição de impressão atual.
splayr: ld a,69      ; tinta ciano (5) no papel preto (0), brilho (64).
    ld (23695),a        ; definir as nossas cores de ecrã temporárias.
    ld a,144            ; código ASCII para UDG 'A'.
    rst 16              ; desenhar o jogador.
    ret

wspace: ld a,71      ; tinta branca (7) no papel preto (0), brilho (64).
    ld (23695),a        ; definir as nossas cores de ecrã temporárias.
    ld a,32             ; caráter de ESPAÇO.
    rst 16              ; mostrar espaço.
    ret

segxy: ld a,22       ; ASCII para caráter AT.
    rst 16              ; mostrar código AT.
    ld a,(ix+1)         ; obter coordenada x do segmento.
    rst 16              ; mostrar código de coordenada.
    ld a,(ix+2)         ; obter coordenada y do segmento.
    rst 16              ; mostrar código de coordenada.
    ret

proseg: ld a,(ix)    ; verificar se o segmento foi desligado
    inc a               ; pela rotina de deteção de colisões.
    ret z               ; estava desativado, logo o segmento está morto.
    call segxy          ; configurar coordenadas do segmento.
    call wspace         ; mostrar um espaço (tinta branca em papel preto).
    call segmov         ; mover segmento.
    ld a,(ix)           ; verificar se o segmento foi desligado
    inc a               ; pela rotina de deteção de colisões.
    ret z               ; estava desativado, logo o segmento está morto.
    call segxy          ; configurar coordenadas do segmento.
    ld a,2              ; código de atributo 2 = segmento vermelho.
    ld (23695),a        ; definir atributos temporários.
    ld a,146            ; UDG 'C' para mostrar o segmento.
    rst 16              ; desenhar segmento.
    ret

segmov: ld a,(ix+1)  ; coordenada x.
    ld c,a              ; área GP x.
    ld a,(ix+2)         ; coordenada y.
    ld b,a              ; área GP y.
    ld a,(ix)           ; byte de estado.
    and a               ; o segmento está a ir para a esquerda?
    jr z,segml          ; a ir para a esquerda - saltar para essa secção.

    ; caso contrário, o segmento está a ir para a direita!
segmr: ld a,(ix+2)   ; coordenada y.
    cp 31               ; já está no limite direito do ecrã?
    jr z,segmd          ; sim - mover segmento para baixo.
    inc a
    ld b,a              ; olhar para a direita.
    call atadd          ; obter endereço de atributo.
    cp 68               ; cogumelos são brilho (64) + verde (4).
    jr z,segmd          ; cogumelo à direita, mover para baixo.
    inc (ix+2)          ; sem obstáculos, mover para a direita.
    ret

    ; caso contrário, o segmento está a ir para a esquerda!
segml: ld a,(ix+2)   ; coordenada y.
    and a               ; já está no limite esquerdo do ecrã?
    jr z,segmd          ; sim - mover segmento para baixo.
    dec a
    ld b,a              ; olhar para a esquerda.
    call atadd          ; obter endereço de atributo em (dispx,dispy).
    cp 68               ; cogumelos são brilho (64) + verde (4).
    jr z,segmd          ; cogumelo à esquerda, mover para baixo.
    dec (ix+2)          ; sem obstáculos, mover para a esquerda.
    ret

    ; caso contrário, o segmento está a ir para baixo!
segmd: ld a,(ix)     ; direção do segmento.
    xor 1               ; inverter direção.
    ld (ix),a           ; guardar nova direção.
    ld a,(ix+1)         ; coordenada y.
    cp 21               ; já está no fundo do ecrã?
    jr z,segmt          ; sim - mover segmento para o topo.

    ; Neste ponto, movemo-nos para baixo independentemente de quaisquer
    ; cogumelos que possam bloquear o caminho do segmento. Qualquer coisa
    ; no caminho do segmento será obliterada.
    inc (ix+1)          ; ainda não chegou ao fundo, mover para baixo.
    ret

    ; mover segmento para o topo do ecrã.
segmt: xor a         ; o mesmo que ld a,0, mas poupa 1 byte.
    ld (ix+1),a         ; nova coordenada x = topo do ecrã.
    ret

    ; Gerador simples de números pseudoaleatórios.
    ; Avança um ponteiro através da ROM (guardado em seed), retornando
    ; o conteúdo do byte nessa posição.
random: ld hl,(seed)
    ld a,h
    and 31
    ld h,a              ; manter nos primeiros 8K da ROM.
    ld a,(hl)           ; obter número "aleatório" da posição.
    inc hl              ; incrementar ponteiro.
    ld (seed),hl
    ret
seed:
    defw 0              ; ponteiro

    ; Calcular endereço do atributo para o caráter em (dispx, dispy).
atadd:
    ld a,c              ; coordenada vertical.
    rrca
    rrca
    rrca                ; multiplicar por 32.
    ld e,a              ; Rodar para a direita com carry 3 vezes é
    and 3               ; mais rápido do que rodar para a esquerda 5 vezes.
    add a,88            ; 88x256=endereço dos atributos.
    ld d,a
    ld a,e
    and 224
    ld e,a
    ld a,b              ; posição horizontal.
    add a,e             ; de=endereço dos atributos.
    ld e,a
    ld a,(de)           ; retornar com atributo no acumulador.
    ret

plx: defb 0          ; coordenada x do jogador.
ply: defb 0          ; coordenada y do jogador.

    ; Gráficos UDG.
blocks: defb 16,16,56,56,124,124,254,254  ; base do jogador.
    defb 24,126,255,255,60,60,60,60          ; cogumelo.
    defb 24,126,126,255,255,126,126,24        ; segmento.

    ; Tabela de segmentos.
    ; Formato: 3 bytes por entrada, 10 segmentos.
    ; byte 1: 255=segmento desligado, 0=esquerda, 1=direita.
    ; byte 2 = coordenada x (vertical).
    ; byte 3 = coordenada y (horizontal).
segmnt: defb 0,0,0   ; segmento 1.
    defb 0,0,0          ; segmento 2.
    defb 0,0,0          ; segmento 3.
    defb 0,0,0          ; segmento 4.
    defb 0,0,0          ; segmento 5.
    defb 0,0,0          ; segmento 6.
    defb 0,0,0          ; segmento 7.
    defb 0,0,0          ; segmento 8.
    defb 0,0,0          ; segmento 9.
    defb 0,0,0          ; segmento 10.
fim:

; --- Carregador BASIC + ficheiro .tap (igual em todos os exemplos) ---
        ORG 23755
basic:  db 0,10                 ; 10 CLEAR 32767: LOAD "" CODE: RANDOMIZE USR 32768
        dw basic_fim-basic-4
        db $FD,$B0,'"32767":',$EF,'""',$AF,':',$F9,$C0,$B0,'"32768"',13
basic_fim:
        EMPTYTAP "cap06_1.tap"
        SAVETAP  "cap06_1.tap",BASIC,"cap06_1",basic,basic_fim-basic,10
        SAVETAP  "cap06_1.tap",CODE,"cap06_1",start,fim-start
```

## Notas

* Nas duas versões da rotina dos alienígenas, a etiqueta `loop0` fica depois de `ld hl,aliens` (ou `ld ix,aliens`) e de `ld b,55`. Se ficasse antes, o ponteiro e o contador seriam repostos em cada volta e o ciclo nunca terminaria. Repare também que `disply` tem de preservar o registo `b`, porque é o contador do `djnz`.
* `(ix+n)` lê o byte que está `n` posições depois do endereço em `ix`, sem alterar `ix`. O deslocamento `n` vai de −128 a +127, e é por isso que cada estrutura pode ter até 128 bytes acessíveis a partir do início.
* No jogo, um segmento morto tem a flag a 255. A rotina `proseg` deteta-o com `inc a` seguido de `ret z`: 255 + 1 dá 0 num registo de 8 bits e a flag Z fica ativa.
