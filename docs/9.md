# Capítulo Nono - Gráficos de Fundo

## Mostrar Blocos

Digamos que queremos escrever um jogo de labirinto num único ecrã. Precisamos de mostrar as paredes à volta das quais o *sprite* do jogador deve ser manipulado, e a melhor forma de o fazer é criar uma tabela de blocos que são transferidos para o ecrã sequencialmente. À medida que percorremos a tabela, encontramos o endereço do gráfico do bloco, calculamos o endereço do ecrã e enviamos o caráter para o ecrã.

Começaremos com a rotina de exibição de caracteres. Ao contrário de uma rotina de *sprites*, precisamos de lidar com posições de caracteres, e felizmente é mais fácil calcular um endereço de ecrã para uma posição de caráter do que para píxeis individuais.

Existem 24 posições verticais e 32 posições horizontais de células de caracteres no ecrã do Spectrum, pelo que as nossas coordenadas estarão entre (0,0) e (23,31). As linhas 0 a 7 caem no primeiro segmento, as linhas 8 a 15 na secção central, e as posições 16 a 23 na terceira parte do ecrã. Por sorte, o byte alto do endereço de ecrã de cada segmento aumenta em 8 de um segmento para o seguinte, pelo que, ao pegar no número da célula vertical e realizar um `and 24`, obtemos imediatamente o deslocamento para o início do endereço do segmento relevante do ecrã. Adicione 64 para o início do ecrã do Spectrum e temos o byte alto do nosso endereço. Precisamos depois de encontrar a célula de caráter correta dentro de cada segmento, por isso pegamos novamente na coordenada vertical, e desta vez usamos `and 7` para determinar qual das sete linhas estamos a tentar encontrar. Multiplicamos este valor pela largura de caracteres do ecrã (32) e adicionamos o número da célula horizontal para encontrar o byte baixo do endereço de ecrã. Um exemplo adequado encontra-se abaixo:

```assembly
    EMPTYTAP "9_prog1.tap"

    ; --- BASIC loader ---
    ORG $5D00
BasicStart:
    db 0,10
    dw Line1End-Line1Start
Line1Start:
    db $fd, $b0, $22, "32767", $22, $0d
Line1End:
    db 0,20
    dw Line2End-Line2Start
Line2Start:
    db $ef, $22, $22, $af, $0d
Line2End:
    db 0,30
    dw Line3End-Line3Start
Line3Start:
    db $f9, $c0, $b0, $22, "32768", $22, $0d
Line3End:
BasicEnd:
    SAVETAP "9_prog1.tap", BASIC, "loader", BasicStart, BasicEnd-BasicStart, 10

    ORG 32768

    DEVICE ZXSPECTRUM48
    ORG $8000

start:
    ; Retornar endereço da célula de caráter do bloco em (b, c).
chadd:
    ld a,b              ; posição vertical.
    and 24              ; qual o segmento: 0, 1 ou 2?
    add a,64            ; 64*256 = 16384, memória de ecrã do Spectrum.
    ld d,a              ; este é o nosso byte alto.
    ld a,b              ; qual era a posição vertical mesmo?
    and 7               ; qual a linha dentro do segmento?
    rrca
    rrca
    rrca                ; multiplicar linha por 32.
    ld e,a              ; byte baixo.
    ld a,c              ; obter coordenada y (horizontal).
    add a,e             ; somar ao byte baixo.
    ld e,a              ; de = endereço da posição do ecrã.
    ret


    SAVESNA "9_prog1.sna", start
    SAVETAP "9_prog1.tap", CODE, "9_prog1", start, $ - start, start
```

Assim que tivermos o nosso endereço de ecrã, o processo de desenhar o caráter no ecrã é direto. Desde que não estejamos a cruzar limites de células de caracteres, a linha de ecrã seguinte cairá sempre 256 bytes após a anterior, pelo que incrementamos o byte alto do endereço para encontrar a linha seguinte.

```assembly
    EMPTYTAP "9_prog2.tap"

    ; --- BASIC loader ---
    ORG $5D00
BasicStart:
    db 0,10
    dw Line1End-Line1Start
Line1Start:
    db $fd, $b0, $22, "32767", $22, $0d
Line1End:
    db 0,20
    dw Line2End-Line2Start
Line2Start:
    db $ef, $22, $22, $af, $0d
Line2End:
    db 0,30
    dw Line3End-Line3Start
Line3Start:
    db $f9, $c0, $b0, $22, "32768", $22, $0d
Line3End:
BasicEnd:
    SAVETAP "9_prog2.tap", BASIC, "loader", BasicStart, BasicEnd-BasicStart, 10

    ORG 32768

    DEVICE ZXSPECTRUM48
    ORG $8000

start:
    ; Mostrar caráter hl em (b, c).
char:
    call chadd          ; encontrar endereço de ecrã para o caráter.
    ld b,8              ; número de píxeis de altura.
char0:
    ld a,(hl)           ; gráfico de origem.
    ld (de),a           ; transferir para o ecrã.
    inc hl              ; seguintes dados.
    inc d               ; próxima linha de píxeis.
    djnz char0          ; repetir.
    ret



; --- Mocks para compilação autónoma ---
chadd: ret

    SAVESNA "9_prog2.sna", start
    SAVETAP "9_prog2.tap", CODE, "9_prog2", start, $ - start, start
```

Quanto à coloração do nosso bloco, cobrimos isso no capítulo sobre a deteção simples de colisões por atributos. A rotina `atadd` dar-nos-á o endereço de uma célula de atributo na célula de caráter (b, c).

Por último, precisamos de decidir qual bloco mostrar em cada posição de célula. Digamos que precisamos de 3 tipos de blocos para o nosso jogo – poderíamos usar o bloco tipo 0 para um espaço, 1 para uma parede e 2 para uma chave. Organizaríamos os gráficos e atributos de cada bloco em tabelas separadas na mesma ordem:

```assembly
    EMPTYTAP "9_prog3.tap"

    ; --- BASIC loader ---
    ORG $5D00
BasicStart:
    db 0,10
    dw Line1End-Line1Start
Line1Start:
    db $fd, $b0, $22, "32767", $22, $0d
Line1End:
    db 0,20
    dw Line2End-Line2Start
Line2Start:
    db $ef, $22, $22, $af, $0d
Line2End:
    db 0,30
    dw Line3End-Line3Start
Line3Start:
    db $f9, $c0, $b0, $22, "32768", $22, $0d
Line3End:
BasicEnd:
    SAVETAP "9_prog3.tap", BASIC, "loader", BasicStart, BasicEnd-BasicStart, 10

    ORG 32768

    DEVICE ZXSPECTRUM48
    ORG $8000

start:
blocks: equ $
    ; bloco 0 = caráter de espaço.
    defb 0,0,0,0,0,0,0,0
    ; bloco 1 = parede.
    defb 1,1,1,255,16,16,16,255
    ; bloco 2 = chave.
    defb 6,9,9,14,16,32,80,32

attrs: equ $
    ; bloco 0 = espaço.
    defb 71
    ; bloco 1 = parede.
    defb 22
    ; bloco 2 = chave.
    defb 70


    SAVESNA "9_prog3.sna", start
    SAVETAP "9_prog3.tap", CODE, "9_prog3", start, $ - start, start
```

À medida que avançamos pela nossa tabela de até 24 linhas e 32 colunas de blocos de labirinto, carregamos o número do bloco no acumulador e chamamos as rotinas `fblock` e `fattr` abaixo para obter os endereços gráficos e de atributos de origem.

```assembly
    EMPTYTAP "9_prog4.tap"

    ; --- BASIC loader ---
    ORG $5D00
BasicStart:
    db 0,10
    dw Line1End-Line1Start
Line1Start:
    db $fd, $b0, $22, "32767", $22, $0d
Line1End:
    db 0,20
    dw Line2End-Line2Start
Line2Start:
    db $ef, $22, $22, $af, $0d
Line2End:
    db 0,30
    dw Line3End-Line3Start
Line3Start:
    db $f9, $c0, $b0, $22, "32768", $22, $0d
Line3End:
BasicEnd:
    SAVETAP "9_prog4.tap", BASIC, "loader", BasicStart, BasicEnd-BasicStart, 10

    ORG 32768

    DEVICE ZXSPECTRUM48
    ORG $8000

start:
    ; Encontrar gráfico da célula.
fblock:
    rlca
    rlca
    rlca                ; multiplicar número do bloco por oito.
    ld e,a              ; deslocamento para o endereço gráfico.
    ld d,0              ; sem byte alto.
    ld hl,blocks        ; endereço dos blocos de caracteres.
    add hl,de           ; apontar para o bloco.
    ret

    ; Encontrar atributo da célula.
fattr:
    ld e,a              ; deslocamento para o endereço de atributo.
    ld d,0              ; sem byte alto.
    ld hl,attrs         ; endereço dos atributos dos blocos.
    add hl,de           ; apontar para o atributo.
    ret



; --- Mocks para compilação autónoma ---
attrs: defb 0
blocks: defb 0

    SAVESNA "9_prog4.sna", start
    SAVETAP "9_prog4.tap", CODE, "9_prog4", start, $ - start, start
```

Usar este método significa que os dados do nosso labirinto requerem um byte de RAM por cada célula de caráter. Para uma área de jogo com 32 células de largura e 16 blocos de altura, isto significaria que cada ecrã ocuparia 512 bytes de memória. Isso seria aceitável para um jogo de plataformas de 20 ecrãs como *Manic Miner*, mas se pretender cem ecrãs ou mais, deverá considerar usar blocos maiores para que sejam necessários menos blocos por ecrã. Ao usar blocos de células de caracteres que têm 16 x 16 píxeis em vez de 8 x 8 no nosso exemplo, cada tabela de ecrã exigiria apenas 128 bytes, o que significa que se poderiam espremer mais ecrãs na memória do Spectrum.

## A Orquestração Tática das Matrizes de Tijolos

Na odisseia subjacente a forrar os fundos e labirintos inultrapassáveis de um jogo de cariz estático a proeza de erguer cenários roga perante um ditame estrito de condensação operatória cravada na memória ditando a arquitetura vulgamente reconhecida na arte dos jogos por blocos amarrados em repetição pura de painéis encaixados (os tiles). Cravar um rasto ditado píxel a píxel à força bruta exigiria da nossa RAM no ZX Spectrum um calvário asfixiante afeto a mais de seis quilobytes exatos unicamente para forrar o mero fundo da área do visor; porventura uma ostentação proibitiva caso almejemos um ecrã cravado em animações de avatar. Deste desígnio cimentou-se o recurso estrito a moldes balizados perante grelhas e painéis unitários cravados em matrizes cegas sob forma tabular invocando de base uma mera etiqueta afeta ao número base (com um zero a atestar estritamente para vácuo sideral cego e um exato número mestre unitário `1` resvalando no estrado perante a impiedosa barreira cega e rígida da parede e os demais a ditar chão afeto).
O encarte cego e unitário afeto a cada pedaço da máscara a atirar da parede transigida atesta e exibe invariavelmente uma reserva balizada nos ditos e precisos oitos bytes absolutos da matriz perante a estrita memória RAM correspondendo fisicamente à fenda horizontal duma valência deitada por oitos e oitos linhas cravadas. Neste bailado encontrar cego na paleta matriz da panela amarrada em valência o início onde repousa o molde virgem do bloco com etiqueta identificativa decalcada sob o número `N` força a engrenagem ditar cabalmente via formula base o atirar no recetáculo da origem via endereço base fundido à conta de `N` atirado ao extremo esticado exato dos blocos multiplicado fletido pelas oito valências das linhas exatas num assalto avante.

Esta alquimia dita no avanço dita no varrer vertiginoso atirando cega e subtilmente transacionado à nossa cirúrgica matriz na finta das entranhas exposta e desnudada em submissão operatória balizada na letal rotina fundacional assente à mnemónica por `fblock`. Para a finta operar transigida no regente primário no Acumulador deitando estrito a etiqueta em cego avanço a engrenagem dita cabal batendo triplo um arrasto fletindo de estribeira num golpe lateral batizado no dicionário z80 perante a invocação de `rlca`. Este esvaziar circular à esquerda não traduz mera manobra atoa; perante o rigor dos trâmites binários embutir todos e quaisquer valores num passo atirado forçado arrastando casas rumo à esquerda decalcando as fintas da sua casa matriz dita uma duplicação matemática inabalável encastrada (a purga matriz da multiplicação empurrando perante o estrito par a dobrar atirando avante base ditada por `2`). Submeter as amarras cegas desta instrução numa cadência impiedosa rodando estritamente cega nos redemoinhos fechados triplicando o seu eco atira e encerra de imediato os rescaldos dum multiplicador exato na ordem exata matriz cravada transigindo perante a valência de oito cravando final e sem atritos ou perdas as oitos matrizes de espaço necessárias a abarcar!
Os despojos decantados da purga arrastam limpos e fletem cabalmente o saldo da etiqueta arrastada atirando-o alojado temporário providencial de resguardo alojando à direita exata contígua em rescaldo afeto a um estrito depósito empurrado ao leito baixo ditando matriz no reservatório fletido sobre `E` enclausurado à retaguarda transacionando em acoplamento numa zerada matriz forçosa via apagão limpando valências do limiar vizinho de `D` cimentando a via operatória e abrindo caminho a alojar a fundação no `DE` cravando a valência originária esticada. Emerge aqui transigido no auge e impulsionando os mastros fletidos ditos a estaca base atirando os faróis apontando cegos originários ao estrito início virgem de alojamento ancorando na rotina matriz apontando a bússola de `HL` ao teto matriz virgem transacionado em repouso da tabela cravando os matrizes puros perante `blocks`. Numa arrancada de esvaziar cego estrita funde no somatório derradeiro atirando em avanço embate letal contíguo de fundição cruzando fletido à morada cravada e atirada e arrastada numa adenda transigida balizando à saciedade num golpe contíguo impiedoso dita `add hl, de`, empurrando imperativo no ponteiro cimentando-o exatamente defronte do exato bloco na vala exata das fatias exigidas das memórias da RAM e resgatando imaculado das trevas a matéria pronta atirando em escape final ao mestre rotineiro devolvendo ao limpo o regresso da pastilha exata e decifrada.
