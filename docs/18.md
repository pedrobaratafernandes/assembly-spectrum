# Capítulo Dezoito - Fazer os Jogos Carregar e Correr Automaticamente

Embora isto seja bastante simples de alcançar para um programador experiente de Sinclair BASIC, é uma área frequentemente negligenciada. Em particular, os programadores que migram para o Spectrum vindos de outras máquinas não estarão familiarizados com a forma como isto é feito.

Para correr uma rotina em código máquina, temos de a iniciar a partir do BASIC. Isto significa escrever um pequeno programa carregador (*loader*) em BASIC, que liberta o espaço para o código máquina, carrega esse código e depois o executa. O tipo mais simples de carregador seria nestas linhas:

`10 CLEAR 24575: LOAD ""CODE: RANDOMIZE USR 24576`

O primeiro comando, `CLEAR`, define o topo da RAM (`RAMTOP`) abaixo da área ocupada pelo código máquina, para que o BASIC não o sobrescreva. Também limpa o ecrã e move a pilha para fora do caminho. O número que se segue deve ser, normalmente, um byte abaixo do primeiro byte do seu jogo. `LOAD ""CODE` carrega o ficheiro de código seguinte presente na fita, e `RANDOMIZE USR` efetivamente chama a rotina de código máquina no endereço especificado, neste caso 24576. Este deve ser o ponto de entrada para o seu jogo.

No Spectrum, a ROM reside nos primeiros 16K, sendo seguida por várias outras coisas, tais como a RAM do ecrã, variáveis de sistema e BASIC. Um local seguro para o seu código é acima desta área, até ao topo da RAM no endereço 65535. Com apenas um curto carregador em BASIC, um endereço de início de 24576, ou mesmo 24000, dar-lhe-á muito espaço para o seu jogo.

Este programa carregador é depois gravado na fita utilizando um comando como este:

`SAVE "nome" LINE 10`

`LINE 10` indica que, ao carregar, o programa BASIC deve ser executado automaticamente a partir da linha 10.

A seguir ao carregador em BASIC vem o ficheiro de código. Pode gravar um ficheiro de código desta forma:

`SAVE "nome" CODE 24576,40960`

`CODE` diz ao Spectrum para gravar um ficheiro de código, por oposição ao BASIC. O primeiro número depois deste é o endereço de início do bloco de código, e o último número é o seu comprimento.

Isto é bastante simples, mas e se quisermos adicionar um ecrã de carregamento (*loading screen*)? Bem, isso é suficientemente fácil. Podemos carregar um ecrã usando:

`LOAD ""SCREEN$`

O que isto fará é carregar um bloco de código de até 6912 bytes de comprimento para o início da visualização do ecrã no endereço 16384. Colocar o ficheiro do ecrã lá é um pouco mais complicado, porque não podemos simplesmente gravar o ecrã diretamente como um ficheiro, visto que as duas linhas inferiores seriam sobrescritas com a mensagem de sistema "Start tape, then press any key". Portanto, carregamos a nossa imagem num ponto da RAM – digamos, 32768 – e depois usamos:

`SAVE "nome" CODE 32768,6912`

6912 é o tamanho da RAM de visualização do Spectrum. Quando recarregamos o bloco a partir da fita usando `LOAD ""SCREEN$`, estamos a especificar que queremos forçar o ficheiro de código a ser carregado na memória do ecrã. Sob estas circunstâncias, não importa onde o ficheiro de código estava localizado quando foi gravado.

Agora temos outro problema: a mensagem "Bytes: nome" que é impressa ao carregar o bloco de código não iria sobrescrever parte do ecrã? Sim, iria. Podemos superar isto fazendo um `poke` no fluxo de saída:

`POKE 23739,111`

Isto resolverá o problema para nós. Assim, o nosso carregador BASIC passa a ser:

`10 CLEAR 24575: LOAD ""SCREEN$: POKE 23739,111: LOAD ""CODE: RANDOMIZE USR 24576`

## Estrutura de um Carregador BASIC em sjasmplus

Para automatizar a criação de fitas virtuais de ZX Spectrum (`.tap`) com o compilador **sjasmplus**, nós não escrevemos código em BASIC no emulador. Em vez disso, programamos a estrutura binária do programa BASIC diretamente no código assembly Z80 através de bytes de dados (`db` ou `defb`).

Abaixo está o bloco de código que utilizamos para gerar e empacotar o carregador no topo da nossa fita:

```assembly
    EMPTYTAP "jogo.tap"

    ; --- BASIC loader ---
    ORG $5D00
BasicStart:
    db 0,10                         ; Linha 10 (número da linha em 2 bytes)
    dw Line1End-Line1Start          ; Comprimento da linha 10
Line1Start:
    db $fd, $b0, $22, "32767", $22, $0d ; CLEAR VAL "32767" + Nova Linha
Line1End:
    db 0,20                         ; Linha 20
    dw Line2End-Line2Start          ; Comprimento da linha 20
Line2Start:
    db $ef, $22, $22, $af, $0d      ; LOAD "" CODE + Nova Linha
Line2End:
    db 0,30                         ; Linha 30
    dw Line3End-Line3Start          ; Comprimento da linha 30
Line3Start:
    db $f9, $c0, $b0, $22, "32768", $22, $0d ; RANDOMIZE USR VAL "32768" + Nova Linha
Line3End:
BasicEnd:
    SAVETAP "jogo.tap", BASIC, "loader", BasicStart, BasicEnd-BasicStart, 10

    ORG 32768
    
    ; O seu código em código máquina Z80 começa aqui...
```

## Anatomia dos Tokens e Hexadecimais no Carregador

O Sinclair BASIC guarda os programas na memória de forma "tokenizada". Isto significa que as palavras-chave (como `CLEAR`, `LOAD`, `CODE`) não são guardadas letra a letra como texto, mas sim convertidas para bytes individuais chamados **tokens** (caracteres com valores ASCII superiores a 127).

Aqui está o que cada byte hexadecimal representa na estrutura do carregador:

### 1. Metadados das Linhas
* **`db 0, 10`**: O Sinclair BASIC guarda o número da linha como um inteiro de 16 bits em formato big-endian. Portanto, a linha `10` é representada pelo byte alto `0` e o byte baixo `10`.
* **`dw LineEnd - LineStart`**: Define o comprimento em bytes da linha de comandos correspondente, permitindo à ROM do Spectrum saltar de linha em linha na memória.
* **`$0d` (13 em decimal)**: Representa o byte de retorno de carro (*carriage return* / newline), marcando o fim de uma linha BASIC.

### 2. A Linha 10 (`CLEAR VAL "32767"`)
`db $fd, $b0, $22, "32767", $22, $0d`
* **`$fd` (253 em decimal)**: É o token interno para a palavra-chave **`CLEAR`**.
* **`$b0` (176 em decimal)**: É o token para a função **`VAL`**.
* **`$22` (34 em decimal)**: É o código ASCII correspondente ao caracter de aspas (**`"`**).
* **`"32767"`**: A representação em texto do endereço de memória de limite (RAMTOP).
* **`$22` (34 em decimal)**: O caracter de fecho de aspas (**`"`**).

> [!TIP]
> **O truque do `VAL ""`:** No Sinclair BASIC, a gravação interna de números é complexa. Cada número guardado é seguido por um marcador e mais 5 bytes que contêm a representação em vírgula flutuante desse número. 
> Para evitar ter de calcular estes 5 bytes no assembler, usamos o truque `VAL "numero"`. A ROM do Spectrum interpreta `"32767"` como texto e calcula o número em runtime de forma automática!

### 3. A Linha 20 (`LOAD "" CODE`)
`db $ef, $22, $22, $af, $0d`
* **`$ef` (239 em decimal)**: É o token para a palavra-chave **`LOAD`**.
* **`$22`, `$22`**: Duas aspas seguidas (**`""`**), indicando para carregar o primeiro ficheiro sem importar o nome.
* **`$af` (175 em decimal)**: É o token para o parâmetro **`CODE`**, que avisa a ROM que deve carregar dados binários directamente para a memória RAM.

### 4. A Linha 30 (`RANDOMIZE USR VAL "32768"`)
`db $f9, $c0, $b0, $22, "32768", $22, $0d`
* **`$f9` (249 em decimal)**: É o token para **`RANDOMIZE`**.
* **`$c0` (192 em decimal)**: É o token para **`USR`**.
* **`$b0` (176 em decimal)**: O token para **`VAL`**.
* **`$22`, `"32768"`, `$22`**: A string correspondente ao endereço de execução da sua rotina (`start:`) envolta em aspas.

## Diretivas do sjasmplus explicadas

No final das nossas declarações de dados BASIC, usamos as seguintes directivas de exportação:

1. **`EMPTYTAP "jogo.tap"`**: Inicializa um novo ficheiro `.tap` limpo no disco.
2. **`SAVETAP "jogo.tap", BASIC, "loader", BasicStart, BasicEnd-BasicStart, 10`**:
   * Grava no ficheiro `.tap` o bloco que acabámos de descrever.
   * `BASIC`: Especifica o tipo de bloco na fita como um programa BASIC.
   * `"loader"`: O nome de cabeçalho que aparece no ecrã ao carregar (máximo de 10 caracteres).
   * `BasicStart`: O endereço inicial do bloco.
   * `BasicEnd-BasicStart`: O tamanho total do programa em bytes.
   * `10`: O número da linha a partir da qual o programa deve iniciar automaticamente (`LINE 10`).
