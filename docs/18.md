# Capítulo Dezoito - Fazer os Jogos Carregar e Correr Automaticamente

Embora isto seja bastante simples de alcançar para um programador experiente de Sinclair BASIC, é uma área frequentemente negligenciada. Em particular, os programadores que migram para o Spectrum vindos de outras máquinas não estarão familiarizados com a forma como isto é feito.

Para correr uma rotina em código máquina, temos de a iniciar a partir do BASIC. Isto significa escrever um pequeno programa carregador (*loader*) em BASIC, que liberta o espaço para o código máquina, carrega esse código e depois o executa. O tipo mais simples de carregador seria nestas linhas:

`10 CLEAR 24575: LOAD ""CODE: RANDOMIZE USR 24576`

O primeiro comando, `CLEAR`, define o topo da RAM (`RAMTOP`) abaixo da área ocupada pelo código máquina, para que o BASIC não o sobrescreva. Também limpa o ecrã e move a pilha para fora do caminho. O número que se segue deve ser, normalmente, um byte abaixo do primeiro byte do seu jogo. `LOAD ""CODE` carrega o ficheiro de código seguinte presente na fita, e `RANDOMIZE USR` efetivamente chama a rotina de código máquina no endereço especificado, neste caso 24576. Este deve ser o ponto de entrada para o seu jogo.

No Spectrum, a ROM reside nos primeiros 16K, sendo seguida por várias outras coisas, tais como a RAM do ecrã, variáveis de sistema e BASIC. Um local seguro para o seu código é acima desta área, até ao topo da RAM no endereço 65535. Com apenas um curto carregador em BASIC, um endereço de início de 24576, ou mesmo 24000, dar-lhe-á muito espaço para o seu jogo.

Este programa carregador é depois gravado na fita utilizando um comando como este:

`SAVE "nome" LINE 10`

`LINE 10` indica que, ao carregar, o programa BASIC deve ser executado automaticamente a partir da linha 10.

A seguir ao carregador em BASIC vem o ficheiro de código. Pode gravar um ficheiro de código desta forma:

`SAVE "nome" CODE 24576,40960`

`CODE` diz ao Spectrum para gravar um ficheiro de código, por oposição ao BASIC. O primeiro número depois deste é o endereço de início do bloco de código, e o último número é o seu comprimento.

Isto é bastante simples, mas e se quisermos adicionar um ecrã de carregamento (*loading screen*)? Bem, isso é suficientemente fácil. Podemos carregar um ecrã usando:

`LOAD ""SCREEN$`

O que isto fará é carregar um bloco de código de até 6912 bytes de comprimento para o início da visualização do ecrã no endereço 16384. Colocar o ficheiro do ecrã lá é um pouco mais complicado, porque não podemos simplesmente gravar o ecrã diretamente como um ficheiro, visto que as duas linhas inferiores seriam sobrescritas com a mensagem de sistema "Start tape, then press any key". Portanto, carregamos a nossa imagem num ponto da RAM – digamos, 32768 – e depois usamos:

`SAVE "nome" CODE 32768,6912`

6912 é o tamanho da RAM de visualização do Spectrum. Quando recarregamos o bloco a partir da fita usando `LOAD ""SCREEN$`, estamos a especificar que queremos forçar o ficheiro de código a ser carregado na memória do ecrã. Sob estas circunstâncias, não importa onde o ficheiro de código estava localizado quando foi gravado.

Agora temos outro problema: a mensagem "Bytes: nome" que é impressa ao carregar o bloco de código não iria sobrescrever parte do ecrã? Sim, iria. Podemos superar isto fazendo um `poke` no fluxo de saída:

`POKE 23739,111`

Isto resolverá o problema para nós. Assim, o nosso carregador BASIC passa a ser:

`10 CLEAR 24575: LOAD ""SCREEN$: POKE 23739,111: LOAD ""CODE: RANDOMIZE USR 24576`

## O Mesmo com o sjasmplus

Hoje não precisamos de escrever o carregador no Spectrum nem de gravar os blocos um a um: o sjasmplus constrói a cassete inteira. Todos os exemplos deste livro já usam um carregador mínimo (ver [Preparar o Ambiente](ferramentas.md)). Este exemplo acrescenta um ecrã de carregamento, seguindo exatamente os passos descritos acima. O carregador BASIC é:

```basic
10 CLEAR VAL "32767": LOAD ""SCREEN$: POKE VAL "23739",VAL "111": LOAD ""CODE: RANDOMIZE USR VAL "32768"
```

Para o exemplo não depender de um ficheiro de imagem, o próprio sjasmplus gera o ecrã com `DUP`: riscas nos píxeis e faixas de cor nos atributos. Num jogo a sério, trocaria essas linhas por `incbin "ecra.scr"`, um ficheiro de 6912 bytes criado num editor gráfico. Quando o programa arranca, espera por uma tecla, limpa o ecrã e escreve uma mensagem.

```assembly
        DEVICE ZXSPECTRUM48
        ORG 32768
start:
        ld a,244            ; desfazer o POKE 23739,111 do carregador,
        ld (23739),a        ; senão nada do que imprimirmos aparece.
        ld hl,23560         ; LAST K.
        ld (hl),0
tecla:  ld a,(hl)
        and a
        jr z,tecla          ; esperar por uma tecla.
        call 3503           ; limpar o ecrã.
        ld de,msg
        ld bc,msgfim-msg
        call 8252           ; escrever a mensagem.
        ret
msg:    defb 'O jogo comecaria aqui.'
msgfim:
fim:

; --- Ecrã de carregamento: 6144 bytes de píxeis + 768 de atributos ---
        ORG 49152
ecra:
n = 0
        DUP 6144                ; em cada carácter: 4 linhas de tinta, 4 de papel.
        defb ((n >> 10) & 1) * 255
n = n + 1
        EDUP
n = 0
        DUP 768                 ; uma faixa de cor por cada linha de caracteres.
        defb 64 + (((n / 32) & 7) << 3) + (((n / 32) + 3) & 7)
n = n + 1
        EDUP

; --- Carregador BASIC com ecrã de carregamento ---
        ORG 23755
basic:  db 0,10
        dw basic_fim-basic-4
        db $FD,$B0,'"32767":'           ; CLEAR VAL "32767":
        db $EF,'""',$AA,':'             ; LOAD ""SCREEN$:
        db $F4,$B0,'"23739",',$B0,'"111":' ; POKE VAL "23739",VAL "111":
        db $EF,'""',$AF,':'             ; LOAD ""CODE:
        db $F9,$C0,$B0,'"32768"',13     ; RANDOMIZE USR VAL "32768"
basic_fim:
        EMPTYTAP "cap18.tap"
        SAVETAP  "cap18.tap",BASIC,"cap18",basic,basic_fim-basic,10
        SAVETAP  "cap18.tap",CODE,"ecra",ecra,6912
        SAVETAP  "cap18.tap",CODE,"codigo",start,fim-start
```

Os tokens novos em relação ao carregador habitual são `$AA` (`SCREEN$`) e `$F4` (`POKE`). O ecrã é gravado a partir do endereço 49152, onde o sjasmplus o montou, mas isso não importa: como explicado acima, `LOAD ""SCREEN$` coloca-o sempre em 16384.

O `POKE 23739,111` muda o byte baixo do endereço da rotina de saída do canal "S" (o ecrã), guardado em 23739 e 23740, de 244 para 111. O endereço passa de 2548 (`$09F4`, a rotina de impressão) para 2415 (`$096F`), onde a ROM tem apenas uma instrução `ret`. Tudo o que for impresso nesse canal é ignorado, e por isso a mensagem `Bytes: codigo` não estraga a imagem. O efeito secundário é que, enquanto não for desfeito, nada do que o programa imprimir com `rst 16` aparece. É por isso que o programa começa por repor o valor original, 244.
