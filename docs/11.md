# Capítulo Onze - Movimento dos Inimigos

Já temos o nosso campo de jogo e conseguimos permitir que o jogador manipule um *sprite* à sua volta, mas o que precisamos agora são de alguns *sprites* inimigos para o jogador evitar. Um programador novato poderia ter dificuldades aqui, mas na realidade é muito mais simples do que parece à primeira vista.

## Inimigos em Patrulha

O tipo de inimigo mais fácil de programar é aquele que segue um algoritmo fixo ou uma rota de patrulha predeterminada. Já cobrimos uma técnica desse tipo no jogo Centipede anteriormente. Outro exemplo muito simples é o encontrado em jogos como *Jet Set Willy*, onde um *sprite* viaja numa única direção até chegar ao fim da sua patrulha, mudando depois de direção e voltando ao seu ponto de partida, antes de mudar de direção novamente e reiniciar o ciclo. Como deve imaginar, estas rotinas são incrivelmente fáceis de escrever.

Primeiro, configuramos a nossa tabela de estrutura de alienígenas com as posições de coordenadas mínimas e máximas e a direção atual. Geralmente é uma boa ideia comentar estas tabelas, pelo que faremos isso também.

```assembly
    EMPTYTAP "11_prog1.tap"

    ; --- BASIC loader ---
    ORG $5D00
BasicStart:
    db 0,10
    dw Line1End-Line1Start
Line1Start:
    db $fd, $b0, $22, "32767", $22, $0d
Line1End:
    db 0,20
    dw Line2End-Line2Start
Line2Start:
    db $ef, $22, $22, $af, $0d
Line2End:
    db 0,30
    dw Line3End-Line3Start
Line3Start:
    db $f9, $c0, $b0, $22, "32768", $22, $0d
Line3End:
BasicEnd:
    SAVETAP "11_prog1.tap", BASIC, "loader", BasicStart, BasicEnd-BasicStart, 10

    ORG 32768

    DEVICE ZXSPECTRUM48
    ORG $8000

start:
    ; Tabela de dados de alienígenas, 6 bytes por alienígena.
    ; ix     = tipo de gráfico, ex: galinha/Amoebatron etc.
    ; ix + 1 = direção: 0=cima, 1=direita, 2=baixo, 3=esquerda.
    ; ix + 2 = coordenada x atual.
    ; ix + 3 = coordenada y atual.
    ; ix + 4 = coord x ou y mínima, depende da direção.
    ; ix + 5 = coord x ou y máxima, depende da direção.
altab:
    defb 0,0,0,0,0,0
    defb 0,0,0,0,0,0
    defb 0,0,0,0,0,0


    SAVESNA "11_prog1.sna", start
    SAVETAP "11_prog1.tap", CODE, "11_prog1", start, $ - start, start
```

depois, para manipular o nosso *sprite*, poderíamos escrever algo como isto:

```assembly
    EMPTYTAP "11_prog2.tap"

    ; --- BASIC loader ---
    ORG $5D00
BasicStart:
    db 0,10
    dw Line1End-Line1Start
Line1Start:
    db $fd, $b0, $22, "32767", $22, $0d
Line1End:
    db 0,20
    dw Line2End-Line2Start
Line2Start:
    db $ef, $22, $22, $af, $0d
Line2End:
    db 0,30
    dw Line3End-Line3Start
Line3Start:
    db $f9, $c0, $b0, $22, "32768", $22, $0d
Line3End:
BasicEnd:
    SAVETAP "11_prog2.tap", BASIC, "loader", BasicStart, BasicEnd-BasicStart, 10

    ORG 32768

    DEVICE ZXSPECTRUM48
    ORG $8000

start:
    ld a,(ix+1)         ; direção de movimento do alienígena.
    rra                 ; rodar bit baixo para o carry.
    jr nc,movav         ; sem carry = 0 ou 2, deve ser vertical.

    ; a direção é 1 ou 3, logo é horizontal.
    rra                 ; rodar o bit seguinte para o carry para teste.
    jr nc,movar         ; direção 1 = mover alienígena para a direita.

    ; Mover alienígena para a esquerda.
moval:
    ld a,(ix+3)         ; obter coordenada y.
    sub 2               ; mover para a esquerda.
    ld (ix+3),a
    cp (ix+4)           ; já atingiu o mínimo?
    jr z,movax          ; sim - mudar de direção.
    jr c,movax          ; ultrapassou o mínimo.
    ret

    ; Mover alienígena para a direita.
movar:
    ld a,(ix+3)         ; obter coordenada y.
    add a,2             ; mover para a direita.
    ld (ix+3),a
    cp (ix+5)           ; já atingiu o máximo?
    jr nc,movax         ; sim - mudar de direção.
    ret

    ; Mover alienígena verticalmente.
movav:
    rra                 ; testar direção.
    jr c,movad          ; direção 2 é para baixo.

    ; Mover alienígena para cima.
movau:
    ld a,(ix+2)         ; obter coordenada x.
    sub 2               ; mover para cima.
    ld (ix+2),a
    cp (ix+4)           ; já atingiu o mínimo?
    jr z,movax          ; sim - mudar de direção.
    ret

    ; Mover alienígena para baixo.
movad:
    ld a,(ix+2)         ; obter coordenada x.
    add a,2             ; mover para baixo.
    ld (ix+2),a
    cp (ix+5)           ; já atingiu o máximo?
    jr nc,movax         ; sim - mudar de direção.
    ret

    ; Alterar direção do alienígena.
movax:
    ld a,(ix+1)         ; flag de direção.
    xor 2               ; inverter direção, quer
                    ; horizontalmente quer verticalmente.
    ld (ix+1),a         ; definir nova direção.
    ret


    SAVESNA "11_prog2.sna", start
    SAVETAP "11_prog2.tap", CODE, "11_prog2", start, $ - start, start
```

Se quiséssemos ir mais longe, poderíamos introduzir uma flag extra na nossa tabela, `ix+6`, para controlar a velocidade do *sprite*, e apenas o mover, digamos, a cada dois fotogramas (*frames*) se a flag estiver ativa. Embora seja simples de escrever e poupe memória, este tipo de movimento é bastante básico e previsível, tendo utilidade limitada. Para inimigos em patrulha mais complexos, por exemplo, as vagas de ataque de alienígenas num jogo de tiros (*shoot-'em-up*), precisamos de tabelas de coordenadas. Embora o código seja novamente simples de escrever, as tabelas de coordenadas consomem memória rapidamente, especialmente se forem guardadas as coordenadas x e y. Para aceder a essa tabela, precisamos de dois bytes por *sprite* que atuam como um ponteiro para a tabela de coordenadas.

Uma secção de código típica poderia ser assim:

```assembly
    EMPTYTAP "11_prog3.tap"

    ; --- BASIC loader ---
    ORG $5D00
BasicStart:
    db 0,10
    dw Line1End-Line1Start
Line1Start:
    db $fd, $b0, $22, "32767", $22, $0d
Line1End:
    db 0,20
    dw Line2End-Line2Start
Line2Start:
    db $ef, $22, $22, $af, $0d
Line2End:
    db 0,30
    dw Line3End-Line3Start
Line3Start:
    db $f9, $c0, $b0, $22, "32768", $22, $0d
Line3End:
BasicEnd:
    SAVETAP "11_prog3.tap", BASIC, "loader", BasicStart, BasicEnd-BasicStart, 10

    ORG 32768

    DEVICE ZXSPECTRUM48
    ORG $8000

start:
    ld l,(ix+2)         ; byte baixo do ponteiro, little endian.
    ld h,(ix+3)         ; byte alto do ponteiro.
    ld c,(hl)           ; colocar coordenada x em c.
    inc hl              ; apontar para coordenada y.
    ld b,(hl)           ; colocar coordenada y em b.
    inc hl              ; apontar para a próxima posição.
    ld (ix+2),l         ; byte baixo do próximo ponteiro.
    ld (ix+3),h         ; byte alto do próximo ponteiro.


    SAVESNA "11_prog3.sna", start
    SAVETAP "11_prog3.tap", CODE, "11_prog3", start, $ - start, start
```

O exemplo ligeiramente mais complicado abaixo demonstra uma vaga de ataque de 8 naves utilizando uma tabela de coordenadas verticais. A posição horizontal de cada *sprite* move-se para a esquerda a um ritmo constante de 2 píxeis por fotograma, pelo que não há necessidade de a guardar. Este código utiliza a rotina de *sprites* com deslocamento do Capítulo 8, pelo que os *sprites* piscam um pouco, mas isso não é importante aqui.

```assembly
    EMPTYTAP "11_prog4.tap"

    ; --- BASIC loader ---
    ORG $5D00
BasicStart:
    db 0,10
    dw Line1End-Line1Start
Line1Start:
    db $fd, $b0, $22, "32767", $22, $0d
Line1End:
    db 0,20
    dw Line2End-Line2Start
Line2Start:
    db $ef, $22, $22, $af, $0d
Line2End:
    db 0,30
    dw Line3End-Line3Start
Line3Start:
    db $f9, $c0, $b0, $22, "32768", $22, $0d
Line3End:
BasicEnd:
    SAVETAP "11_prog4.tap", BASIC, "loader", BasicStart, BasicEnd-BasicStart, 10

    ORG 32768

    DEVICE ZXSPECTRUM48
    ORG $8000

start:
mloop:
    halt                ; esperar pelo feixe da TV.
    ld ix,entab         ; apontar para naves ímpares.
    call mship          ; mover naves.
    halt
    ld ix,entab+4       ; apontar para naves pares.
    call mship          ; mover naves pares.
    call gwave          ; gerar novas vagas.
    jp mloop            ; voltar ao início do ciclo.

    ; Mover naves espaciais inimigas.
mship:
    ld b,4              ; número a processar.
mship0:
    push bc             ; guardar contador.
    ld a,(ix)           ; obter ponteiro baixo.
    ld l,a              ; colocar em l.
    ld h,(ix+1)         ; obter byte alto.
    or h                ; verificar se ponteiro está configurado.
    and a
    call nz,mship1      ; está? sim, processar.
    ld de,8             ; saltar para a entrada seguinte.
    add ix,de           ; apontar para o próximo inimigo.
    pop bc              ; restaurar contador.
    djnz mship0         ; repetir para todos os inimigos.
    ret

mship1:
    push hl             ; guardar ponteiro para coordenada.
    call dship          ; apagar esta nave.
    pop hl              ; restaurar coordenada.
    ld a,(hl)           ; obter próxima coordenada.
    inc hl              ; avançar ponteiro.
    ld (ix),l           ; byte baixo do novo ponteiro.
    ld (ix+1),h         ; byte alto do ponteiro.
    ld (ix+2),a         ; definir coordenada x.
    ld a,(ix+3)         ; obter posição horizontal.
    sub 2               ; mover para a esquerda 2 píxeis.
    ld (ix+3),a         ; definir nova posição.
    cp 240              ; já atingiu o limite do ecrã?
    jp c,dship          ; ainda não, mostrar na nova posição.
    xor a               ; zerar acumulador.
    ld (ix),a           ; limpar byte baixo do ponteiro.
    ld (ix+1),a         ; limpar byte alto do ponteiro.
    ld hl,numenm        ; número de inimigos no ecrã.
    dec (hl)            ; um a menos para processar.
    ret

gwave:
    ld hl,shipc         ; contador de naves.
    dec (hl)            ; menos uma.
    ld a,(hl)           ; verificar novo valor.
    cp 128              ; à espera do próximo ataque?
    jr z,gwave2         ; ataque iminente, configurar.
    ret nc              ; sim.
    and 7               ; altura de gerar uma nova nave?
    ret nz              ; ainda não.
    ld ix,entab         ; tabela de inimigos.
    ld de,4             ; tamanho de cada entrada.
    ld b,8              ; número a verificar.
gwave0:
    ld a,(ix)           ; byte baixo do ponteiro.
    ld h,(ix+1)         ; byte alto.
    or h
    jr z,gwave1         ; sim, esta entrada está vazia.
    add ix,de           ; apontar para o próximo espaço de nave.
    djnz gwave0         ; repetir até encontrar um.
    ret

gwave2:
    ld hl,wavnum        ; número da vaga atual.
    ld a,(hl)           ; obter configuração atual.
    inc a               ; seguinte.
    and 3               ; reiniciar após a 4ª vaga.
    ld (hl),a           ; gravar nova configuração.
    ret

gwave1:
    ld hl,numenm        ; número de inimigos no ecrã.
    inc (hl)            ; mais um a processar.
    ld a,(wavnum)       ; número da vaga.
    ld hl,wavlst        ; ponteiros dos dados da vaga.
    rlca
    rlca                ; multiplicar por 2.
                    ; multiplicar por 4.
    ld e,a              ; deslocamento em e.
    ld d,0              ; sem byte alto.
    add hl,de           ; encontrar endereço da vaga.
    ld a,(shipc)        ; contador de naves.
    and 8               ; ataque ímpar ou par?
    rrca
    rrca                ; ajustar múltiplo de 2 em conformidade.
    ld e,a              ; deslocamento em e.
    ld d,0              ; sem byte alto.
    add hl,de           ; apontar para a primeira ou segunda metade do ataque.
    ld e,(hl)           ; byte baixo do ponteiro do ataque.
    inc hl              ; segundo byte.
    ld d,(hl)           ; byte alto do ponteiro do ataque.
    ld (ix),e           ; byte baixo do ponteiro.
    ld (ix+1),d         ; byte alto.
    ld a,(de)           ; obter primeira coordenada.
    ld (ix+2),a         ; definir x.
    ld (ix+3),240       ; começar no limite direito do ecrã.

    ; Mostrar naves inimigas.
dship:
    ld hl,shipg         ; endereço do sprite.
    ld b,(ix+3)         ; coordenada y.
    ld c,(ix+2)         ; coordenada x.
    ld (xcoord),bc      ; configurar coordenadas da rotina de sprite.
    jp sprite           ; chamar rotina de sprite.

shipc: defb 128      ; contador.
numenm: defb 0       ; número de inimigos.

    ; Coordenadas das vagas de ataque.
    ; Apenas a coordenada vertical é guardada, pois as naves movem-se todas
    ; para a esquerda 2 píxeis a cada fotograma.
coord0:
    defb 40,40,40,40,40,40,40,40
    defb 40,40,40,40,40,40,40,40
    defb 42,44,46,48,50,52,54,56
    defb 58,60,62,64,66,68,70,72
    defb 72,72,72,72,72,72,72,72
    defb 72,72,72,72,72,72,72,72
    defb 70,68,66,64,62,60,58,56
    defb 54,52,50,48,46,44,42,40
    defb 40,40,40,40,40,40,40,40
    defb 40,40,40,40,40,40,40,40
    defb 38,36,34,32,30,28,26,24
    defb 22,20,18,16,14,12,10,8
    defb 6,4,2,0,2,4,6,8
    defb 10,12,14,16,18,20,22,24
    defb 26,28,30,32,34,36,38,40

coord1:
    defb 136,136,136,136,136,136,136,136
    defb 136,136,136,136,136,136,136,136
    defb 134,132,130,128,126,124,122,120
    defb 118,116,114,112,110,108,106,104
    defb 104,104,104,104,104,104,104,104
    defb 104,104,104,104,104,104,104,104
    defb 106,108,110,112,114,116,118,120
    defb 122,124,126,128,130,132,134,136
    defb 136,136,136,136,136,136,136,136
    defb 136,136,136,136,136,136,136,136
    defb 138,140,142,144,146,148,150,152
    defb 154,156,158,160,162,164,166,168
    defb 170,172,174,176,174,172,170,168
    defb 166,164,162,160,158,156,154,152
    defb 150,148,146,144,142,140,138,136

    ; Lista de vagas de ataque.
wavlst:
    defw coord0,coord0,coord1,coord1
    defw coord1,coord0,coord0,coord1
wavnum:
    defb 0                ; ponteiro da vaga atual.

    ; Sprite da nave espacial.
shipg:
    defb 248,252,48,24,24,48,12,96,24,48,31,243,127,247,255,247
    defb 255,247,127,247,31,243,24,48,12,96,24,48,48,24,248,252

    ; Rotina de sprite com deslocamento.
sprit7:
    xor 7               ; complementar os últimos 3 bits.
    inc a               ; adicionar um para dar sorte!
sprit3:
    rl d                ; rodar para a esquerda...
    rl c                ; ...para o byte do meio...
    rl e                ; ...e finalmente para a célula de caráter esquerda.
    dec a               ; contar deslocamentos efetuados.
    jr nz,sprit3        ; regressar até terminar todos os deslocamentos.

    ; A linha da imagem está em e + c + d, precisamos dela na forma c + d + e.
    ld a,e
    ld e,d
    ld d,c
    ld c,a
    jr sprit0

sprite:
    ld a,(xcoord)
    ld (tmp1),a
    call scadd
    ld a,16
sprit1:
    ex af,af'
    push de
    ld c,(hl)
    inc hl
    ld d,(hl)
    inc hl
    ld (tmp0),hl
    ld e,0
    ld a,b
    and 7
    jr z,sprit0
    cp 5
    jr nc,sprit7
    and a
sprit2:
    rr c
    rr d
    rr e
    dec a
    jr nz,sprit2

sprit0:
    pop hl
    ld a,(hl)
    xor c
    ld (hl),a
    inc l
    ld a,(hl)
    xor d
    ld (hl),a
    inc hl
    ld a,(hl)
    xor e
    ld (hl),a
    ld a,(tmp1)
    inc a
    ld (tmp1),a
    and 63
    jr z,sprit4
    and 7
    jr z,sprit5
    dec hl
    dec l
    inc h
sprit6:
    ex de,hl
    ld hl,(tmp0)
    ex af,af'
    dec a
    jp nz,sprit1
    ret

sprit4:
    ld de,30
    add hl,de
    jp sprit6

sprit5:
    ld de,63774
    add hl,de
    jp sprit6

scadd:
    ld a,(xcoord)
    ld e,a
    and 7
    add a,64
    ld d,a
    ld a,e
    and 192
    rrca
    rrca
    rrca
    add a,d
    ld d,a
    ld a,e
    rlca
    rlca
    and 224
    ld e,a
    ld a,(ycoord)
    rrca
    rrca
    rrca
    and 31
    add a,e
    ld e,a
    ret

xcoord: defb 0
ycoord: defb 0
tmp0: defw 0
tmp1: defb 0

    ; Tabela de naves inimigas, 8 entradas x 4 bytes cada.
entab:
    defb 0,0,0,0
    defb 0,0,0,0
    defb 0,0,0,0
    defb 0,0,0,0
    defb 0,0,0,0
    defb 0,0,0,0
    defb 0,0,0,0
    defb 0,0,0,0


    SAVESNA "11_prog4.sna", start
    SAVETAP "11_prog4.tap", CODE, "11_prog4", start, $ - start, start
```

## Alienígenas Inteligentes

Até agora temos lidado com drones previsíveis, mas e se quisermos dar ao jogador a ilusão de que os *sprites* inimigos pensam por si mesmos? Uma forma de começar a fazer isto seria dar-lhes um processo de tomada de decisão inteiramente aleatório.

Aqui está o código fonte de *Turbomania*, um jogo originalmente escrito para a competição de programação em 1K no ano de 2005. É muito simples, mas incorpora um movimento puramente aleatório. Os carros inimigos deslocam-se numa direção até já não conseguirem avançar, selecionando depois outra direção ao calhas. Adicionalmente, um carro pode mudar de direção aleatoriamente mesmo que consiga continuar na sua direção atual. É muito primitivo, claro, basta olhar para a rotina `mcar` e verá exatamente o que quero dizer.

```assembly
    EMPTYTAP "11_prog5.tap"

    ; --- BASIC loader ---
    ORG $5D00
BasicStart:
    db 0,10
    dw Line1End-Line1Start
Line1Start:
    db $fd, $b0, $22, "24575", $22, $0d
Line1End:
    db 0,20
    dw Line2End-Line2Start
Line2Start:
    db $ef, $22, $22, $af, $0d
Line2End:
    db 0,30
    dw Line3End-Line3Start
Line3Start:
    db $f9, $c0, $b0, $22, "24576", $22, $0d
Line3End:
BasicEnd:
    SAVETAP "11_prog5.tap", BASIC, "loader", BasicStart, BasicEnd-BasicStart, 10

    ORG 24576

    DEVICE ZXSPECTRUM48
    ORG 24576

start:

    ; Constantes.
YELLOW: equ 49       ; atributo amarelo normal.
YELLOB: equ YELLOW + 64 ; atributo amarelo brilhante.

    ; Código principal do jogo.
    ; Limpar o ecrã para dar verde nas margens.
waitk:
    ld hl,23693         ; variável de sistema para atributos.
    ld (hl),36          ; queremos fundo verde.
    ld a,(23560)        ; ler teclado.
    cp 32               ; SPACE pressionado?
    jr nz,waitk         ; não, esperar.
    call nexlev         ; jogar o jogo.
    jr waitk            ; SPACE para reiniciar o jogo.

    ; Limpar dados do nível.
nexlev:
    call 3503           ; limpar o ecrã.
    ld hl,rmdat         ; dados do ecrã/sala.
    ld de,rmdat+1
    ld (hl),1           ; configurar bloco de sombra.
    ld bc,16            ; comprimento do ecrã menos o primeiro byte.
    ldir                ; copiar para o resto da primeira linha.
    ld bc,160           ; comprimento do ecrã menos a primeira linha.
    ld (hl),b           ; limpar primeiro byte.
    ldir                ; limpar dados do ecrã.

    ; Configurar blocos padrão.
    ld c,15             ; última posição do bloco.
popbl0:
    ld b,9              ; última linha.
popbl1:
    call filblk         ; preencher bloco.
    dec b               ; uma coluna acima.
    jr z,popbl2
    dec b
    jr popbl1
popbl2:
    dec c
    jr z,popbl3
    dec c
    jr popbl0

    ; Agora desenhar os elementos únicos deste nível.
popbl3:
    ld b,7
popbl5:
    push bc
    call random
    and 6
    add a,2
    ld b,a
popbl4:
    call random
    and 14
    cp 1
    ; ...



; --- Mocks para compilação autónoma ---
filblk: ret
rmdat: defb 0
random: ret

    SAVESNA "11_prog5.sna", start
    SAVETAP "11_prog5.tap", CODE, "11_prog5", start, $ - start, start
```

    ; chkpx0 remove endereço de retorno da pilha.
chkpx0: pop de
    ret

    ; Preencher um bloco no mapa.
    ; Obter endereço do bloco.
filblk:
    ld a,b              ; número da linha.
    rlca
    rlca
    rlca
    rlca                ; multiplicar por 16.
    add a,c             ; adicionar ao total do deslocamento.
    ld e,a              ; deslocamento baixo.
    ld d,0              ; sem byte alto.
    ld hl,rmdat         ; endereço dos dados do nível.
    add hl,de           ; adicionar ao endereço do bloco.

    ; O endereço do bloco está em hl, vamos preenchê-lo.
    ld (hl),2           ; definir bloco ativo.
    ld de,16            ; distância para o bloco abaixo.
    add hl,de           ; apontar para lá.
    ld a,(hl)           ; verificar.
    and a               ; já está definido?
    ret nz              ; sim, não sobrescrever.
    ld (hl),1           ; definir a sombra.
    ret

    ; Desenhar um ecrã consistindo inteiramente em blocos de atributos.
atroom:
    ld hl,rmdat         ; dados do nível.
    ld a,1
    ld (dispx),a        ; começar na linha 1.
    ld b,11             ; contagem de linhas.
atrm0:
    push bc
    ld b,15             ; contagem de colunas.
    ld a,1
    ld (dispy),a        ; começar na esquerda do ecrã.
atrm1:
    push bc
    ld a,(hl)           ; obter próximo tipo de bloco.
    push hl             ; guardar endereço dos dados.
    rlca
    rlca                ; multiplicar número do bloco por 4.
    ld e,a              ; deslocamento do endereço do bloco.
    ld d,0              ; sem byte alto.
    ld hl,blkatt        ; atributos do bloco.
    add hl,de           ; apontar para o bloco pretendido.
    call atadd          ; obter endereço da posição no ecrã.
    ldi                 ; transferir primeiro bloco.
    ldi                 ; e o segundo.
    ld bc,30            ; distância para a linha seguinte.
    ex de,hl            ; trocar célula e endereço de ecrã.
    add hl,bc           ; apontar para a próxima linha abaixo.
    ex de,hl            ; trocar de volta.
    ldi                 ; desenhar terceira célula.
    ldi                 ; quarta célula de atributo.
    ld hl,dispy
    inc (hl)
    inc (hl)            ; avançar duas células na coluna.
    pop hl              ; restaurar endereço do nível.
    pop bc              ; restaurar contador de colunas.
    inc hl              ; apontar para próximo bloco.
    djnz atrm1          ; processar resto da linha.
    inc hl              ; saltar 1 char para manter alinhado.
    ld a,(dispx)
    add a,2             ; avançar 2 células na vertical.
    ld (dispx),a        ; nova linha.
    pop bc              ; restaurar contador.
    djnz atrm0          ; repetir para o resto das linhas.
    ret

    ; Atributos dos blocos de fundo.
blkatt:
    defb YELLOB,YELLOB  ; espaço.
    defb YELLOB,YELLOB  ; espaço de sombra.
    defb YELLOW,YELLOW  ; padrão quadriculado preto/branco.
    defb YELLOB,YELLOB

    defb 124,68
    defb 68,124

    ; Calcular endereço do atributo para o caráter em (dispx, dispy).
atadd:
    push hl             ; preservar hl.
    ld hl,(dispx)       ; coordenadas em caracteres.
    add hl,hl
    add hl,hl
    add hl,hl
    ld b,h              ; copiar coordenada y para b.
    ld c,l              ; colocar coordenada x em c.
    call ataddp         ; obter endereço físico dos atributos.
    ex de,hl            ; colocar endereço em de.
    pop hl              ; restaurar hl.
    ret

    ; Obter atributos do jogador.
gpatts:
    ld bc,(playx)       ; coordenadas do jogador.

    ; Calcular endereço do atributo para o píxel em (c, b).
ataddp:
    ld a,c
    rlca
    rlca
    ld l,a              ; dividir por 64.
    and 3               ; mascarar para encontrar segmento.
    add a,88            ; atributos começam em 88*256=22528.
    ld h,a              ; byte alto resolvido.
    ld a,l
    and 224             ; queremos múltiplo de 32.
    ld l,a
    ld a,b              ; obter posição horizontal.
    rra
    rra
    rra                 ; dividir por 8.
    and 31              ; no intervalo 0-31.
    add a,l
    ld l,a              ; byte baixo resolvido.
    ld a,(hl)           ; obter conteúdo da célula.
    ret

    ; Mover carro - mudança de direção necessária.
mcarcd:
    ld a,(hl)
    inc a
    and 3               ; rodar no sentido dos ponteiros do relógio (4 direções).
    ld (hl),a           ; nova direção.

    ; Mover um carro inimigo.
mcar:
    push hl             ; preservar ponteiro do carro.
    call getabc         ; obter coordenadas e direção.
    call movc           ; mover o carro.
    pop hl              ; restaurar ponteiro.
    jr nz,mcarcd        ; não se pode mover, mudar direção.
    inc hl
    ld a,c
    ld (hl),a           ; atualizar x em c.
    inc hl
    ld (hl),b           ; atualizar y.
    or b
    and 31
    cp 8                ; estamos num ponto de viragem válido?
    ret nz              ; não, não pode mudar de direção.
    ld a,r              ; número aleatório do registo R.
    cp 23
    ret nc              ; se for maior, não muda.
    push hl
    call random         ; obter número aleatório.
    pop hl
    dec hl
    dec hl
    and 3               ; direção no intervalo 0-3.
    ld (hl),a           ; nova direção.
    ret

    ; Obter coordenadas e direção do carro.
getabc:
    ld a,(hl)           ; direção.
    inc hl
    ld c,(hl)           ; posição x.
    inc hl
    ld b,(hl)           ; posição y.
    ret

    ; Processar carro apontado por hl.
procar:
    push hl
    push hl             ; guardar ponteiros.
    call scar           ; apagar carro.
    pop hl
    call mcar           ; mover carro.
    pop hl              ; restaurar ponteiro.

    ; Mostrar carro inimigo.
scar:
    call getabc
    jr dplay0           ; obter coordenadas e mostrar.

    ; Mostrar sprite do jogador.
dplayr:
    ld bc,(playx)       ; coordenadas do jogador.
    ld a,(playd)        ; direção do jogador.
dplay0:
    rrca
    rrca
    rrca                ; multiplicar por 32.
    ld e,a
    ld d,0
    ld hl,cargfx        ; gráficos dos carros.
    add hl,de           ; somar deslocamento ao sprite.
    jr sprite           ; chamar rotina de sprite.



; --- Mocks para compilação autónoma ---
movc: ret
playd: defb 0
YELLOB: equ 0
cargfx: defb 0
rmdat: defb 0
YELLOW: equ 0
playx: defb 0
dispx: defb 0
random: ret
sprite: ret
dispy: defb 0

    SAVESNA "11_prog6.sna", start
    SAVETAP "11_prog6.tap", CODE, "11_prog6", start, $ - start, start

## O Melhor Movimento dos Alienígenas

As melhores rotinas de movimento de alienígenas utilizam uma combinação de elementos aleatórios e algoritmos de perseguição (*hunter-killer*). Para superar o problema apresentado no código acima, precisamos de uma flag adicional para indicar o estado atual do inimigo (neste caso, a sua direção). Podemos mover o *sprite* numa determinada direção até que seja possível mudar de rumo vertical ou horizontalmente, momento em que uma nova direção é selecionada dependendo da posição do jogador. No entanto, caso não seja possível mover-se na direção pretendida, tomamos a direção oposta. Usando este método, um *sprite* pode encontrar o seu próprio caminho na maioria dos labirintos sem ficar preso com muita frequência.

De facto, para garantir absolutamente que o *sprite* não ficará preso, podemos adicionar um elemento aleatório para que, de tempos a tempos, a nova direção seja escolhida de forma aleatória e não com base na diferença das coordenadas x e y.

## Aumentar os Níveis de Dificuldade

A ponderação aplicada à decisão de mudança de direção determinará os níveis de inteligência do *sprite*. Se a nova direção tiver 90% de probabilidade de ser escolhida ao calhas e apenas 10% com base nas coordenadas, o alienígena vagará sem rumo durante algum tempo e só se aproximará do jogador lentamente. Dito isto, uma decisão aleatória pode por vezes ser a mais acertada ao perseguir o jogador. Um alienígena num ecrã mais difícil pode ter 60% de probabilidade de escolher uma nova direção aleatoriamente e 40% com base na posição relativa do jogador. Este alienígena perseguirá o jogador muito mais de perto. Ao ajustar estas percentagens, é possível determinar os níveis de dificuldade ao longo de um jogo e garantir uma transição suave desde os ecrãs iniciais mais simples até aos níveis finais diabolicamente difíceis.
