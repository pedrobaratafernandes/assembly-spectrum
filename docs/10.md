# Capítulo Dez - Pontuações e Pontuações Máximas

## Mais Rotinas de Pontuação

Até agora, temos utilizado uma rotina de pontuação pouco sofisticada. A nossa pontuação é mantida como um número de 16 bits guardado num par de registos e, para a mostrar, utilizámos a rotina de impressão/visualização de números de linha da ROM do Sinclair. Existem dois inconvenientes principais neste método: primeiro, estamos limitados a números de 0 a 9999; segundo, o aspeto visual é terrível.

Poderíamos converter nós próprios um número de 16 bits em ASCII da seguinte forma:

```assembly
    EMPTYTAP "10_prog1.tap"

    ; --- BASIC loader ---
    ORG $5D00
BasicStart:
    db 0,10
    dw Line1End-Line1Start
Line1Start:
    db $fd, $b0, $22, "32767", $22, $0d
Line1End:
    db 0,20
    dw Line2End-Line2Start
Line2Start:
    db $ef, $22, $22, $af, $0d
Line2End:
    db 0,30
    dw Line3End-Line3Start
Line3Start:
    db $f9, $c0, $b0, $22, "32768", $22, $0d
Line3End:
BasicEnd:
    SAVETAP "10_prog1.tap", BASIC, "loader", BasicStart, BasicEnd-BasicStart, 10

    ORG 32768

    DEVICE ZXSPECTRUM48
    ORG $8000

start:
    ; Mostrar o número passado em hl, alinhado à direita.
shwnum:
    ld a,48             ; zeros iniciais (ou 32 para espaços).
    ld de,10000
    call shwdg          ; mostrar dígito da casa das dezenas de milhar.
    ld de,1000
    call shwdg          ; mostrar dígito da casa dos milhares.
    ld de,100
    call shwdg          ; mostrar dígito da casa das centenas.
    ld de,10
    call shwdg          ; mostrar dígito da casa das dezenas.
    or 16               ; o último dígito é sempre mostrado.
    ld de,1
shwdg:
    and 48              ; limpar carry, limpar dígito.
shwdg1:
    sbc hl,de
    jr c,shwdg0         ; nada para mostrar.
    or 16               ; algo para mostrar, torná-lo um dígito.
    inc a               ; incrementar dígito.
    jr shwdg1           ; repetir até a coluna ser zero.
shwdg0:
    add hl,de           ; restaurar o total.
    push af
    rst 16              ; mostrar caráter.
    pop af
    ret


    SAVESNA "10_prog1.sna", start
    SAVETAP "10_prog1.tap", CODE, "10_prog1", start, $ - start, start
```

Este método funciona bem, embora continuemos limitados a uma pontuação de cinco dígitos não superior a 65535. Para uma apresentação mais profissional, completa com qualquer número de zeros iniciais, precisamos de manter a pontuação como uma string de dígitos ASCII.

Utilizo a mesma técnica de pontuação há cerca de 15 anos. Não é terrivelmente sofisticada, mas é boa o suficiente para o que precisamos. Este método utiliza um caráter ASCII por dígito, o que facilita a sua exibição. Por curiosidade, esta rotina foi retirada do jogo de tiros *More Tea, Vicar?*:

```assembly
    EMPTYTAP "10_prog2.tap"

    ; --- BASIC loader ---
    ORG $5D00
BasicStart:
    db 0,10
    dw Line1End-Line1Start
Line1Start:
    db $fd, $b0, $22, "32767", $22, $0d
Line1End:
    db 0,20
    dw Line2End-Line2Start
Line2Start:
    db $ef, $22, $22, $af, $0d
Line2End:
    db 0,30
    dw Line3End-Line3Start
Line3Start:
    db $f9, $c0, $b0, $22, "32768", $22, $0d
Line3End:
BasicEnd:
    SAVETAP "10_prog2.tap", BASIC, "loader", BasicStart, BasicEnd-BasicStart, 10

    ORG 32768

    DEVICE ZXSPECTRUM48
    ORG $8000

start:
score: defb '000000'

uscor:
    ld a,(hl)           ; valor atual do dígito.
    add a,b             ; adicionar pontos a este dígito.
    ld (hl),a           ; colocar o novo dígito de volta na string.
    cp 58               ; valor superior ao ASCII '9'?
    ret c               ; não - podemos descansar.
    sub 10              ; subtrair 10.
    ld (hl),a           ; colocar o novo caráter de volta na string.
uscor0:
    dec hl              ; caráter anterior na string.
    inc (hl)            ; incrementar este dígito em um.
    ld a,(hl)           ; qual é o novo valor?
    cp 58               ; ultrapassou o ASCII nove?
    ret c               ; não, pontuação processada.
    sub 10              ; subtrair dez.
    ld (hl),a           ; colocar de volta.
    jp uscor0           ; repetir o processo.


    SAVESNA "10_prog2.sna", start
    SAVETAP "10_prog2.tap", CODE, "10_prog2", start, $ - start, start
```

Para a utilizar, apontamos `HL` para o dígito que gostaríamos de incrementar, colocamos a quantidade a adicionar no registo `B` e chamamos `uscor`. Por exemplo, para adicionar 250 pontos à pontuação, são necessárias 6 linhas:

```assembly
    EMPTYTAP "10_prog3.tap"

    ; --- BASIC loader ---
    ORG $5D00
BasicStart:
    db 0,10
    dw Line1End-Line1Start
Line1Start:
    db $fd, $b0, $22, "32767", $22, $0d
Line1End:
    db 0,20
    dw Line2End-Line2Start
Line2Start:
    db $ef, $22, $22, $af, $0d
Line2End:
    db 0,30
    dw Line3End-Line3Start
Line3Start:
    db $f9, $c0, $b0, $22, "32768", $22, $0d
Line3End:
BasicEnd:
    SAVETAP "10_prog3.tap", BASIC, "loader", BasicStart, BasicEnd-BasicStart, 10

    ORG 32768

    DEVICE ZXSPECTRUM48
    ORG $8000

start:
    ; Adicionar 250 à pontuação.
    ld hl,score+3       ; apontar para a coluna das centenas.
    ld b,2              ; 2 centenas = 200.
    call uscor          ; incrementar a pontuação.
    ld hl,score+4       ; apontar para a coluna das dezenas.
    ld b,5              ; 5 dezenas = 50.
    call uscor          ; incrementar a pontuação.



; --- Mocks para compilação autónoma ---
score: defw 0
uscor: ret

    SAVESNA "10_prog3.sna", start
    SAVETAP "10_prog3.tap", CODE, "10_prog3", start, $ - start, start
```

Simples, mas faz o seu trabalho. Os mais puristas apontariam, sem dúvida, que isto poderia ser feito usando BCD (Binary Coded Decimal), e que todas as instruções para isso estão no conjunto de instruções do Z80.

## Tabelas de Pontuações Máximas

As rotinas de pontuações máximas (*high scores*) não são especialmente fáceis de escrever para um principiante, mas assim que escrever uma, poderá reutilizá-la vezes sem conta. O princípio básico é que começamos no fundo da tabela e subimos até encontrar uma pontuação que seja maior ou igual à pontuação do jogador. Em seguida, deslocamos todos os dados na tabela abaixo desse ponto uma posição para baixo e copiamos o nome e a pontuação do jogador para a tabela nessa posição.

Podemos definir o par de registos `HL` ou `IX` para o primeiro dígito da pontuação mais baixa na tabela e comparar cada dígito com o correspondente na pontuação do jogador. Se o dígito na pontuação do jogador for mais alto, subimos uma posição; se for mais baixo, paramos aí e copiamos a pontuação do jogador para a tabela uma posição abaixo. Se ambos os dígitos forem iguais, passamos para o dígito seguinte e repetimos a verificação até que os dígitos sejam diferentes ou tenhamos verificado todos os dígitos da pontuação. Se as pontuações forem idênticas, colocamos a entrada do jogador na tabela uma posição abaixo. Isto é repetido até que uma pontuação na tabela seja mais alta do que a pontuação do jogador, ou até chegarmos ao topo da tabela.

Ao inicializar uma tabela de pontuações máximas pela primeira vez, pode ser tentador colocar o seu próprio nome no topo com uma pontuação muito difícil de bater. Tente resistir a esta tentação. As tabelas de pontuações máximas servem para o jogador avaliar o seu próprio desempenho, e não faz sentido frustrar o jogador tornando a primeira posição quase impossível de alcançar.

## A Alquimia Decimal e os Mistérios do BCD

Ao adentrarmos no domínio das contagens, dos recordes batidos e das cimeiras atingidas pelo jogador transigimos inegavelmente num bailado de aritmética imposta na base da conversão decimal. A arquitetura elementar dita o encastramento natural dos valores absolutos cravando-os no seio da RAM num estrito binário puro (onde por via do exemplo uma mera amarra cravada sob a matriz `00010100` flete o absoluto decimal contíguo a vinte). Contudo perante o rigor do espelho ditado no ecrã e à mercê do olhar voraz do jogador este somatório binário resvala perante a inabilidade do Z80 em o extrair num despejo direto a texto sem o mergulhar nas dolorosas e tortuosas sucessões encastradas das divisões cegas encadeadas deitado em sucessivas divisões base à escala das dezenas e centenas perante uma engrenagem que penaliza brutalmente a velocidade do ciclo de processamento do chip perante divisões matemáticas de pura força e atrito.

O escape redentor imposto nesta vala apelida-se pelo formato batizado vulgo as iniciais contíguas do cimentado BCD (ou à letra o ditame anglo-saxónico fletido da sigla Binary Coded Decimal). Por esta engenhoca transigida divide-se artificialmente cada base unitária do byte originário cravado nas metades em fatias cravadas em base na casa limítrofe de estritos quatro bits independentes (vulgar e afamado nibble). Neste domínio confinado isolado do seu par adjacente o dito nibble escuda e alberga cego a finta do estrito número decimal contido deitado base entre matriz nula no zero saltando teto amarrado cego alojado contíguo ao limite ditado pelo nove. Munido desta batuta perante a valência da cifra alojando os pontos absolutos deitado pelo quarenta e cinco, estampa o mestre da engrenagem no tapete um estrito decalcado cravado balizado hexadecimal matriz em base `$45` fletindo sem rodeios binários na pureza ditada fletindo pelo decalcado visual cego em base `0100 0101` (na qual a finta dita decalcada no extremo altaneiro arrasta pura a base matriz quatro relegando originário contíguo perante amarra baixa o encarte fletido da valência estrita do cincos). Perante a mágica do espelho decalcado atirando e empurrando avante o rescaldo à face limiar deitando ao decifrar para texto o desígnio resvala pura varredura transigindo isolar via decalcado o mero nibble deitado e atirar com contíguo abono aditivo à raiz decalcando soma à base na casa quatro dezenas oito (o baluarte ditado da raiz matriz deitando o caracter zero da base matriz encartada cravado ASCII pura em '0').

Nesta engrenagem onde se fletem adições matriz atirando a este formato fletindo a impiedosa e letal engrenagem binária sob comando deitando a invocação à raiz originária assente batizada perante matriz em `add` o rescaldo flete perante calvário; balizando `$09` mais contíguo `$01` empurra desoladamente perante raiz decalcada cravando no espelho o letal engano cego decantado matriz sob engano afeto e atirado nulo dita `$0A` num revés cravado na base matemática da casa hexadecimal invés do exigido transigido décimo ditando limpo a cobiçada estrita `$10` impulsionada estrita via ditado em BCD! A redenção impulsionadora a este apuro decai fletida com encarte isolado cravado perante a batida da sublime instrução singular deitando amarra no encarte cravado da instrução invocada base batendo em avanço a letal engrenagem atirada batida em `daa`. O bailado deitando matriz dita do seu afamado ajustador decimal resgata originário estrito na face cravada deitada a poeira deixada nas bandeiras submetendo e transigindo base escrutínio perante o derradeiro arrasto no pilar do Acumulador deitado singular a `A`. Caso o rescaldo cravado na esteira espelhe finta liminar de extravasar a dita amarra na raiz das unidades deitada à base e limiar teto cravado nove num estrito nibble decantado deitando cega contígua as invocações empurradas na bandeira acendendo a fúria em Carry no limite de base fletida adiciona forçoso e automático seis empurrado à morada desse nibble fletindo estrito pulo balizado transigindo no poço impiedoso decalcando perante as letras puras das marcas esburacadas atiradas cravadas entre a amarra nula decalcando avante `A` saltando teto cravado ao impiedoso `F` trancando a balança na harmonia matriz ancorando a precisão no cais decimal ditado de salvação limpa perante as adições; poupando os calvários no Assembly do modesto Z80!
