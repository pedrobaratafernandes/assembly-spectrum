# Capítulo Um - Texto e Gráficos Simples

## Introdução ao sjasmplus

O **sjasmplus** é um compilador cruzado (*cross-assembler*) moderno para o processador Z80. Um compilador cruzado permite-lhe escrever o código Z80 num computador moderno (como um PC com Linux, macOS ou Windows) e compilá-lo para gerar ficheiros executáveis no formato do ZX Spectrum (como `.tap` ou `.sna`), que podem depois ser carregados diretamente em emuladores ou transferidos para hardware real.

### Porquê utilizar o sjasmplus?
*   **Velocidade e Praticidade**: Desenvolver diretamente no Spectrum (ou mesmo num emulador) com editores antigos é lento e limitado. Com o sjasmplus, pode utilizar editores de texto modernos (como o VS Code) e compilar instantaneamente a partir da linha de comandos.
*   **Emulação Direta**: Gera ficheiros de instantâneo (`.sna`) ou fita (`.tap`) de forma automatizada.
*   **Compatibilidade e Funcionalidades Modernas**: Suporta diretivas avançadas, macros, compilação condicional e estruturas de dados complexas, facilitando a gestão de projetos de grande escala.

### Como Instalar o sjasmplus e o emulador Fuse

#### O que é o emulador Fuse?

O **Fuse (Free Unix Spectrum Emulator)** é um dos emuladores mais populares e completos do ZX Spectrum para sistemas Unix/Linux. Suporta a emulação fiel de múltiplos modelos (16K, 48K, 128K, +2, +2A, +3, etc.) e permite executar diretamente os ficheiros de instantâneo (`.sna`) e cassete (`.tap`) gerados pelo sjasmplus.

#### Instalação no Arch Linux

No Arch Linux, tanto o **sjasmplus** (versão moderna mantida por z00m128) como o **Fuse** estão disponíveis no AUR (Arch User Repository) e podem ser facilmente instalados utilizando um assistente de AUR como o `yay` ou `paru`:

1.  **Instalar o sjasmplus**:
    ```bash
    yay -S sjasmplus-z00m128
    ```

2.  **Instalar o emulador Fuse**:
    ```bash
    yay -S fuse-emulator
    ```

*(Nota: Evite confundir o pacote `fuse-emulator` com o pacote `fuse2` ou `fuse3` do repositório oficial do Arch, que se refere à interface do sistema de ficheiros "Filesystem in Userspace" do Linux).*

#### Instalação no Debian/Ubuntu/etc.

Se estiver a utilizar um sistema baseado em Debian ou Ubuntu, pode instalar as ferramentas compilando o **sjasmplus** a partir do código fonte e instalando o **Fuse** via `apt`:

1.  **Instalar dependências de compilação e o emulador Fuse**:
    ```bash
    sudo apt-get update
    sudo apt-get install git build-essential cmake fuse-emulator-common fuse-emulator-utils
    ```

2.  **Obter o código fonte do sjasmplus e compilar**:
    ```bash
    git clone --recursive -j8 https://github.com/z00m128/sjasmplus.git
    cd sjasmplus
    make clean && make
    ```

3.  **Instalar o sjasmplus no sistema**:
    *   Para instalação global (requer privilégios de administrador):
        ```bash
        sudo make install
        ```
    *   Para instalação local (na sua pasta de utilizador):
        ```bash
        mkdir -p ~/.local/bin
        make PREFIX=~/.local install
        ```
        *(Nota: Certifique-se de que `~/.local/bin` está na sua variável de ambiente `PATH`).*

### Diretivas de Exportação: SAVESNA e SAVETAP

O sjasmplus suporta diretivas especiais que permitem instruir o assembler a criar automaticamente ficheiros prontos a correr no ZX Spectrum. Para as utilizar, deve definir o dispositivo virtual no início do código (por exemplo, `DEVICE ZXSPECTRUM48`).

#### 1. SAVESNA
Exporta o estado atual da memória do dispositivo virtual para um ficheiro de instantâneo (*snapshot*) `.sna`.
*   **Sintaxe**:
    ```assembly
; --- Mocks para compilação autónoma ---
start_address: equ $8000

        SAVESNA "nome_ficheiro.sna", start_address
```
*   **Como funciona**: Guarda uma imagem completa da RAM do Spectrum de 48K ou 128K. O parâmetro `start_address` define o endereço de execução onde o CPU virtual começará a executar o código imediatamente após o carregamento do instantâneo no emulador.

#### 2. SAVETAP
Cria um ficheiro de imagem de fita virtual `.tap` contendo blocos de dados ou código.
*   **Sintaxe**:
    ```assembly
; --- Mocks para compilação autónoma ---
start_address: equ $8000


; --- Mocks para compilação autónoma ---
length: equ 0


; --- Mocks para compilação autónoma ---
execution_address: equ $8000

        SAVETAP "nome_ficheiro.tap", CODE, "nome_bloco", start_address, length, execution_address
```
*   **Como funciona**:
    *   `"nome_ficheiro.tap"`: Nome do ficheiro `.tap` de saída.
    *   `CODE`: Especifica que o bloco a gravar é do tipo código binário.
    *   `"nome_bloco"`: O nome de cabeçalho do bloco na fita (máximo 10 caracteres).
    *   `start_address`: Endereço de memória de onde os dados começam a ser lidos para gravação.
    *   `length`: Comprimento em bytes do bloco a gravar (muitas vezes calculado como `$ - start_address` para guardar tudo desde o início até à posição atual).
    *   `execution_address`: Endereço para onde o Spectrum salta para iniciar a execução do código (usado pelo carregador).

## Olá Mundo

O primeiro programa em BASIC que a maioria dos programadores novatos escreve é geralmente nestes moldes:

```basic
10 PRINT "Hello world"
20 GOTO 10
```

Tudo bem, o texto pode diferir. O seu primeiro esforço pode ter dito "O Dave é o maior" ou "O Rob esteve aqui", mas sejamos realistas, apresentar texto e gráficos no ecrã é provavelmente o aspeto mais importante da escrita de qualquer videojogo e, com a exceção de máquinas de pinball ou de moedas, é praticamente impossível conceber um jogo sem um ecrã. Com isto em mente, comecemos este tutorial com algumas rotinas de visualização importantes na ROM do Spectrum.

Então, como faríamos para converter o programa em BASIC acima para código máquina? Bem, podemos usar o PRINT utilizando a instrução RST 16 — efetivamente o mesmo que PRINT CHR$ a —, mas isso apenas imprime o caráter guardado no acumulador para o canal atual. Para imprimir uma string no ecrã, precisamos de chamar duas rotinas: uma para abrir o ecrã superior para impressão (canal 2) e a segunda para imprimir a string. A rotina no endereço da ROM 5633 abrirá o número do canal que passamos no acumulador, e a 8252 imprimirá uma string a começar em de com comprimento bc para este canal. Assim que o canal 2 é aberto, todas as impressões são enviadas para o ecrã superior até chamarmos 5633 com outro valor para enviar o output para outro lado. Outros canais interessantes são o 1 para o ecrã inferior (como PRINT #1 em BASIC, e podemos usar isto para apresentar nas duas linhas de baixo) e o 3 para a impressora ZX.

```assembly
    DEVICE ZXSPECTRUM48
    ORG $8000

start:
    ld a,2             ; ecrã superior
    call 5633          ; abrir canal
loop:              
    ld de, string      ; endereço da string
    ld bc, eostr-string ; comprimento da string a imprimir
    call 8252          ; imprimir a nossa string
    jp loop            ; repetir até o ecrã estar cheio
string: defb '(o seu nome) é porreiro'
eostr: equ $       


    SAVESNA "1_prog1.sna", start
    SAVETAP "1_prog1.tap", CODE, "1_prog1", start, $ - start, start
```

Executar esta listagem enche o ecrã com o texto até que a mensagem "scroll?" seja apresentada no fundo. Irá notar, contudo, que em vez de cada linha de texto aparecer numa linha própria como na listagem BASIC, o início de cada string segue logo após o fim da anterior, o que não é exatamente o que queríamos. Para conseguir isto, precisamos de quebrar a linha nós próprios usando um código de controlo ASCII. Uma forma de fazer isto seria carregar o acumulador com o código para uma nova linha (13) e depois usar RST 16 para imprimir este código. Outra forma mais eficiente é adicionar este código ASCII ao final da nossa string desta forma:

```assembly
    DEVICE ZXSPECTRUM48
    ORG $8000

start:
string: defb '(o seu nome) é porreiro'
    defb 13
eostr: equ $


    SAVESNA "1_prog2.sna", start
    SAVETAP "1_prog2.tap", CODE, "1_prog2", start, $ - start, start
```

Existem vários códigos de controlo ASCII como este que alteram a posição de impressão atual, cores, etc., e a experimentação ajudará a decidir quais achará mais úteis. Aqui estão os principais que utilizo:

* **13 NEWLINE**: Define a posição de impressão para o início da próxima linha.
* **16,c INK**: Define a cor da tinta para o valor do byte seguinte.
* **17,c PAPER**: Define a cor do papel para o valor do byte seguinte.
* **22,x,y AT**: Define as coordenadas x e y de impressão para os valores especificados nos dois bytes seguintes.

O código 22 é particularmente útil para definir as coordenadas nas quais uma string ou caráter gráfico deve ser apresentado. Este exemplo apresentará um ponto de exclamação no canto inferior direito do ecrã:

```assembly
    DEVICE ZXSPECTRUM48
    ORG $8000

start:
    ld a,2             ; ecrã superior
    call 5633          ; abrir canal
    ld de, string      ; endereço da string
    ld bc,eostr-string ; comprimento da string a imprimir
    call 8252          ; imprimir a nossa string
    ret               
string: defb 22, 21, 31,'!'
eostr: equ $       


    SAVESNA "1_prog3.sna", start
    SAVETAP "1_prog3.tap", CODE, "1_prog3", start, $ - start, start
```

Este programa vai um passo mais além e anima um asterisco desde o fundo até ao topo do ecrã:

```assembly
    DEVICE ZXSPECTRUM48
    ORG $8000

start:
loop:
    ld a,2
    call 5633          ; 2 = ecrã superior. abrir canal.
    ld a,21            ; linha 21 = fundo do ecrã.
    ld (xcoord), a     ; definir coordenada x inicial.
    call setxy         ; configurar as nossas coordenadas x/y.
    ld a, '*'          ; queremos um asterisco aqui.
    rst 16             ; apresentá-lo.
    call delay         ; queremos um atraso.
    call setxy         ; configurar as nossas coordenadas x/y.
    ld a,32            ; código ASCII para espaço.
    rst 16             ; apagar o asterisco antigo.
    ld hl, xcoord      ; posição vertical.
    dec (hl)           ; movê-lo uma linha para cima.
    ld a, (hl)         ; onde está ele agora?
    cp 255             ; já passou o topo do ecrã?
    jr nz, loop        ; não, continuar.
    ret               
delay: ld b,10      ; duração do atraso.
delay0: halt        ; esperar por uma interrupção.
    djnz delay0        ; loop.
    ret                ; retornar.
setxy: ld a, 22     ; código de controlo ASCII para AT.
    rst 16             ; imprimi-lo.
    ld a, (xcoord)     ; posição vertical.
    rst 16             ; imprimi-lo.
    ld a, (ycoord)     ; coordenada y.
    rst 16             ; imprimi-lo.
    ret               
xcoord: defb 0     
ycoord: defb 15    


    SAVESNA "1_prog4.sna", start
    SAVETAP "1_prog4.tap", CODE, "1_prog4", start, $ - start, start
```

## Imprimir Gráficos Simples

Mover asteriscos pelo ecrã é muito bonito, mas mesmo para o jogo mais simples precisamos realmente de exibir gráficos. Gráficos avançados são discutidos em capítulos posteriores; por agora usaremos apenas gráficos simples do tipo Space Invader e, como qualquer programador de BASIC lhe dirá, o Spectrum tem um mecanismo muito simples para isto: o Gráfico Definido pelo Utilizador (User Defined Graphic), geralmente abreviado para UDG.

A tabela ASCII do Spectrum contém 21 (19 no modo 128k) carateres gráficos definidos pelo utilizador, começando no código 144 e indo até 164 (162 no modo 128k). Em BASIC, os UDGs são definidos introduzindo dados (poking) na área UDG no topo da RAM, mas em código máquina faz mais sentido alterar a variável de sistema que aponta para a localização de memória onde os UDGs estão armazenados, o que é feito alterando o valor de dois bytes no endereço 23675.

Podemos agora modificar o nosso programa do asterisco móvel para mostrar um gráfico em vez disso com algumas alterações:

```assembly
    DEVICE ZXSPECTRUM48
    ORG $8000

start:
    ld hl,udgs         ; UDGS.
    ld (23675),hl      ; configurar variável de sistema UDG.
    ld a,2             ; 2 = ecrã superior. abrir canal.
    call 5633         
loop:
    ld a,21            ; linha 21 = fundo do ecrã.
    ld (xcoord), a     ; definir coordenada x inicial.
    call setxy         ; configurar as nossas coordenadas x/y.
    ld a,144           ; mostrar UDG em vez do asterisco
    rst 16             ; apresentá-lo.
    call delay         ; queremos um atraso.
    call setxy         ; configurar as nossas coordenadas x/y.
    ld a,32            ; código ASCII para espaço.
    rst 16             ; apagar o asterisco antigo.
    call setxy         ; configurar as nossas coordenadas x/y.
    ld hl, xcoord      ; posição vertical.
    dec (hl)           ; movê-lo uma linha para cima.
    ld a, (xcoord)     ; onde está ele agora?
    cp 255             ; já passou o topo do ecrã?
    jr nz, loop        ; não, continuar.
    ret               
delay:
    ld b,10            ; duração do atraso.
delay0:
    halt               ; esperar por uma interrupção.
    djnz delay0        ; loop.
    ret                ; retornar.
setxy:
    ld a, 22           ; código de controlo ASCII para AT.
    rst 16             ; imprimi-lo.
    ld a, (xcoord)     ; posição vertical.
    rst 16             ; imprimi-lo.
    ld a, (ycoord)     ; coordenada y.
    rst 16             ; imprimi-lo.
    ret               
xcoord: defb 0     
ycoord: defb 15    
udgs: defb 60,126,219,153
    defb 255,255,219,219


    SAVESNA "1_prog5.sna", start
    SAVETAP "1_prog5.tap", CODE, "1_prog5", start, $ - start, start
```

É claro que não há razão para não poder usar mais do que os 21 UDGs se assim o desejar. Basta configurar vários bancos deles em memória e apontar para cada um à medida que precisa. Alternativamente, poderia redefinir o conjunto de carateres. Isto dá uma gama maior de carateres ASCII de 32 (ESPAÇO) a 127 (o símbolo de copyright). Poderia até misturar texto e gráficos, redefinindo as letras e números da sua fonte para o estilo da sua escolha, usando depois os símbolos e letras minúsculas para alienígenas, zombies ou o que o seu jogo necessitar.

Para apontar para outro conjunto, subtraímos 256 do endereço onde a fonte está colocada e colocamo-lo na variável de sistema de dois bytes no endereço 23606. A fonte Sinclair padrão, por exemplo, está localizada no endereço da ROM 15616, portanto a variável de sistema no endereço 23606 aponta para 15360 quando o Spectrum é ligado pela primeira vez.

Este código copia a fonte da ROM da Sinclair para a RAM, tornando-a "mais carregada" à medida que avança, e depois define a variável de sistema para apontar para ela:

```assembly
    DEVICE ZXSPECTRUM48
    ORG $8000

start:
    ld hl,15616        ; fonte da ROM.
    ld de, 60000       ; endereço da nossa fonte.
    ld bc,768          ; 96 carateres * 8 linhas a alterar.
font1: ld a, (hl)   ; obter mapa de bits.
    rlca               ; rodar para a esquerda.
    or (hl)            ; combinar as 2 imagens.
    ld (de), a         ; escrever na nova fonte.
    inc hl             ; próximo byte da antiga.
    inc de             ; próximo byte da nova.
    dec bc             ; decrementar contador.
    ld a,b             ; byte alto.
    or c               ; combinar com byte baixo.
    jr nz, font1       ; repetir até bc=zero.
    ld hl,60000-256    ; fonte menos 32*8.
    ld (23606), hl     ; apontar para a nova fonte.
    ret               


    SAVESNA "1_prog6.sna", start
    SAVETAP "1_prog6.tap", CODE, "1_prog6", start, $ - start, start
```

## Mostrar Números

Para a maioria dos jogos é melhor definir a pontuação do jogador como uma string de dígitos ASCII, embora isso signifique mais trabalho nas rotinas de pontuação e torne as tabelas de pontuações máximas um verdadeiro pesadelo para um programador de linguagem assembly inexperiente. Abordaremos isto num capítulo posterior, mas por agora usaremos algumas rotinas úteis da ROM para imprimir números por nós.

Há duas formas de imprimir um número no ecrã, a primeira das quais é usar a mesma rotina que a ROM utiliza para imprimir números de linha do Sinclair BASIC. Para isto, carregamos simplesmente o par de registos bc com o número que desejamos imprimir e depois chamamos 6683:

```assembly
    DEVICE ZXSPECTRUM48
    ORG $8000

start:
    ld bc, (score)
    call 6683



; --- Mocks para compilação autónoma ---
score: defw 0

    SAVESNA "1_prog7.sna", start
    SAVETAP "1_prog7.tap", CODE, "1_prog7", start, $ - start, start
```

No entanto, como os números de linha do BASIC apenas podem ir até 9999, isto tem a desvantagem de apenas ser capaz de mostrar um número de quatro dígitos. Assim que a pontuação do jogador atinge 10000, outros carateres ASCII são mostrados em vez de números.

Felizmente, existe outro método que vai muito mais alto. Em vez de chamar a rotina de exibição de número de linha, podemos chamar a rotina para colocar o conteúdo dos registos bc na pilha da calculadora (calculator stack), e depois outra rotina que exibe o número no topo desta pilha. Não se preocupe com o que é a pilha da calculadora e qual a sua função porque é de pouca utilidade para um programador de jogos de arcada, mas onde pudermos tirar partido dela, fa-lo-emos.

Basta lembrar que as seguintes três linhas apresentarão um número de 0 a 65535 inclusive:

```assembly
    DEVICE ZXSPECTRUM48
    ORG $8000

start:
    ld bc, (score) ; empilhar número em bc.
    call 11563    
    call 11747     ; exibir topo da pilha da calc.



; --- Mocks para compilação autónoma ---
score: defw 0

    SAVESNA "1_prog8.sna", start
    SAVETAP "1_prog8.tap", CODE, "1_prog8", start, $ - start, start
```

## Mudar as Cores

Para definir permanentemente os níveis de ink (tinta), paper (papel), brilho e flash, podemos escrever diretamente para a variável de sistema em 23693 e, em seguida, limpar o ecrã com uma chamada à ROM:

```assembly
    DEVICE ZXSPECTRUM48
    ORG $8000

start:
    ; queremos um ecrã amarelo.
    ld a,49          ; tinta azul (1) em papel amarelo (6*8).
    ld (23693), a    ; definir as cores do ecrã.
    call 3503        ; limpar o ecrã.


    SAVESNA "1_prog9.sna", start
    SAVETAP "1_prog9.tap", CODE, "1_prog9", start, $ - start, start
```

A forma mais rápida e simples de definir a cor da margem (border) é escrever na porta 254. Os 3 bits menos significativos do byte que enviamos determinam a cor, por isso, para definir a margem para vermelho:

```assembly
    DEVICE ZXSPECTRUM48
    ORG $8000

start:
    ld a,2           ; 2 é o código para vermelho.
    out (254), a     ; escrever na porta 254.


    SAVESNA "1_prog10.sna", start
    SAVETAP "1_prog10.tap", CODE, "1_prog10", start, $ - start, start
```

A porta 254 também controla o altifalante e a entrada Mic nos bits 3 e 4. No entanto, o efeito de margem só durará até à sua próxima chamada à rotina de som do beeper na ROM (mais sobre isso depois), pelo que é necessária uma solução mais permanente.

Para o fazer, precisamos simplesmente de carregar o acumulador com a cor requerida e chamar a rotina da ROM em 8859. Isto mudará a cor e definirá a variável de sistema BORDCR (localizada no endereço 23624) em conformidade.

Para definir uma margem vermelha permanente podemos fazer isto:

```assembly
    DEVICE ZXSPECTRUM48
    ORG $8000

start:
    ld a,2           ; 2 é o código para vermelho.
    call 8859        ; definir cor da margem.


    SAVESNA "1_prog11.sna", start
    SAVETAP "1_prog11.tap", CODE, "1_prog11", start, $ - start, start
```
