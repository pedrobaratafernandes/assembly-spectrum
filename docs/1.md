# Capítulo Um - Texto e Gráficos Simples

> Antes de começar, prepare o sjasmplus e o Fuse como explicado em [Preparar o Ambiente](ferramentas.md). Todos os programas completos deste capítulo compilam com `sjasmplus nome.asm` e geram um `.tap` pronto a abrir no Fuse.

## Olá Mundo

O primeiro programa em BASIC que a maioria dos programadores novatos escreve é geralmente nestes moldes:

```basic
10 PRINT "Hello world"
20 GOTO 10
```

Tudo bem, o texto pode diferir. O seu primeiro esforço pode ter dito "O Dave é o maior" ou "O Rob esteve aqui", mas sejamos realistas: apresentar texto e gráficos no ecrã é provavelmente o aspeto mais importante da escrita de qualquer videojogo e, com a exceção de máquinas de pinball ou de moedas, é praticamente impossível conceber um jogo sem um ecrã. Com isto em mente, comecemos este tutorial com algumas rotinas de visualização importantes na ROM do Spectrum.

Então, como faríamos para converter o programa em BASIC acima para código máquina? Bem, podemos fazer PRINT com a instrução `rst 16` — efetivamente o mesmo que `PRINT CHR$ a` —, mas isso apenas imprime o carácter guardado no acumulador para o canal atual. Para imprimir uma string no ecrã, precisamos de chamar duas rotinas: uma para abrir o ecrã superior para impressão (canal 2) e a segunda para imprimir a string. A rotina no endereço da ROM 5633 abre o canal cujo número passamos no acumulador, e a rotina em 8252 imprime nesse canal uma string que começa no endereço `de` e tem `bc` bytes de comprimento. Assim que o canal 2 é aberto, todas as impressões são enviadas para o ecrã superior até chamarmos 5633 com outro valor. Outros canais interessantes são o 1, para o ecrã inferior (como `PRINT #1` em BASIC; podemos usá-lo para escrever nas duas linhas de baixo), e o 3, para a impressora ZX.

```assembly
        DEVICE ZXSPECTRUM48
        ORG 32768
start:
        ld a,2              ; 2 = ecrã superior.
        call 5633           ; abrir canal.
loop:   ld de,string        ; endereço da string.
        ld bc,eostr-string  ; comprimento da string a imprimir.
        call 8252           ; imprimir a nossa string.
        jp loop             ; repetir até o ecrã estar cheio.

string: defb '(o seu nome) e fixe'
eostr:  equ $
fim:

; --- Carregador BASIC + ficheiro .tap (igual em todos os exemplos) ---
        ORG 23755
basic:  db 0,10                 ; 10 CLEAR 32767: LOAD "" CODE: RANDOMIZE USR 32768
        dw basic_fim-basic-4
        db $FD,$B0,'"32767":',$EF,'""',$AF,':',$F9,$C0,$B0,'"32768"',13
basic_fim:
        EMPTYTAP "cap01_1.tap"
        SAVETAP  "cap01_1.tap",BASIC,"cap01_1",basic,basic_fim-basic,10
        SAVETAP  "cap01_1.tap",CODE,"cap01_1",start,fim-start
```

Executar esta listagem enche o ecrã com o texto até que a mensagem `scroll?` apareça no fundo (responda com N, ou com a tecla BREAK, para voltar ao BASIC). Irá notar, contudo, que em vez de cada linha de texto aparecer numa linha própria como na listagem BASIC, o início de cada string segue logo após o fim da anterior, o que não é exatamente o que queríamos. Para o conseguir, precisamos de mudar de linha nós próprios, usando um código de controlo ASCII. Uma forma de o fazer seria carregar o acumulador com o código de mudança de linha (13) e depois usar `rst 16` para imprimir este código. Outra forma, mais eficiente, é acrescentar este código ao final da nossa string:

```assembly
        DEVICE ZXSPECTRUM48
        ORG 32768
start:
        ld a,2              ; 2 = ecrã superior.
        call 5633           ; abrir canal.
loop:   ld de,string        ; endereço da string.
        ld bc,eostr-string  ; comprimento da string a imprimir.
        call 8252           ; imprimir a nossa string.
        jp loop             ; repetir até o ecrã estar cheio.

string: defb '(o seu nome) e fixe'
        defb 13             ; código de mudança de linha.
eostr:  equ $
fim:

; --- Carregador BASIC + ficheiro .tap (igual em todos os exemplos) ---
        ORG 23755
basic:  db 0,10                 ; 10 CLEAR 32767: LOAD "" CODE: RANDOMIZE USR 32768
        dw basic_fim-basic-4
        db $FD,$B0,'"32767":',$EF,'""',$AF,':',$F9,$C0,$B0,'"32768"',13
basic_fim:
        EMPTYTAP "cap01_2.tap"
        SAVETAP  "cap01_2.tap",BASIC,"cap01_2",basic,basic_fim-basic,10
        SAVETAP  "cap01_2.tap",CODE,"cap01_2",start,fim-start
```

Existem vários códigos de controlo como este, que alteram a posição de impressão atual, as cores, etc., e a experimentação ajudará a decidir quais lhe são mais úteis. Aqui estão os principais que utilizo:

| Código | Nome | Efeito |
| :--- | :--- | :--- |
| `13` | NEWLINE | Passa a posição de impressão para o início da linha seguinte. |
| `16,c` | INK | Define a cor da tinta com o valor do byte seguinte. |
| `17,c` | PAPER | Define a cor do papel com o valor do byte seguinte. |
| `22,x,y` | AT | Define as coordenadas de impressão com os valores dos dois bytes seguintes (linha, coluna). |

O código 22 é particularmente útil para definir as coordenadas nas quais uma string ou um carácter gráfico deve ser apresentado. Este exemplo apresenta um ponto de exclamação no canto inferior direito do ecrã:

```assembly
        DEVICE ZXSPECTRUM48
        ORG 32768
start:
        ld a,2              ; ecrã superior.
        call 5633           ; abrir canal.
        ld de,string        ; endereço da string.
        ld bc,eostr-string  ; comprimento da string a imprimir.
        call 8252           ; imprimir a nossa string.
        ret

string: defb 22,21,31,'!'   ; AT 21,31; "!"
eostr:  equ $
fim:

; --- Carregador BASIC + ficheiro .tap (igual em todos os exemplos) ---
        ORG 23755
basic:  db 0,10                 ; 10 CLEAR 32767: LOAD "" CODE: RANDOMIZE USR 32768
        dw basic_fim-basic-4
        db $FD,$B0,'"32767":',$EF,'""',$AF,':',$F9,$C0,$B0,'"32768"',13
basic_fim:
        EMPTYTAP "cap01_3.tap"
        SAVETAP  "cap01_3.tap",BASIC,"cap01_3",basic,basic_fim-basic,10
        SAVETAP  "cap01_3.tap",CODE,"cap01_3",start,fim-start
```

Este programa vai um passo mais além e anima um asterisco desde o fundo até ao topo do ecrã:

```assembly
        DEVICE ZXSPECTRUM48
        ORG 32768
start:
        ld a,2              ; 2 = ecrã superior.
        call 5633           ; abrir canal.
        ld a,21             ; linha 21 = fundo do ecrã.
        ld (xcoord),a       ; definir coordenada x inicial.
loop:   call setxy          ; posicionar o cursor nas nossas coordenadas.
        ld a,'*'            ; queremos um asterisco aqui.
        rst 16              ; apresentá-lo.
        call delay          ; queremos um atraso.
        call setxy          ; posicionar o cursor nas nossas coordenadas.
        ld a,32             ; código ASCII do espaço.
        rst 16              ; apagar o asterisco antigo.
        ld hl,xcoord        ; posição vertical.
        dec (hl)            ; subir uma linha.
        ld a,(hl)           ; onde está ele agora?
        cp 255              ; já passou o topo do ecrã?
        jr nz,loop          ; não, continuar.
        ret

delay:  ld b,10             ; duração do atraso.
delay0: halt                ; esperar por uma interrupção.
        djnz delay0         ; repetir.
        ret

setxy:  ld a,22             ; código de controlo AT.
        rst 16              ; imprimi-lo.
        ld a,(xcoord)       ; posição vertical.
        rst 16              ; imprimi-la.
        ld a,(ycoord)       ; posição horizontal.
        rst 16              ; imprimi-la.
        ret

xcoord: defb 0
ycoord: defb 15
fim:

; --- Carregador BASIC + ficheiro .tap (igual em todos os exemplos) ---
        ORG 23755
basic:  db 0,10                 ; 10 CLEAR 32767: LOAD "" CODE: RANDOMIZE USR 32768
        dw basic_fim-basic-4
        db $FD,$B0,'"32767":',$EF,'""',$AF,':',$F9,$C0,$B0,'"32768"',13
basic_fim:
        EMPTYTAP "cap01_4.tap"
        SAVETAP  "cap01_4.tap",BASIC,"cap01_4",basic,basic_fim-basic,10
        SAVETAP  "cap01_4.tap",CODE,"cap01_4",start,fim-start
```

Repare que a etiqueta `loop` fica **depois** da inicialização da coordenada. Se ficasse antes de `ld a,21`, o asterisco voltaria à linha 21 em cada volta do ciclo e nunca sairia do sítio.

## Imprimir Gráficos Simples

Mover asteriscos pelo ecrã é muito bonito, mas mesmo para o jogo mais simples precisamos realmente de mostrar gráficos. Os gráficos avançados são discutidos em capítulos posteriores; por agora usaremos apenas gráficos simples do tipo *Space Invaders* e, como qualquer programador de BASIC lhe dirá, o Spectrum tem um mecanismo muito simples para isto: o Gráfico Definido pelo Utilizador (*User Defined Graphic*), geralmente abreviado para UDG.

A tabela de caracteres do Spectrum contém 21 caracteres gráficos definidos pelo utilizador (19 no modo 128K), do código 144 até ao 164 (162 no modo 128K). Em BASIC, os UDGs definem-se escrevendo dados (com `POKE`) na área de UDGs no topo da RAM, mas em código máquina faz mais sentido alterar a variável de sistema que aponta para o sítio onde os UDGs estão guardados, o que se faz alterando o valor de dois bytes no endereço 23675 (a variável `UDG`).

Podemos agora modificar o nosso programa do asterisco para mostrar um gráfico, com algumas alterações:

```assembly
        DEVICE ZXSPECTRUM48
        ORG 32768
start:
        ld hl,udgs          ; os nossos UDGs.
        ld (23675),hl       ; apontar a variável de sistema UDG para eles.
        ld a,2              ; 2 = ecrã superior.
        call 5633           ; abrir canal.
        ld a,21             ; linha 21 = fundo do ecrã.
        ld (xcoord),a       ; definir coordenada x inicial.
loop:   call setxy          ; posicionar o cursor nas nossas coordenadas.
        ld a,144            ; mostrar o UDG "A" em vez do asterisco.
        rst 16              ; apresentá-lo.
        call delay          ; queremos um atraso.
        call setxy          ; posicionar o cursor nas nossas coordenadas.
        ld a,32             ; código ASCII do espaço.
        rst 16              ; apagar o gráfico antigo.
        ld hl,xcoord        ; posição vertical.
        dec (hl)            ; subir uma linha.
        ld a,(hl)           ; onde está ele agora?
        cp 255              ; já passou o topo do ecrã?
        jr nz,loop          ; não, continuar.
        ret

delay:  ld b,10             ; duração do atraso.
delay0: halt                ; esperar por uma interrupção.
        djnz delay0         ; repetir.
        ret

setxy:  ld a,22             ; código de controlo AT.
        rst 16              ; imprimi-lo.
        ld a,(xcoord)       ; posição vertical.
        rst 16              ; imprimi-la.
        ld a,(ycoord)       ; posição horizontal.
        rst 16              ; imprimi-la.
        ret

xcoord: defb 0
ycoord: defb 15
udgs:   defb 60,126,219,153 ; o nosso gráfico, 8 bytes = 8 linhas de 8 píxeis.
        defb 255,255,219,219
fim:

; --- Carregador BASIC + ficheiro .tap (igual em todos os exemplos) ---
        ORG 23755
basic:  db 0,10                 ; 10 CLEAR 32767: LOAD "" CODE: RANDOMIZE USR 32768
        dw basic_fim-basic-4
        db $FD,$B0,'"32767":',$EF,'""',$AF,':',$F9,$C0,$B0,'"32768"',13
basic_fim:
        EMPTYTAP "cap01_5.tap"
        SAVETAP  "cap01_5.tap",BASIC,"cap01_5",basic,basic_fim-basic,10
        SAVETAP  "cap01_5.tap",CODE,"cap01_5",start,fim-start
```

É claro que nada impede que use mais do que os 21 UDGs, se assim o desejar. Basta ter vários bancos deles em memória e apontar para cada um à medida que precisa.

Em alternativa, pode redefinir o conjunto de caracteres. Isto dá-lhe uma gama maior, do código 32 (espaço) ao 127 (o símbolo de copyright). Pode até misturar texto e gráficos, redefinindo as letras e os números com o estilo da sua escolha e usando depois os símbolos e as letras minúsculas para alienígenas, zombies ou o que o seu jogo precisar. Para apontar para outro conjunto, subtraímos 256 ao endereço onde a fonte está e colocamos o resultado na variável de sistema de dois bytes no endereço 23606 (a variável `CHARS`). A fonte padrão da Sinclair, por exemplo, está no endereço 15616 da ROM, e por isso a variável em 23606 contém 15360 quando o Spectrum é ligado.

Este código copia a fonte da ROM para a RAM, tornando-a mais "negrita" pelo caminho, e depois põe a variável de sistema a apontar para ela. Quando o programa volta ao BASIC, a mensagem `0 OK` já aparece com a nova fonte:

```assembly
        DEVICE ZXSPECTRUM48
        ORG 32768
start:
        ld hl,15616         ; fonte da ROM.
        ld de,60000         ; endereço da nossa fonte.
        ld bc,768           ; 96 caracteres * 8 linhas a alterar.
font1:  ld a,(hl)           ; obter o padrão de bits.
        rlca                ; rodar para a esquerda.
        or (hl)             ; combinar as 2 imagens.
        ld (de),a           ; escrever na nova fonte.
        inc hl              ; próximo byte da antiga.
        inc de              ; próximo byte da nova.
        dec bc              ; decrementar o contador.
        ld a,b              ; byte alto.
        or c                ; combinar com o byte baixo.
        jr nz,font1         ; repetir até bc=zero.
        ld hl,60000-256     ; fonte menos 32*8.
        ld (23606),hl       ; apontar para a nova fonte.
        ret
fim:

; --- Carregador BASIC + ficheiro .tap (igual em todos os exemplos) ---
        ORG 23755
basic:  db 0,10                 ; 10 CLEAR 32767: LOAD "" CODE: RANDOMIZE USR 32768
        dw basic_fim-basic-4
        db $FD,$B0,'"32767":',$EF,'""',$AF,':',$F9,$C0,$B0,'"32768"',13
basic_fim:
        EMPTYTAP "cap01_6.tap"
        SAVETAP  "cap01_6.tap",BASIC,"cap01_6",basic,basic_fim-basic,10
        SAVETAP  "cap01_6.tap",CODE,"cap01_6",start,fim-start
```

## Mostrar Números

Na maioria dos jogos é melhor guardar a pontuação do jogador como uma string de dígitos ASCII, embora isso dê mais trabalho nas rotinas de pontuação e torne as tabelas de pontuações máximas um verdadeiro pesadelo para um programador de assembly inexperiente. Abordaremos isto num capítulo posterior; por agora, usaremos algumas rotinas úteis da ROM para imprimir números por nós.

Há duas formas de imprimir um número no ecrã. A primeira é usar a rotina que a ROM utiliza para imprimir os números de linha do Sinclair BASIC. Para isso, basta carregar o par de registos `bc` com o número que queremos imprimir e chamar 6683:

```assembly
        DEVICE ZXSPECTRUM48
        ORG 32768
start:
        ld a,2              ; ecrã superior.
        call 5633           ; abrir canal.
        ld bc,(score)       ; número a imprimir.
        call 6683           ; imprimir bc (de 0 a 9999).
        ret

score:  defw 1234
fim:

; --- Carregador BASIC + ficheiro .tap (igual em todos os exemplos) ---
        ORG 23755
basic:  db 0,10                 ; 10 CLEAR 32767: LOAD "" CODE: RANDOMIZE USR 32768
        dw basic_fim-basic-4
        db $FD,$B0,'"32767":',$EF,'""',$AF,':',$F9,$C0,$B0,'"32768"',13
basic_fim:
        EMPTYTAP "cap01_7.tap"
        SAVETAP  "cap01_7.tap",BASIC,"cap01_7",basic,basic_fim-basic,10
        SAVETAP  "cap01_7.tap",CODE,"cap01_7",start,fim-start
```

No entanto, como os números de linha do BASIC só vão até 9999, este método só consegue mostrar números de quatro dígitos. Quando a pontuação do jogador chega a 10000, aparecem outros caracteres em vez de algarismos.

Felizmente, existe outro método que vai muito mais longe. Em vez de chamar a rotina dos números de linha, podemos chamar a rotina que coloca o conteúdo de `bc` na pilha da calculadora (*calculator stack*) e depois outra rotina que mostra o número no topo dessa pilha. Não se preocupe com o que é a pilha da calculadora: tem pouca utilidade para um programador de jogos de arcada, mas onde pudermos tirar partido dela, fá-lo-emos. Basta lembrar que estas três linhas mostram um número de 0 a 65535:

```assembly
        DEVICE ZXSPECTRUM48
        ORG 32768
start:
        ld a,2              ; ecrã superior.
        call 5633           ; abrir canal.
        ld bc,(score)       ; número a imprimir.
        call 11563          ; colocar bc na pilha da calculadora.
        call 11747          ; mostrar o topo da pilha da calculadora.
        ret

score:  defw 54321
fim:

; --- Carregador BASIC + ficheiro .tap (igual em todos os exemplos) ---
        ORG 23755
basic:  db 0,10                 ; 10 CLEAR 32767: LOAD "" CODE: RANDOMIZE USR 32768
        dw basic_fim-basic-4
        db $FD,$B0,'"32767":',$EF,'""',$AF,':',$F9,$C0,$B0,'"32768"',13
basic_fim:
        EMPTYTAP "cap01_8.tap"
        SAVETAP  "cap01_8.tap",BASIC,"cap01_8",basic,basic_fim-basic,10
        SAVETAP  "cap01_8.tap",CODE,"cap01_8",start,fim-start
```

## Mudar as Cores

Para definir de forma permanente a tinta (*ink*), o papel (*paper*), o brilho e o *flash*, podemos escrever diretamente na variável de sistema `ATTR-P`, no endereço 23693, e depois limpar o ecrã com uma chamada à ROM:

```assembly
        DEVICE ZXSPECTRUM48
        ORG 32768
start:
        ; queremos um ecrã amarelo.
        ld a,49             ; tinta azul (1) em papel amarelo (6*8).
        ld (23693),a        ; definir as cores do ecrã.
        call 3503           ; limpar o ecrã.
        ret
fim:

; --- Carregador BASIC + ficheiro .tap (igual em todos os exemplos) ---
        ORG 23755
basic:  db 0,10                 ; 10 CLEAR 32767: LOAD "" CODE: RANDOMIZE USR 32768
        dw basic_fim-basic-4
        db $FD,$B0,'"32767":',$EF,'""',$AF,':',$F9,$C0,$B0,'"32768"',13
basic_fim:
        EMPTYTAP "cap01_9.tap"
        SAVETAP  "cap01_9.tap",BASIC,"cap01_9",basic,basic_fim-basic,10
        SAVETAP  "cap01_9.tap",CODE,"cap01_9",start,fim-start
```

A forma mais rápida e simples de mudar a cor da margem (*border*) é escrever na porta 254. Os 3 bits menos significativos do byte que enviamos determinam a cor; por isso, para pôr a margem a vermelho:

```assembly
        DEVICE ZXSPECTRUM48
        ORG 32768
start:
        ld a,2              ; 2 é o código do vermelho.
        out (254),a         ; escrever na porta 254.
        ret
fim:

; --- Carregador BASIC + ficheiro .tap (igual em todos os exemplos) ---
        ORG 23755
basic:  db 0,10                 ; 10 CLEAR 32767: LOAD "" CODE: RANDOMIZE USR 32768
        dw basic_fim-basic-4
        db $FD,$B0,'"32767":',$EF,'""',$AF,':',$F9,$C0,$B0,'"32768"',13
basic_fim:
        EMPTYTAP "cap01_10.tap"
        SAVETAP  "cap01_10.tap",BASIC,"cap01_10",basic,basic_fim-basic,10
        SAVETAP  "cap01_10.tap",CODE,"cap01_10",start,fim-start
```

A porta 254 também controla o altifalante e a ficha MIC, nos bits 4 e 3. No entanto, esta cor só dura até à próxima vez que a ROM mexer na margem (por exemplo, a rotina de som da ROM, ou o próprio BASIC quando o programa termina), por isso é necessária uma solução mais permanente. Para isso, basta carregar o acumulador com a cor pretendida e chamar a rotina da ROM em 8859. Esta rotina muda a cor e atualiza a variável de sistema `BORDCR` (no endereço 23624). Para uma margem vermelha permanente:

```assembly
        DEVICE ZXSPECTRUM48
        ORG 32768
start:
        ld a,2              ; 2 é o código do vermelho.
        call 8859           ; definir a cor da margem.
        ret
fim:

; --- Carregador BASIC + ficheiro .tap (igual em todos os exemplos) ---
        ORG 23755
basic:  db 0,10                 ; 10 CLEAR 32767: LOAD "" CODE: RANDOMIZE USR 32768
        dw basic_fim-basic-4
        db $FD,$B0,'"32767":',$EF,'""',$AF,':',$F9,$C0,$B0,'"32768"',13
basic_fim:
        EMPTYTAP "cap01_11.tap"
        SAVETAP  "cap01_11.tap",BASIC,"cap01_11",basic,basic_fim-basic,10
        SAVETAP  "cap01_11.tap",CODE,"cap01_11",start,fim-start
```

## Resumo

| Endereço | Rotina ou variável | Uso |
| :--- | :--- | :--- |
| `rst 16` | PRINT-A | Imprime o carácter em `a` no canal atual. |
| 5633 | CHAN-OPEN | Abre o canal indicado em `a` (1 = ecrã inferior, 2 = ecrã superior, 3 = impressora). |
| 8252 | PR-STRING | Imprime `bc` caracteres a partir do endereço `de`. |
| 3503 | CLS | Limpa o ecrã com as cores de `ATTR-P` e abre o canal 2. |
| 6683 | OUT-NUM | Imprime `bc` (0 a 9999). |
| 11563 + 11747 | STACK-BC + PRINT-FP | Imprime `bc` (0 a 65535). |
| 8859 | BORDER | Muda a cor da margem para `a` e atualiza `BORDCR`. |
| 23606 | CHARS | Endereço da fonte menos 256. |
| 23675 | UDG | Endereço do primeiro UDG. |
| 23693 | ATTR-P | Cores permanentes. |
| 23695 | ATTR-T | Cores temporárias (usadas pela próxima impressão). |

Um atributo de cor é um byte com a tinta nos bits 0-2, o papel nos bits 3-5, o brilho no bit 6 e o *flash* no bit 7. As cores vão de 0 a 7: preto, azul, vermelho, magenta, verde, ciano, amarelo e branco. Por isso, tinta azul em papel amarelo é 1 + 6×8 = 49, e tinta branca em papel preto com brilho é 7 + 0×8 + 64 = 71.
