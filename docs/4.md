# Capítulo Quatro - Números Aleatórios

Gerar números aleatórios em código máquina pode ser um problema complicado para um programador principiante.
Antes de mais nada, vamos esclarecer uma coisa. Não existe um gerador de números aleatórios propriamente dito. O CPU limita-se a seguir instruções e não tem mente própria, não podendo simplesmente tirar um número do nada com base num capricho. Em vez disso, precisa de seguir uma fórmula que produzirá uma sequência imprevisível de números que não parecem seguir qualquer tipo de padrão, dando assim a impressão de aleatoriedade. Tudo o que podemos fazer é retornar um número pseudoaleatório.

Um método para obter um número pseudoaleatório seria usar a sequência de Fibonacci, no entanto, o método mais fácil e rápido de gerar um número pseudoaleatório de 8 bits no Spectrum é avançar um ponteiro através da ROM e examinar o conteúdo do byte em cada posição sucessivamente. Há um pequeno inconveniente neste método – a ROM do Sinclair contém uma área muito uniforme e não aleatória em direção ao fim, a qual é melhor evitar. Ao limitar o ponteiro para, digamos, os primeiros 8K da ROM, continuamos a ter uma sequência de 8192 números "aleatórios", mais do que suficiente para a maioria dos jogos. De facto, todos os jogos que escrevi com um gerador de números aleatórios utilizam este método, ou um muito semelhante:

```assembly
    EMPTYTAP "4_prog1.tap"

    ; --- BASIC loader ---
    ORG $5D00
BasicStart:
    db 0,10
    dw Line1End-Line1Start
Line1Start:
    db $fd, $b0, $22, "32767", $22, $0d
Line1End:
    db 0,20
    dw Line2End-Line2Start
Line2Start:
    db $ef, $22, $22, $af, $0d
Line2End:
    db 0,30
    dw Line3End-Line3Start
Line3Start:
    db $f9, $c0, $b0, $22, "32768", $22, $0d
Line3End:
BasicEnd:
    SAVETAP "4_prog1.tap", BASIC, "loader", BasicStart, BasicEnd-BasicStart, 10

    ORG 32768

    DEVICE ZXSPECTRUM48
    ORG $8000

start:
    ; Gerador simples de números pseudoaleatórios.
    ; Avança um ponteiro através da ROM (guardado em seed), retornando
    ; o conteúdo do byte nessa posição.
random: ld hl,(seed)
    ld a,h
    and 31
    ld h,a              ; manter nos primeiros 8K da ROM.
    ld a,(hl)           ; obter número "aleatório" da posição.
    inc hl              ; incrementar ponteiro.
    ld (seed),hl
    ret
seed:
    defw 0              ; ponteiro.


    SAVESNA "4_prog1.sna", start
    SAVETAP "4_prog1.tap", CODE, "4_prog1", start, $ - start, start
```

Vamos colocar o nosso novo gerador de números aleatórios em uso no nosso jogo Centipede. Qualquer jogo Centipede precisa de cogumelos — muitos deles — espalhados aleatoriamente pela área de jogo, e agora podemos chamar a rotina `random` para fornecer coordenadas para cada cogumelo à medida que os mostramos. O código abaixo mostra as adições que precisamos de fazer.

```assembly
    EMPTYTAP "4_prog2.tap"

    ; --- BASIC loader ---
    ORG $5D00
BasicStart:
    db 0,10
    dw Line1End-Line1Start
Line1Start:
    db $fd, $b0, $22, "32767", $22, $0d
Line1End:
    db 0,20
    dw Line2End-Line2Start
Line2Start:
    db $ef, $22, $22, $af, $0d
Line2End:
    db 0,30
    dw Line3End-Line3Start
Line3Start:
    db $f9, $c0, $b0, $22, "32768", $22, $0d
Line3End:
BasicEnd:
    SAVETAP "4_prog2.tap", BASIC, "loader", BasicStart, BasicEnd-BasicStart, 10

    ORG 32768

    DEVICE ZXSPECTRUM48
    ORG $8000

start:
    ; Queremos um ecrã preto.
    ld a,71             ; tinta branca (7) em papel preto (0), brilho (64).
    ld (23693),a        ; definir as cores do nosso ecrã.
    xor a               ; forma rápida de carregar o acumulador com zero.
    call 8859           ; definir as cores permanentes da margem.

    ; Configurar os gráficos.
    ld hl,blocks        ; endereço dos dados dos gráficos definidos pelo utilizador.
    ld (23675),hl       ; fazer os UDGs apontarem para aí.

    ; Ok, vamos iniciar o jogo.
    call 3503           ; rotina da ROM que limpa o ecrã, abre o canal 2.

    ; Inicializar coordenadas.
    ld hl,21+15*256     ; carregar par hl com coordenadas iniciais.
    ld (plx),hl         ; definir as coordenadas do jogador.

    call basexy         ; definir as posições x e y do jogador.
    call splayr         ; mostrar símbolo da base do jogador.

    ; Agora queremos encher a área de jogo com cogumelos.
    ld a,68             ; tinta verde (4) em papel preto (0), brilho (64).
    ld (23695),a        ; definir as nossas cores temporárias.
    ld b,50             ; começar com alguns.
mushlp: ld a,22      ; código de controlo para o caráter AT.
    rst 16
    call random         ; obter um número "aleatório".
    and 15              ; queremos a coordenada vertical no intervalo de 0 a 15.
    rst 16
    call random         ; obter outro número pseudoaleatório.
    and 31              ; queremos a coordenada horizontal no intervalo de 0 a 31.
    rst 16
    ld a,145            ; UDG 'B' é o gráfico do cogumelo.
    rst 16              ; colocar cogumelo no ecrã.
    djnz mushlp         ; ciclo de volta até que todos os cogumelos sejam mostrados.

    ; Este é o ciclo principal.
mloop: equ $

    ; Apagar o jogador.
    call basexy         ; definir as posições x e y do jogador.
    call wspace         ; mostrar espaço sobre o jogador.

    ; Agora que apagámos o jogador, podemos movê-lo antes de o voltar a mostrar
    ; nas suas novas coordenadas.
    ld bc,63486         ; linha do teclado 1-5 / porta do joystick 2.
    in a,(c)            ; ver que teclas estão pressionadas.
    rra                 ; bit mais exterior = tecla 1.
    push af             ; lembrar o valor.
    call nc,mpl         ; está a ser pressionada, mover para a esquerda.
    pop af              ; restaurar acumulador.
    rra                 ; próximo bit (valor 2) = tecla 2.
    push af             ; lembrar o valor.
    call nc,mpr         ; está a ser pressionada, mover para a direita.
    pop af              ; restaurar acumulador.
    rra                 ; próximo bit (valor 4) = tecla 3.
    push af             ; lembrar o valor.
    call nc,mpd         ; está a ser pressionada, mover para baixo.
    pop af              ; restaurar acumulador.
    rra                 ; próximo bit (valor 8) = tecla 4.
    call nc,mpu         ; está a ser pressionada, mover para cima.

    ; Agora que se moveu, podemos voltar a mostrar o jogador.
    call basexy         ; definir as posições x e y do jogador.
    call splayr         ; mostrar o jogador.

    halt                ; atraso.

    ; Saltar de volta para o início do ciclo principal.
    jp mloop

    ; Mover jogador para a esquerda.
mpl:
    ld hl,ply           ; lembre-se, y é a coordenada horizontal!
    ld a,(hl)           ; qual é o valor atual?
    and a               ; é zero?
    ret z               ; sim, não podemos ir mais para a esquerda.
    dec (hl)            ; subtrair 1 à coordenada y.
    ret

    ; Mover jogador para a direita.
mpr:
    ld hl,ply           ; lembre-se, y é a coordenada horizontal!
    ld a,(hl)           ; qual é o valor atual?
    cp 31               ; está na extremidade direita (31)?
    ret z               ; sim, não podemos ir mais para a direita.
    inc (hl)            ; adicionar 1 à coordenada y.
    ret

    ; Mover jogador para cima.
mpu:
    ld hl,plx           ; lembre-se, x é a coordenada vertical!
    ld a,(hl)           ; qual é o valor atual?
    cp 4                ; está no limite superior (4)?
    ret z               ; sim, não podemos ir mais para cima.
    dec (hl)            ; subtrair 1 à coordenada x.
    ret

    ; Mover jogador para baixo.
mpd:
    ld hl,plx           ; lembre-se, x é a coordenada vertical!
    ld a,(hl)           ; qual é o valor atual?
    cp 21               ; já está no fundo (21)?
    ret z               ; sim, não podemos descer mais.
    inc (hl)            ; adicionar 1 à coordenada x.
    ret

    ; Configurar as coordenadas x e y para a posição da base/arma do jogador,
    ; esta rotina é chamada antes da visualização e eliminação da base.
basexy: ld a,22      ; código AT.
    rst 16
    ld a,(plx)          ; coordenada vertical do jogador.
    rst 16              ; definir posição vertical do jogador.
    ld a,(ply)          ; posição horizontal do jogador.
    rst 16              ; definir a coordenada horizontal.
    ret

    ; Mostrar o jogador na posição de impressão atual.
splayr: ld a,69      ; tinta ciano (5) no papel preto (0), brilho (64).
    ld (23695),a        ; definir as nossas cores de ecrã temporárias.
    ld a,144            ; código ASCII para Gráfico Definido pelo Utilizador 'A'.
    rst 16              ; desenhar o jogador.
    ret

wspace: ld a,71      ; tinta branca (7) no papel preto (0), brilho (64).
    ld (23695),a        ; definir as nossas cores de ecrã temporárias.
    ld a,32             ; caráter de ESPAÇO.
    rst 16              ; mostrar espaço.
    ret

    ; Gerador simples de números pseudoaleatórios.
    ; Avança um ponteiro através da ROM (guardado em seed), retornando
    ; o conteúdo do byte nessa posição.
random: ld hl,(seed)
    ld a,h
    and 31
    ld h,a              ; manter nos primeiros 8K da ROM.
    ld a,(hl)           ; obter número "aleatório" da posição.
    inc hl              ; incrementar ponteiro.
    ld (seed),hl
    ret
seed:
    defw 0              ; ponteiro

plx: defb 0          ; coordenada x do jogador.
ply: defb 0          ; coordenada y do jogador.

    ; Gráficos UDG.
blocks: defb 16,16,56,56,124,124,254,254  ; base do jogador.
    defb 24,126,255,255,60,60,60,60          ; cogumelo.


    SAVESNA "4_prog2.sna", start
    SAVETAP "4_prog2.tap", CODE, "4_prog2", start, $ - start, start
```

Uma vez executado, este programa parece-se muito mais com um jogo Centipede do que antes, mas há um grande problema. Os cogumelos estão distribuídos de forma aleatória pelo ecrã, mas o jogador consegue passar diretamente através deles. É necessária alguma forma de deteção de colisão para evitar que isto aconteça, e iremos abordar esse tema no próximo capítulo.

## O Engenho da Ilusão: Decifrar a Falsa Aleatoriedade

No dealbar desta nova incursão, convém desmascarar a engenhosa pantomina subjacente à nossa rotina de números supostamente aleatórios. O austero Z80 que habita no âmago do ZX Spectrum desconhece na sua frieza matemática o luxo e a incerteza de um verdadeiro gerador físico de entropia ditado por hardware. A carência é ultrapassada através duma miragem cirúrgica alicerçada num recanto sagrado do próprio computador: os primórdios dos seus dezasseis kilobytes de memória inicial (balizados estritamente do marco `$0000` até à orla de `$3FFF`), onde repousa encerrada de fábrica a intocável ROM. Esta dita ROM não é mais do que a espinha dorsal de todo o código máquina encarregue de acordar a máquina e correr a alma do Sinclair BASIC. 
Perante as puras abstrações algorítmicas do processador, as intricadas e morosas instruções encastradas nesta região sagrada assumem o modesto semblante de dados nus: fileiras cegas de meros bytes encafuados com valores de 0 a 255. Graças à extrema densidade e aparente desconexão matemática visual do estendal brutal destas milhares de instruções heterogéneas alinhavadas consecutivamente de fábrica, a leitura vertiginosa transigindo este leito através do trilho consecutivo dum ponteiro faz despontar uma bizarra cacofonia numérica. É precisamente a extração individual perante cada novo passo desse caos contíguo aparente na estática da ROM que transfigura um código banal e imutável num exímio poço de "ruído" numérico pseudoaleatório com propriedades divinais na orquestração dos caprichos dos nossos videojogos.

Desfiar a manobra que extrai e afunila esta cacofonia passa forçosamente pela dissecação impiedosa de cada dita e linha do algoritmo encarregue dessa leitura cega batizado modestamente como `random`. O estribo da jornada assenta invariavelmente na recuperação da dita semente fundacional ditada pela invocação de abertura através do comando de transferência para apontar alojado no par `ld hl, (seed)`. A alusão vital ditada na orla dos estritos parênteses decreta cabalmente o assalto ao conteúdo encerrado no preciso endereço reservado sob a etiqueta nominal de `seed`, alocando providencialmente e recarregando esse rasto com a matriz de dezasseis bits assentes e confinados à proteção segura na calha do par de registos `HL`.
A encruzilhada contígua cimenta as defesas contra invasões imprevistas varrendo limites fronteiriços, submetendo o registo alto deste leito face à manobra assente numa cirurgia perante a instrução `and 31`. Sob o rigor matemático dos trâmites binários, o número trinta e um desdobra-se e rebaixa perante a purificação de um ditame amarrado em zero inicial seguido duma procissão exata de oitos bits recheada e balizada na matriz base cravada de uns ditos `00011111`. Comprimir esta estrita máscara de cerco em colisão e atrito cruzado dita por encarte sobre as metades do registo alojado em `H` (regente da metade altiva superior nas amarras dos confins do endereço) ceifa e extermina qualquer desvio superior impiedosamente estipulando um teto matemático implacável de 31. Coroando e empurrando este limite inviolável a rotina esmaga de imediato o estribo cravando o destino inabalável onde o par `HL` fica irrevogavelmente enclausurado operando estritamente cativo no interior balizado inferior dos escombros ditos no vale dos oitos kilobytes base (restringindo varrimentos colados cegamente num horizonte absoluto exato de 0 até um topo a atirar na fasquia 8191 em decimal das valências de base alojando do inicial marco em `$0000` esticando irrevogavelmente ao limite barreira intransponível na fenda superior amarrada em `$1FFF`). O engenhoso confinamento impede em definitivo descarrilamentos de transbordos de leitura atirando o apontador com a semente numa viagem fatal desbravando acidental dados voláteis além-fronteiras na RAM originando colapsos de lógica caóticos que implodiriam a dita pureza aparente estática cravada do aleatório.
Em chão seguro resvala no auge da missão o confiscar dum byte almejado atirando do trilho apontado balizado em `HL` num resgate providencial encostado no âmago de abrigo do Acumulador assente através do golpe `ld a, (hl)`. Resta afinal à maquinaria arrastar a coroa empurrando e acautelando a viagem futura perante um resguardo unitário na matriz ditado sob o estrito cume no incremento vital cravado no rodopio unitário operatório assente subscrito na diretiva `inc hl`; devolvendo em último desígnio o valioso espolio do avanço num resguardo e descanso letárgico seguro ditado e recarregado sob o manto do encarte contíguo com devolução ditada por `ld (seed), hl`. Nasce ali em banho vitalícia a conservação estática assegurando a semente perpetrada reescrita preservada intacta na vala das calhas aguardando serena a chamada duma iminente repetição infalível operatória na dita função da falsa incerteza.
