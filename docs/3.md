# Capítulo Três - Efeitos Sonoros do Altifalante

## O Altifalante

Existem duas formas de gerar som e música no ZX Spectrum, a melhor e mais complicada das quais é através do chip de som AY-3-8912 nos modelos 128K. Este método é descrito em detalhe num capítulo posterior, mas por agora vamo-nos focar no altifalante do 48K. Pode ser simples, mas este método tem a sua utilidade, especialmente para efeitos sonoros curtos e rápidos durante os jogos.

## Beep

Antes de mais nada, precisamos de saber como produzir um sinal sonoro (*beep*) de um determinado tom e duração, e a ROM do Sinclair tem uma rotina bastante acessível para fazer o trabalho por nós no endereço 949. Tudo o que é necessário é passar os parâmetros de tom no par de registos HL e a duração em DE, chamar 949 e obtemos um *beep* apropriado.

Infelizmente, a forma como calculamos os parâmetros necessários é um pouco complicada, pois requer algum cálculo. Precisamos de saber o valor em Hertz para a frequência da nota a emitir, que é essencialmente apenas o número de vezes que o altifalante precisa de ser alternado a cada segundo para produzir o tom desejado. Uma tabela adequada encontra-se abaixo:

| Nota | Frequência (Hz) |
| :--- | :--- |
| Dó Central | 261.63 |
| Dó sustenido | 277.18 |
| Ré | 293.66 |
| Ré sustenido | 311.13 |
| Mi | 329.63 |
| Fá | 349.23 |
| Fá sustenido | 369.99 |
| Sol | 392.00 |
| Sol sustenido | 415.30 |
| Lá | 440.00 |
| Lá sustenido | 466.16 |
| Si | 493.88 |

Para cada oitava acima, basta duplicar a frequência; para descer uma oitava, divida-a por dois. Por exemplo, para produzir uma nota Dó uma oitava acima do Dó central, pegamos no valor do Dó Central - 261.63, e duplicamos para 523.26.

Uma vez estabelecida a frequência, multiplicamo-la pelo número de segundos pretendidos e passamos o resultado à rotina da ROM no par de registos DE como a duração - portanto, para reproduzir a nota Dó central durante um décimo de segundo, a duração necessária seria 261.63 * 0.1 = 26. O tom é calculado dividindo primeiro 437500 pela frequência, subtraindo 30.125 e passando o resultado nos registos HL. Para o Dó central, isto significaria um valor de 437500 / 261.63 - 30.125 = 1642.

Por outras palavras:
DE = Duração = Frequência * Segundos
HL = Tom = 437500 / Frequência - 30.125

Assim, para tocar a nota Sol sustenido uma oitava acima do Dó central durante um quarto de segundo:

```assembly
    EMPTYTAP "3_prog1.tap"

    ; --- BASIC loader ---
    ORG $5D00
BasicStart:
    db 0,10
    dw Line1End-Line1Start
Line1Start:
    db $fd, $b0, $22, "32767", $22, $0d
Line1End:
    db 0,20
    dw Line2End-Line2Start
Line2Start:
    db $ef, $22, $22, $af, $0d
Line2End:
    db 0,30
    dw Line3End-Line3Start
Line3Start:
    db $f9, $c0, $b0, $22, "32768", $22, $0d
Line3End:
BasicEnd:
    SAVETAP "3_prog1.tap", BASIC, "loader", BasicStart, BasicEnd-BasicStart, 10

    ORG 32768

    DEVICE ZXSPECTRUM48
    ORG $8000

start:
    ; Frequência do Sol sustenido na oitava do Dó central = 415.30
    ; Frequência do Sol sustenido uma oitava acima = 830.60
    ; Duração = 830.6 / 4 = 207.65
    ; Tom = 437500 / 830.6 - 30.125 = 496.6
    ld hl,497          ; tom.
    ld de,208          ; duração.
    call 949           ; rotina do beeper da ROM.
    ret


    SAVESNA "3_prog1.sna", start
    SAVETAP "3_prog1.tap", CODE, "3_prog1", start, $ - start, start
```

Claro que esta rotina não serve apenas para notas musicais - também a podemos usar para uma variedade de efeitos, sendo um dos meus favoritos uma rotina simples de *pitch bend* (modulação de tom):

```assembly
    EMPTYTAP "3_prog2.tap"

    ; --- BASIC loader ---
    ORG $5D00
BasicStart:
    db 0,10
    dw Line1End-Line1Start
Line1Start:
    db $fd, $b0, $22, "32767", $22, $0d
Line1End:
    db 0,20
    dw Line2End-Line2Start
Line2Start:
    db $ef, $22, $22, $af, $0d
Line2End:
    db 0,30
    dw Line3End-Line3Start
Line3Start:
    db $f9, $c0, $b0, $22, "32768", $22, $0d
Line3End:
BasicEnd:
    SAVETAP "3_prog2.tap", BASIC, "loader", BasicStart, BasicEnd-BasicStart, 10

    ORG 32768

    DEVICE ZXSPECTRUM48
    ORG $8000

start:
loop:
    ld hl,500          ; tom inicial.
    ld b,250           ; comprimento da modulação.
    push bc
    push hl            ; guardar tom.
    ld de,1            ; duração muito curta.
    call 949           ; rotina do beeper da ROM.
    pop hl             ; restaurar tom.
    inc hl             ; tom a subir.
    pop bc
    djnz loop          ; repetir.
    ret


    SAVESNA "3_prog2.sna", start
    SAVETAP "3_prog2.tap", CODE, "3_prog2", start, $ - start, start
```

Experimente a rotina acima - ao fazer pequenos ajustes, é bastante fácil subir e descer o tom, e alterar a frequência inicial, a modulação de tom e a duração, produzindo uma série de efeitos interessantes. Mas fica um aviso: não abuse nos valores de tom ou duração, caso contrário a rotina do beeper ficará bloqueada e não conseguirá recuperar o controlo do seu Spectrum sem o reiniciar.

## Ruído Branco

Ao utilizar o altifalante, nem sequer precisamos de nos limitar às rotinas da ROM; é bastante fácil escrever as nossas próprias rotinas de efeitos sonoros, especialmente se quisermos gerar ruído branco para colisões e explosões. O ruído branco é normalmente muito mais divertido de usar.

Para gerar ruído branco, tudo o que precisamos é de um gerador de números aleatórios rápido e simples (uma sequência de Fibonacci poderia funcionar, mas eu recomendaria percorrer um ponteiro pelos primeiros 8K da ROM e obter o byte em cada posição para conseguir um número de 8 bits razoavelmente aleatório). Depois, escreva esse valor na porta 254. Lembre-se de que esta porta também controla a cor da margem (border), por isso, se não quiser um efeito de margem listrada multicolorida, precisamos de mascarar os bits da margem com AND 248 e adicionar o número da cor da margem que pretendemos (1 para azul, 2 para vermelho, etc.) antes de executar uma instrução OUT (254).

Depois de fazermos isto, precisamos de colocar um pequeno ciclo de atraso (curto para tons altos, longo para tons mais baixos) e repetir o processo algumas centenas de vezes. Isto dar-nos-á um bom efeito de "explosão" (*crash*).

Esta rotina é baseada num efeito sonoro do Egghead 3:

```assembly
    EMPTYTAP "3_prog3.tap"

    ; --- BASIC loader ---
    ORG $5D00
BasicStart:
    db 0,10
    dw Line1End-Line1Start
Line1Start:
    db $fd, $b0, $22, "32767", $22, $0d
Line1End:
    db 0,20
    dw Line2End-Line2Start
Line2Start:
    db $ef, $22, $22, $af, $0d
Line2End:
    db 0,30
    dw Line3End-Line3Start
Line3Start:
    db $f9, $c0, $b0, $22, "32768", $22, $0d
Line3End:
BasicEnd:
    SAVETAP "3_prog3.tap", BASIC, "loader", BasicStart, BasicEnd-BasicStart, 10

    ORG 32768

    DEVICE ZXSPECTRUM48
    ORG $8000

start:
noise:
    ld e,250           ; repetir 250 vezes.
    ld hl,0            ; ponteiro inicial na ROM.
noise2: push de
    ld b,32            ; comprimento do passo.
noise0: push bc
    ld a,(hl)          ; próximo número "aleatório".
    inc hl             ; ponteiro.
    and 248            ; queremos uma margem preta.
    out (254),a        ; escrever no altifalante.
    ld a,e
        cpl                ; à medida que e diminui...
                   ; ...aumentamos o atraso.
noise1: dec a       ; decrementar contador do ciclo.
    jr nz,noise1       ; ciclo de atraso.
    pop bc
    djnz noise0        ; próximo passo.
    pop de
    ld a,e
    sub 24             ; tamanho do passo.
    cp 30              ; fim do intervalo.
    ret z
    ret c
    ld e,a
    cpl
noise3: ld b,40
noise4: djnz noise4 ; período de silêncio.
    dec a
    jr nz,noise3
    jr noise2


    SAVESNA "3_prog3.sna", start
    SAVETAP "3_prog3.tap", CODE, "3_prog3", start, $ - start, start
```

## Explicação para Iniciantes: Como Funciona sob o Capô

A geração de som e ruído no Spectrum ilustra dois conceitos cruciais do Z80: a cooperação com a ROM de fábrica da máquina e a gestão da pilha para proteger os nossos dados.

### 1. Chamadas de ROM (`call`) e Rotinas Embutidas
O ZX Spectrum possui um chip de memória de apenas leitura (ROM) de 16KB que contém o interpretador de BASIC e centenas de rotinas úteis escritas pelos engenheiros da Sinclair.
*   **Rotina do Beeper (endereço `949` ou `$03B5`)**: Esta rotina lê a duração no par de registos `DE` e o tom no par de registos `HL`, fazendo o altifalante oscilar na frequência correta. Em vez de escrevermos dezenas de linhas de código para calcular tempos de onda e enviar impulsos elétricos para o altifalante, basta fazermos `call 949`.
*   A instrução `call` empilha automaticamente o endereço da instrução seguinte na memória e salta para a ROM. Quando a ROM executa a instrução `ret` no final do beeper, o CPU sabe exatamente para onde voltar no nosso código.

### 2. A Pilha (Stack) e as instruções `push` / `pop`
Como o Z80 tem muito poucos registos (`A`, `B`, `C`, etc.), é muito comum ficarmos sem espaço temporário para guardar valores. Pior: ao chamarmos uma rotina da ROM (como o beeper em `949`), essa rotina vai usar os registos para o seu próprio trabalho, apagando quaisquer valores que lá estivessem antes!
Para evitar perder os dados, usamos a **Pilha** (uma zona especial da RAM gerida pelo registo Stack Pointer `SP`):
*   **`push hl`**: Guarda temporariamente o valor de `HL` "no topo" da pilha.
*   **`pop hl`**: Retira o valor do topo da pilha e coloca-o de volta em `HL`.
*   Ao fazermos:
    ```assembly
    push hl   ; guardar o tom antes da chamada
    call 949  ; chamar a ROM (que vai destruir HL, DE, BC...)
    pop hl    ; restaurar o nosso tom original intacto
    ```
    Garantimos que o nosso ciclo principal continua a funcionar com os valores certos.

### 3. Ciclos de Atraso e Controle de Loops (`djnz`)
No Z80, os loops de tempo e repetição de blocos são geridos por flags de estado:
*   **`djnz` (Decrement and Jump if Not Zero)**: É uma instrução extremamente útil. Ela faz automaticamente duas coisas de uma só vez:
    1. Decrementa em 1 o valor do registo `B`.
    2. Se o registo `B` ainda não chegou a zero, o CPU salta para o endereço/label indicado.
    *   Isto é ideal para ciclos que precisam de correr um número fixo de vezes (até 256 vezes).
*   **`jr nz, label` (Jump Relative if Not Zero)**: Faz o salto se a última operação aritmética ou lógica (como `dec a` ou `sub 24`) não deu um resultado igual a zero. Se deu zero, o salto é ignorado e o programa continua na linha seguinte.
