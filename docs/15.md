# Capítulo Quinze - Matemática

Somar e subtrair é bastante simples no CPU do Spectrum; temos uma abundância de instruções para realizar estas tarefas. Mas, ao contrário de alguns processadores posteriores da série, o programador do Z80A tem de fazer a sua própria multiplicação e divisão. Embora tais cálculos sejam raros, eles têm a sua utilidade em certos tipos de jogos e, até ter rotinas para fazer o trabalho, algumas coisas são muito difíceis de realizar. Por exemplo, sem o teorema de Pitágoras, pode ser difícil programar um *sprite* inimigo para disparar contra o jogador com algum grau de precisão.

Suponha que o *sprite* A precisa de disparar um tiro contra o *sprite* B. Precisamos de encontrar o ângulo no qual o *sprite* A deve disparar, e alguma trigonometria é necessária para fazer isto. Sabemos as coordenadas dos *sprites*, Ax, Ay, Bx e By, e as distâncias entre estas, Bx-Ax e By-Ay, dar-nos-ão os comprimentos dos catetos oposto e adjacente. Infelizmente, a única forma de calcular o ângulo a partir do cateto oposto e do adjacente é usar o arco-tangente e, como as tangentes apenas são adequadas para certos ângulos, é preferível usarmos o seno ou o cosseno. Portanto, para encontrar o ângulo do *sprite* A para o *sprite* B, precisamos de encontrar o comprimento da hipotenusa.

A hipotenusa é calculada elevando ao quadrado a distância x, somando-a ao quadrado da distância y e, de seguida, encontrando a raiz quadrada da soma. Existem rotinas na ROM do Sinclair para fazer tudo isto, mas há um grave inconveniente: como qualquer pessoa que já tenha usado o Sinclair BASIC lhe dirá, as rotinas matemáticas da ROM são incrivelmente lentas para a escrita de jogos. Portanto, temos de meter mãos à obra e escrever as nossas próprias rotinas.

Elevar ao quadrado as nossas distâncias x e y significa usar uma rotina de multiplicação e multiplicar os números por si mesmos. Felizmente, esta parte é relativamente simples. A multiplicação é realizada da mesma forma que faria uma multiplicação longa no papel, embora desta vez estejamos a trabalhar em binário. Tudo o que é necessário é deslocamento (*shifting*), teste de bits e adição. Onde existir um bit no nosso primeiro fator, adicionamos o segundo fator ao total. De seguida, deslocamos o segundo fator para a esquerda e testamos o bit seguinte no nosso primeiro fator. A rotina abaixo, retirada de *Kuiper Pursuit*, demonstra a técnica ao multiplicar `H` por `D` e retornar o resultado em `HL`.

```assembly
    ; HL = H * D
imul:
    ld e,d              ; fazer do acumulador o primeiro multiplicador.
    ld a,h
    ld hl,0             ; zerar total.
    ld d,h              ; zerar byte alto para de = multiplicador.
    ld b,8              ; repetir 8 vezes.
imul1:
    rra                 ; rodar o bit mais à direita para o carry.
    jr nc,imul2         ; não estava ativo.
    add hl,de           ; bit estava ativo, adicionar de.
imul2:
    and a               ; reiniciar carry.
    rl e
    rl d                ; deslocar de 1 bit para a esquerda.
    djnz imul1          ; repetir 8 vezes.
    ret
```

Agora precisamos de uma raiz quadrada, que é onde começam os nossos problemas. As raízes quadradas são muito mais complicadas. Isto implica fazer muitas divisões, por isso primeiro precisamos de uma rotina de divisão. Esta funciona de forma oposta à multiplicação, através de deslocamentos e subtrações. A rotina seguinte divide `HL` por `D` e devolve o resultado em `HL` e o resto em `A`. Funciona como a divisão longa feita à mão, em binário: os bits do dividendo entram um a um no resto (`add hl,hl` seguido de `rla`) e, sempre que o resto chega para subtrair o divisor, subtrai-se e põe-se a 1 o bit correspondente do resultado. Os bits do resultado vão ocupando o lugar dos bits do dividendo que já saíram de `HL`, e é por isso que o resultado fica no próprio `HL`.

> A rotina de divisão que acompanhava este capítulo no livro original (de *Kuiper Pursuit*) tem um erro e devolve resultados errados na maioria dos casos (por exemplo, 17611 / 146 dava 60 em vez de 120). A versão abaixo foi reescrita e testada com mais de 20 000 divisões.

```assembly
    ; HL = HL / D (D de 1 a 255), resto em A.
idiv:
    xor a               ; a = resto parcial, começa a zero.
    ld b,16             ; 16 bits no dividendo.
idiv1:
    add hl,hl           ; deslocar hl para a esquerda: o bit de cima vai para o carry...
    rla                 ; ...e entra no resto.
    jr c,idiv2          ; o resto passou de 255, por isso é maior do que d.
    cp d                ; o resto já chega para subtrair d?
    jr c,idiv3          ; não, este bit do resultado fica a 0.
idiv2:
    sub d               ; sim: subtrair o divisor ao resto
    inc l               ; e pôr a 1 este bit do resultado.
idiv3:
    djnz idiv1          ; repetir para os 16 bits.
    ret
```

Da mesma forma que a multiplicação é composta por deslocamentos e adições, e a divisão é feita através de deslocamentos e subtrações, as raízes quadradas podem ser calculadas por deslocamento e divisão. Estamos simplesmente a tentar encontrar o número que "melhor se ajusta" e que, quando multiplicado por si mesmo, nos dá o número com o qual começámos. Não entrarei em explicações detalhadas sobre como funciona a rotina seguinte – se estiver interessado, siga os comentários e analise-a num depurador (*debugger*). Esta rotina, baseada na de *Blizzard's Rift* e adaptada à rotina de divisão acima, devolve a raiz quadrada de `HL` no acumulador. A ideia é construir o resultado bit a bit, do mais alto para o mais baixo: para cada bit, experimenta-se o resultado com esse bit ligado (o "candidato") e verifica-se se número / candidato ≥ candidato, o que é o mesmo que candidato² ≤ número. Se for, o bit fica ligado.

```assembly
    ; Devolve em a a raiz quadrada (inteira) de hl.
isqr:
    ld (sqbuf0),hl      ; número de que queremos a raiz quadrada.
    xor a
    ld (sqbuf2),a       ; resultado, começa a zero.
    ld a,128            ; começar pelo bit mais alto.
    ld (sqbuf1),a       ; bit a experimentar.
    ld b,8              ; 8 bits no resultado.
isqr1:
    push bc             ; guardar contador do ciclo.
    ld a,(sqbuf2)       ; resultado até agora.
    ld d,a
    ld a,(sqbuf1)       ; próximo bit a experimentar.
    or d                ; juntá-lo ao resultado: este é o candidato.
    ld d,a
    push de             ; guardar o candidato.
    ld hl,(sqbuf0)      ; número original.
    call idiv           ; hl = número / candidato.
    pop de              ; recuperar o candidato em d.
    ld a,h
    and a               ; quociente maior do que 255?
    jr nz,isqr2         ; sim, é certamente >= candidato: guardar o bit.
    ld a,l
    cp d                ; quociente < candidato?
    jr c,isqr0          ; sim, o candidato é demasiado grande.
isqr2:
    ld a,d
    ld (sqbuf2),a       ; guardar o novo resultado.
isqr0:
    ld hl,sqbuf1        ; bit que experimentámos.
    and a               ; limpar flag de carry.
    rr (hl)             ; passar ao bit seguinte, à direita.
    pop bc              ; restaurar contador do ciclo.
    djnz isqr1          ; repetir.
    ld a,(sqbuf2)       ; devolver o resultado em a.
    ret

sqbuf0: defw 0
sqbuf1: defb 0
sqbuf2: defb 0
```

Com o comprimento da hipotenusa calculado, podemos simplesmente dividir o cateto oposto pela hipotenusa para encontrar o cosseno do ângulo. Uma pesquisa rápida na nossa tabela de senos dir-nos-á então que ângulo é esse. Ufa!

Esta é a rotina de cálculo completa retirada de *Blizzard's Rift*. Não é um programa para correr sozinho: além de `imul` e `isqr`, usa uma rotina de divisão de números de vírgula fixa (`div`) e uma tabela de arco-senos (`asn`) que não fazem parte do livro, e as coordenadas da nave e da torre (`nshipx`, `nshipy`, `gunx`, `guny`…). Note que ela utiliza o comprimento do cateto adjacente em vez do oposto, pelo que encontra o arco-cosseno em vez do arco-seno. Também é apenas utilizada quando a nave está acima da torre de artilharia, dando ao jogador a oportunidade de se aproximar sorrateiramente e atacar por baixo. No entanto, demonstra como um *sprite* pode disparar sobre outro com precisão mortal. Se alguma vez jogou *Blizzard's Rift*, saberá exatamente quão letais aquelas torres de artilharia podem ser.

```assembly
    ; A nave está acima da arma, pelo que podemos empregar alguma trigonometria básica para fazer a mira.
    ; Precisamos de encontrar o ângulo e, para o fazer, dividimos o cateto adjacente pela
    ; hipotenusa e encontramos o arco-cosseno.
    ; Antes de mais, colocamos o comprimento do oposto na pilha:
mgunx:
    ld a,(nshipy)       ; coordenada y da nave.
    ld hl,guny          ; coord y da arma.
    sub (hl)            ; encontrar diferença.
    jr nc,mgun0         ; o resultado foi positivo.
    neg                 ; negativo, torná-lo positivo.
mgun0:
    cp 5                ; diferença de y menor que 5?
    jr c,mgunu          ; sim, apontar direto para cima.
    push af             ; colocar comprimento do oposto na pilha.

    ; A seguir, precisamos do comprimento da hipotenusa e podemos usar o
    ; bom e velho teorema de Pitágoras para isso.
    ld h,a              ; copiar a para h.
    ld d,h              ; copiar h para d.
    call imul           ; multiplicar partes inteiras para obter resultado de 16 bits.
    push hl             ; lembrar valor quadrado.

    ld hl,nshipx        ; coordenada x da nave.
    ld a,(gunx)         ; coordenada x da arma.
    sub (hl)            ; encontrar diferença (será sempre positiva).
    ld h,a              ; colocar diferença de x em h.
    ld d,h              ; copiar h para d.
    call imul           ; multiplicar h por d para obter o quadrado.

    pop de              ; obter o último resultado quadrado.
    add hl,de           ; queremos a soma dos dois.
    call isqr           ; encontrar a raiz quadrada, hipotenusa em a.
    pop de              ; cateto oposto agora no registo d.

    ld h,a              ; comprimento da hipotenusa.
    ld l,0              ; sem fração ou sinal.
    ex de,hl            ; trocar os registos.
    ; O cateto oposto e a hipotenusa estão agora em de e hl.
    ; Agora dividimos o primeiro pelo segundo e encontramos o arco-seno.
    ; Lembre-se: seno = oposto / hipotenusa.
    call div            ; a divisão dar-nos-á o seno.
    ex de,hl            ; queremos o resultado em de.
    call asn            ; obter o arco-seno para encontrar o ângulo.
    push af

    ; Muito bem, temos o ângulo mas este é apenas de 0 a pi/2 radianos (64 ângulos),
    ; pelo que precisamos de fazer um ajuste com base no quadrante do círculo.
    ; Podemos estabelecer em que quadrante do círculo o nosso ângulo se encontra
    ; examinando as diferenças entre as coordenadas da nave e da arma.
    ld a,(guny)         ; posição y da arma.
    ld hl,shipy         ; y da nave.
    cp (hl)
    jr nc,mgun2         ; a nave está à direita?
                    ; jogador à esquerda, ângulo no segundo quadrante.

    ; O ângulo a jogar está no primeiro quadrante, pelo que precisa de ser subtraído a 64.
    ld a,64             ; pi/2 radianos = 64 ângulos.
    pop bc              ; ângulo em b.
    sub b               ; fazer a subtração.
    ld (ix+1),a         ; novo ângulo.
    ret                 ; temos o nosso ângulo.

    ; Segundo quadrante - adicionar o valor literal 64 ao nosso ângulo.
mgun2:
    pop af              ; ângulo original.
    add a,192           ; adicionar pi/2 radianos.
    ld (ix+1),a         ; novo ângulo.
    ret                 ; trabalho concluído!
```

## Um Exemplo Completo

Este programa usa as três rotinas para calcular a hipotenusa de três triângulos (√(3² + 4²) = 5, √(30² + 40²) = 50 e √(200² + 100²) ≈ 223) e uma divisão com resto (12345 / 7 = 1763, resto 4), e mostra os resultados no ecrã:

```assembly
        DEVICE ZXSPECTRUM48
        ORG 32768
start:
    ld a,2              ; ecrã superior.
    call 5633           ; abrir canal.
    ld h,3              ; hipotenusa de um triângulo de catetos 3 e 4.
    ld d,4
    call hipot          ; deve dar 5.
    call mostra
    ld h,30             ; catetos 30 e 40: deve dar 50.
    ld d,40
    call hipot
    call mostra
    ld h,200            ; catetos 200 e 100: deve dar 223 (223,6...).
    ld d,100
    call hipot
    call mostra
    ld hl,12345         ; 12345 / 7 = 1763, resto 4.
    ld d,7
    call idiv
    push af             ; guardar o resto.
    ld b,h
    ld c,l
    call 6683           ; mostrar o quociente.
    ld a,' '
    rst 16
    pop af
    ld b,0
    ld c,a
    call 6683           ; mostrar o resto.
    ret

    ; a = raiz quadrada de (h*h + d*d).
hipot:
    push de             ; guardar o segundo cateto.
    ld d,h
    call imul           ; hl = h * h.
    pop de
    push hl             ; guardar o primeiro quadrado.
    ld h,d
    call imul           ; hl = d * d.
    pop de
    add hl,de           ; somar os dois quadrados.
    jp isqr             ; a = raiz quadrada.

    ; Mostrar o número em a e mudar de linha.
mostra:
    ld b,0
    ld c,a
    call 6683           ; mostrar bc.
    ld a,13
    rst 16
    ret

    ; HL = H * D
imul:
    ld e,d              ; fazer do acumulador o primeiro multiplicador.
    ld a,h
    ld hl,0             ; zerar total.
    ld d,h              ; zerar byte alto para de = multiplicador.
    ld b,8              ; repetir 8 vezes.
imul1:
    rra                 ; rodar o bit mais à direita para o carry.
    jr nc,imul2         ; não estava ativo.
    add hl,de           ; bit estava ativo, adicionar de.
imul2:
    and a               ; reiniciar carry.
    rl e
    rl d                ; deslocar de 1 bit para a esquerda.
    djnz imul1          ; repetir 8 vezes.
    ret

    ; HL = HL / D (D de 1 a 255), resto em A.
idiv:
    xor a               ; a = resto parcial, começa a zero.
    ld b,16             ; 16 bits no dividendo.
idiv1:
    add hl,hl           ; deslocar hl para a esquerda: o bit de cima vai para o carry...
    rla                 ; ...e entra no resto.
    jr c,idiv2          ; o resto passou de 255, por isso é maior do que d.
    cp d                ; o resto já chega para subtrair d?
    jr c,idiv3          ; não, este bit do resultado fica a 0.
idiv2:
    sub d               ; sim: subtrair o divisor ao resto
    inc l               ; e pôr a 1 este bit do resultado.
idiv3:
    djnz idiv1          ; repetir para os 16 bits.
    ret

    ; Devolve em a a raiz quadrada (inteira) de hl.
isqr:
    ld (sqbuf0),hl      ; número de que queremos a raiz quadrada.
    xor a
    ld (sqbuf2),a       ; resultado, começa a zero.
    ld a,128            ; começar pelo bit mais alto.
    ld (sqbuf1),a       ; bit a experimentar.
    ld b,8              ; 8 bits no resultado.
isqr1:
    push bc             ; guardar contador do ciclo.
    ld a,(sqbuf2)       ; resultado até agora.
    ld d,a
    ld a,(sqbuf1)       ; próximo bit a experimentar.
    or d                ; juntá-lo ao resultado: este é o candidato.
    ld d,a
    push de             ; guardar o candidato.
    ld hl,(sqbuf0)      ; número original.
    call idiv           ; hl = número / candidato.
    pop de              ; recuperar o candidato em d.
    ld a,h
    and a               ; quociente maior do que 255?
    jr nz,isqr2         ; sim, é certamente >= candidato: guardar o bit.
    ld a,l
    cp d                ; quociente < candidato?
    jr c,isqr0          ; sim, o candidato é demasiado grande.
isqr2:
    ld a,d
    ld (sqbuf2),a       ; guardar o novo resultado.
isqr0:
    ld hl,sqbuf1        ; bit que experimentámos.
    and a               ; limpar flag de carry.
    rr (hl)             ; passar ao bit seguinte, à direita.
    pop bc              ; restaurar contador do ciclo.
    djnz isqr1          ; repetir.
    ld a,(sqbuf2)       ; devolver o resultado em a.
    ret

sqbuf0: defw 0
sqbuf1: defb 0
sqbuf2: defb 0
fim:

; --- Carregador BASIC + ficheiro .tap (igual em todos os exemplos) ---
        ORG 23755
basic:  db 0,10                 ; 10 CLEAR 32767: LOAD "" CODE: RANDOMIZE USR 32768
        dw basic_fim-basic-4
        db $FD,$B0,'"32767":',$EF,'""',$AF,':',$F9,$C0,$B0,'"32768"',13
basic_fim:
        EMPTYTAP "cap15_1.tap"
        SAVETAP  "cap15_1.tap",BASIC,"cap15_1",basic,basic_fim-basic,10
        SAVETAP  "cap15_1.tap",CODE,"cap15_1",start,fim-start
```

## Notas

* `imul` multiplica dois números de 8 bits e dá um resultado de 16 bits (até 255 × 255 = 65025). Por isso, a soma de dois quadrados só cabe em 16 bits se os catetos forem pequenos o suficiente: 200² + 100² = 50000 cabe, mas 200² + 200² = 80000 já não.
* `idiv` não verifica a divisão por zero: com `D` = 0 devolve 65535 e um resto sem significado.
* As três rotinas usam o registo `B` como contador. Quem as chama dentro de um ciclo com `djnz` tem de guardar `B` antes.
